# ADR-0013：横切治理采用强制上下文传播与确定性执行点

状态：Accepted

日期：2026-07-24

## 背景

天机阁已经列出多租户、身份权限、证据血缘、预算资源、风险质量、审计追踪和数据生命周期七个横切维度。如果这些维度只存在于顶层原则或 Agent Prompt 中，它们会在跨面调用、缓存、检索、模型调用和异步任务中丢失。

## 决定

采用以下统一机制：

1. 七个横切维度通过可解析的版本化上下文贯穿请求、契约、对象和调用；
2. 平台控制面拥有主要可执行政策与期望状态；
3. 入口、运行时、数据访问、检索、模型/Tool 网关和产品分发设置确定性强制点；
4. 数据底座保存血缘、账本、审计和生命周期权威记录；
5. 各业务面负责自己的领域质量、风险语义和控制证据；
6. 智能治理面审核高影响例外，能力演进面评估规则效果；
7. Agent 可以规划、解释、审核和建议，不能替代硬隔离、权限判定、预算扣减、审计写入与生命周期执行。

## 理由

- 横切语义只有随执行传播，才能避免局部正确、全链失控；
- 确定性强制点比要求 Agent “记住规则”更可靠并节省 Token；
- 集中政策与分布执行兼顾一致性和边界自治；
- 控制证据可以让架构在没有真实实现的情况下接受场景推演；
- 统一模型可覆盖未来模型、Tool、Agent 和基础设施变化。

## 被拒绝方案

### 每个一级面自行解释横切规则

会产生权限、质量和生命周期语义漂移，跨面组合后无法证明整体正确。

### 全部集中到平台控制面处理

平台无法理解每个领域对象的证据和质量语义，也会形成单点耦合。

### 依赖皇帝或三省 Agent 在 Prompt 中检查

无法可靠覆盖缓存、索引、异步任务、数据副本和底层副作用，且重复消耗 Token。

## 后果

正向：

- 七维度具有统一传播、强制、失败和审计语义；
- 十个一级面可以用同一责任矩阵验证；
- Agent 与 Tool 的边界进一步清晰。

代价：

- 契约、对象和调用必须维护更多上下文引用；
- 策略版本、撤销传播和长时任务重新判定增加复杂度；
- 需要设计 fail-closed 与有限降级之间的精确边界。
