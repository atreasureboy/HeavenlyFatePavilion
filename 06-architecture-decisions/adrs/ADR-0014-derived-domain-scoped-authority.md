# ADR-0014：内部智能主体只拥有派生且分域的权力

状态：Accepted

日期：2026-07-24

## 背景

“仙人—皇帝—三省六部”容易被误读成单一权力树：皇帝位于顶点，因此可以对数据、事实、预算、外部系统和其他主体拥有无限权力。多租户、外部监管、数据权利、供应链和事实验证表明，天机阁实际处于多个权威域的交汇处。

## 决定

天机阁采用分域主权模型：

1. 人类目标、平台运行、租户资源、数据使用、事实接受、产品发布、外部行动和法律约束分别拥有权威主体；
2. 皇帝、三省、六部、Agent、Tool 和内部服务只获得派生、限域、限时且可撤销的权力；
3. 组织地位、模型智商、上下文规模和技术可达性都不能创造授权；
4. 事实接受采用可追溯的验证权威，不服从单纯组织权力；
5. 外部业务状态继续由外部系统及其责任主体拥有；
6. 权威冲突按主权域路由，不交给单一 Agent 自我裁决。

## 理由

- 多租户平台不存在一个可以合法代表所有主体的“总用户”；
- 能读取、能推理、能调用不等于有权使用、决定或行动；
- 事实可信度需要认识论程序，不能由官职高低决定；
- 外部权利和制度不会因系统边界而消失；
- 分域模型可以在未来超级模型出现后继续保持人类主权与责任边界。

## 被拒绝方案

### 皇帝作为全系统绝对权威

叙事简单，但会把交互入口、租户代表、事实裁定、平台运营和外部行动责任混成一个不可审计主体。

### 平台运营者拥有一切最终权力

平台可以控制自身设施，却不能因此取得租户数据、外部权利和现实业务状态的所有权。

### 完全由法律或规则引擎给出单一优先级

不同司法辖区、权利来源和事实争议无法在骨架阶段压缩成一个全局排序；需要先按域识别，再交相应权威处理。

## 后果

正向：

- 越权可以按主权域精确定义；
- 官制叙事不会制造技术上的无限权力；
- 外部生态和受影响主体进入系统上下文；
- 未来模型能力提升不会自动破坏治理边界。

代价：

- 权威冲突可能无法由系统自动解决；
- 上下文必须携带授权来源、代表关系和作用域；
- 跨租户、跨辖区和外部行动需要组合多个权威。
