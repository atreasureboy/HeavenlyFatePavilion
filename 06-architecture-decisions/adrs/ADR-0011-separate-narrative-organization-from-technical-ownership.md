# ADR-0011：官制组织与技术所有权分离

状态：Accepted

日期：2026-07-24

## 背景

三省六部和公共官署为天机阁提供强大的组织叙事，但早期设计容易把一个官署直接等同于一个 Agent、一个服务或一个技术层，造成尚书省与 Scheduler、工部与基础设施、国史馆与数据库等边界冲突。

## 驱动因素

- 官制叙事需要保留治理和讲解价值；
- 技术能力所有权必须遵循十面能力树；
- 一个机构可能需要多种技术形态；
- 高级 Agent 不能承担权限强制、存储和调度等确定性职责；
- 未来模型和实现变化不应迫使重写组织语义。

## 候选方案

1. 每个官署对应一个 Agent；
2. 每个官署对应一个技术服务或层；
3. 使用“叙事机构→逻辑职责→能力→技术形态→实例与状态”的多层映射。

## 决定

采用方案 3。

- 官制是组织与治理视图，不是完整技术分层；
- 一个机构可以协调多个能力，但不改变每个能力的主要所有面；
- 一个机构可以由 Agent、Tool、Service、Policy Engine 和 Data System 共同实现；
- 三省是治理权力组合，不是固定流水线；
- 六部是共享平台上的领域能力包，不复制通用能力；
- 公共官署按真实职责映射，必要时拆成跨面能力组合；
- 稳定机构身份不等于常驻高级模型。

## 影响

正面影响：

- 保留三省六部的架构叙事深度；
- 避免用 Agent 模拟调度、存储、权限和记账；
- 户部、工部和钦天监等跨面机构获得清晰解释；
- 能力、组织和组件可以分别演进。

代价与风险：

- 映射层增加，阅读者需要同时理解组织图和能力图；
- 一个机构跨多个面时容易被误解为多重所有权；
- 组织管理责任和技术状态所有权需要在后续 RACI 中进一步区分。

## 重新评估条件

- 未来组织模型不再使用三省六部叙事；
- 大量机构能够稳定一一对应独立边界上下文；
- 场景验证证明跨面机构映射导致不可接受的治理复杂度；
- 超级模型能力使当前 Agent / Tool 边界发生根本改变。
