# ADR-0002：建立覆盖全系统的能力演进面

状态：Accepted

日期：2026-07-24

## 背景

天机阁面向未来 Agent 能力条件进行终局架构设计。模型、工具、数据语义和多 Agent 范式都将长期快速变化，只演进模型或 Agent 会使其余架构成为时代适配瓶颈。

## 驱动因素

- 跟不上 Agent 时代的系统最终会失去存在意义；
- 并非所有系统部分都能在同一时期实现自主改进；
- 人类设计演进和系统自主演进需要共享评测、版本、发布与回滚基础；
- 演进能力必须在顶层获得稳定位置。

## 候选方案

1. 自我迭代只覆盖模型和 Agent；
2. 自我迭代覆盖部分智能资产；
3. 能力演进覆盖全系统，并同时容纳自主与人类主导两种模式。

## 决定

采用方案 3，将一级面正式命名为“能力演进面”：

```text
能力演进面
├── 自主演进
└── 人类主导演进
```

演进范围包括模型、Agent、Prompt、Context Policy、Tool、Skill、Workflow、领域本体、Schema、数据来源、采集器、检索与关联策略、验证规则、风险模型、评测集、三省六部组织职责、平台控制、多租户机制、数据底座、基础设施和整体架构。

自主程度可以随能力发展而变化，但所有部分都必须保持可演进性。

## 影响

正面影响：

- 避免把演进误解为模型升级或普通运维；
- 当前人工架构迭代与未来系统自主演进能够纳入同一总框架；
- 为未来模型能力跃迁预留组织、数据和运行架构适配入口。

代价与风险：

- 覆盖范围极大，后续必须区分被演进对象、演进机制和变更采用权；
- “全域演进”不等于系统可以自行修改一切，治理与授权仍需独立设计；
- 评测失真可能让演进产生能力退化。

## 重新评估条件

- 证明某类架构对象在原理上不可演进；
- 自主演进与人类演进无法共享任何稳定抽象；
- 能力演进面膨胀到无法形成内聚职责，需要拆分为多个一级面。
