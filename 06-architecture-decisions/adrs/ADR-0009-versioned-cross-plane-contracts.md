# ADR-0009：一级面通过版本化契约协作

状态：Accepted

日期：2026-07-24

## 背景

十个一级面及核心对象已经建立，但如果各面通过自由文本、隐式上下文或直接共享数据库协作，职责所有权仍会被绕过，失败也无法稳定退回正确位置。

## 驱动因素

- 每个一级面需要可验证的输入和输出；
- Agent 自然语言结果必须进入结构化系统契约；
- 多租户、权限、预算、风险和追踪上下文不能跨面丢失；
- 接收方需要能够拒绝越界或不完整请求；
- 同步、异步、Agent 和 Tool 应共享相同业务语义。

## 候选方案

1. 各面自由协作，依赖 Prompt 和共享上下文；
2. 通过共享数据库和通用消息对象交换；
3. 使用版本化、有类型的跨面契约和通用契约信封。

## 决定

采用方案 3。

跨面交互分为 Command、Query、Result、Event、Decision 和 Feedback。所有关键交互必须能够解析发送方、接收方、契约版本、租户作用域、任务上下文、对象引用、前置条件、期望结果、权限、预算、风险、追踪和失败路由。

接收方可以返回 Accepted、Completed、Rejected、Returned、Deferred、Degraded、Failed 或 Cancelled。自然语言可以成为载荷，但不能成为唯一契约结构。

## 影响

正面影响：

- 十面边界从说明文字变成可检查契约；
- 失败、退回、降级和升级拥有统一语义；
- Agent、Tool、Worker 和人类任务可以使用同一业务信封；
- 可在未来替换消息系统和运行平台而保持逻辑契约；
- 上下文传播和审计链获得稳定挂载点。

代价与风险：

- 契约数量、版本和兼容性治理会显著增加；
- 过度同步化或过细契约可能降低演进速度；
- 大对象引用、局部缓存和跨面读取需要后续性能设计；
- 契约信封不能膨胀为每次都复制全部上下文的巨型消息。

## 重新评估条件

- 十面边界发生根本改变；
- 某些高频内部交互证明不需要跨面契约；
- 未来统一运行环境提供同等可审计且更轻量的能力边界；
- 契约治理成本超过其隔离、追踪和替换价值。
