# 能力演进作用全域骨架

状态：Accepted

生效日期：2026-07-24

## 一、这张骨架回答什么

天机阁的能力演进不只是更换模型。它必须能够作用于：

- 皇帝的交互与情报产品；
- 数据认知、情报研判和六部领域能力；
- 三省治理、Agent / Tool 分工和运行体系；
- 数据底座、平台政策和横切治理；
- 来源、本体、Schema、评测和知识解释；
- 基础设施、组织映射和整体架构；
- 暂时不能自主改变、只能由人类演进的部分。

本骨架定义全域演进对象、变更半径、权力关系、共同闭环和不可变底线，不设计具体实验算法、发布系统或组织审批流程。

## 二、能力演进面的准确定位

能力演进面拥有：

- 对全系统效果、成本、失败和时代变化的观察；
- 能力缺口与改进机会的识别；
- 变更候选、实验、评测、回归和影响分析；
- 向有权治理者提交采用、限制、回滚或继续观察建议；
- 自主演进与人类主导演进的共同证据和版本框架。

能力演进面不拥有：

- 其他面的业务权威状态；
- 对自身候选的最终批准权；
- 租户、法律、数据、事实和外部行动主权；
- 绕过平台控制直接改变生产的权力；
- 删除失败实验、历史版本和受影响结果的权力；
- 以“时代进步”为理由改写架构不变量的权力。

因此：

```text
能力演进面
= 全域变化的观察者、实验者与候选协调者
≠ 全域状态的所有者
≠ 能修改一切的超级管理员
```

## 三、九类演进对象

```text
E1 体验对象
   皇帝交互形态、上下文组织、主动通知和人机控制体验

E2 产品对象
   报告、图谱、档案、告警、解释和交付方式

E3 认识与研判对象
   采集、清洗、实体关联、Diff、事实验证、趋势、预测和风险方法

E4 领域对象
   六部本体、来源、规则、Agent、Tool、专业质量标准

E5 治理与组织对象
   三省职责、封驳方式、官署映射、升级路径、Agent / Tool 边界

E6 运行对象
   Agent、Prompt、Context Policy、Memory、Skill、Workflow、调度和运行策略

E7 知识与数据对象
   Source、Schema、本体、索引、图谱、血缘、存储和生命周期结构

E8 平台与横切对象
   租户、权限、预算、风险、审计、策略、目录、版本和强制点

E9 承载与架构对象
   模型供应、基础设施、区域形态、跨面契约、核心对象、能力树和一级骨架
```

演进对象可以横跨多面，但每个对象仍有当前权威所有者。覆盖全域不等于演进面复制全部所有权。

## 四、四种演进来源

```text
运行驱动
→ 质量、成本、失败、事故、人工接管和现实效果

时代驱动
→ 新模型、新 Agent 范式、新 Tool、外部制度和信息环境变化

目标驱动
→ 仙人、租户、平台和产品方向提出的新能力要求

架构驱动
→ 宏观扫描、压力测试、反架构发现和人类架构设计
```

来源只产生 `Evolution Evidence` 或候选目标，不能直接产生生产变更权。

## 五、五级变更半径

| 半径 | 变化范围 | 典型对象 | 骨架要求 |
|---|---|---|---|
| R1 局部替换 | 单一实现或局部配置 | 模型版本、Tool、Prompt、来源 | 保持契约与权威语义 |
| R2 能力组合 | 一个能力或工作方式 | Agent / Tool 分工、Workflow、检索与评测 | 检查上下游、成本和回归 |
| R3 跨面协同 | 多个一级面的关系 | 全局流、对象转化、产品纠正和运行形态 | 多所有者共同评审与影响追踪 |
| R4 治理语义 | 权力、作用域或横切规则 | 三省职责、授权、租户、证据和风险标准 | 外部权威、人类批准与强回退要求 |
| R5 架构骨架 | 一级职责与稳定不变量 | 十面、核心对象、契约、尺度轴与生存底线 | 新架构迭代、全局闭合和人类最终采用 |

变更半径不是按代码行数判断。一个很小的策略修改可能改变权限语义，因而属于 R4；一次大规模基础设施替换若保持逻辑契约，可能仍只是 R1 或 R2。

## 六、提议权、验证权、采用权、发布权分离

```text
任何主体
→ 可以在权限范围内提供观察或变更建议

能力演进面
→ 形成候选、实验、评测、影响和回滚证据

对象权威所有者
→ 判断领域语义是否可接受

智能治理面 / 有权人类
→ 对风险、权力与高影响采用作决定

平台控制面
→ 将已批准候选变成版本化期望状态

智能执行与运行面
→ 在限定作用域实例化、灰度、停止和回报实际状态

数据底座面
→ 保存版本、证据、结果、决定和影响血缘
```

同一个人或模型可以在低风险变更中承担多个角色，但这些角色的决定类型和记录仍可区分。高风险和大半径变更不能由受益候选自己完成唯一验证和采用。

## 七、三层嵌套演进循环

### 7.1 局部能力循环

```text
局部观察
→ 局部候选
→ 沙箱 / 评测
→ 限域采用
→ 保留 / 调整 / 回滚
```

用于模型、Tool、Prompt、来源和局部策略。

### 7.2 跨面系统循环

```text
多个面出现共同缺口
→ 分析对象、契约、状态和横切影响
→ 多所有者候选
→ 端到端场景与回归
→ 治理采用
→ 平台发布与运行观察
```

用于工作流、对象转化、运行形态、产品和治理协同。

### 7.3 架构循环

```text
时代变化 / 宏观压力 / 反架构发现
→ 重新扫描问题空间与一级边界
→ 提出架构候选
→ 对象、契约、状态、横切和场景闭合
→ 人类架构采用
→ 新基线与历史基线并存
```

当前 HeavenlyFatePavilion 文档迭代本身就是“人类主导架构循环”的现实样例。

三个循环共享证据、候选、版本和回滚思想，但不要求使用同一技术工作流。

## 八、十面的演进关系

| 被演进面 | 提供的演进证据 | 对候选拥有的权威 |
|---|---|---|
| 人机交互 | 目标误解、使用反馈、接管与停止体验 | 交互语义和控制呈现验收 |
| 情报产品 | 消费、传播、纠正和现实影响 | 产品契约、受众和发布质量验收 |
| 数据认知 | 来源、关联、Diff、事实错误和污染 | 认识语义与事实接受标准验收 |
| 情报研判 | 预测评分、风险失效和替代解释 | 研判语义、不确定性和失效条件验收 |
| 智能治理 | 计划、封驳、冲突、升级和权力异常 | 治理决定与制衡边界验收 |
| 领域能力 | 领域盲区、法规、来源和专业效果 | 领域本体、规则与质量验收 |
| 智能执行与运行 | 成本、延迟、失败、循环、接管和恢复 | 实例化安全与运行可行性验收 |
| 数据底座 | 版本、血缘、质量、容量和生命周期证据 | 持久语义、历史和供应契约验收 |
| 平台控制 | 策略效果、租户、公平、预算和实际偏差 | 期望状态、策略版本和发布验收 |
| 能力演进 | 实验、回归、对抗、时代变化和候选比较 | 演进证据与候选状态，不拥有他面采用权 |

任何面都可以拒绝破坏自身稳定契约的候选，但不能借此否决其他主权域有权进行的独立变化。

## 九、七个横切维度如何演进

横切规则的演进必须同时检查：

```text
规则权威是否仍然正确
Context 是否能够表达新语义
所有强制点是否理解同一版本
历史对象适用旧规则还是新规则
失败时采用阻断、兼容、降级还是回滚
租户、区域和运行中任务如何过渡
审计能否证明何时、为何、对谁生效
```

横切变化不能只升级中央策略而忽略入口、缓存、数据访问、模型、Tool、产品和生命周期执行点。

## 十、演进影响的四个方向

### 10.1 向前影响

新版本如何改变未来任务、知识和产品。

### 10.2 向后兼容

旧任务、旧对象、旧租户配置和旧产品能否继续被理解。

### 10.3 历史重释

新能力是否要求用新视角重新计算历史，结果应作为当前重释存在，不能覆盖当时结论。

### 10.4 派生影响纠正

失败版本曾生成的事实、关系、研判、产品、告警或外部行动，如何被找到、隔离、重评和纠正。

```text
回滚能力版本
≠ 自动消除该版本已经产生的现实与知识影响
```

## 十一、自主程度与变更半径分离

自主程度高，不代表允许的变更半径大：

```text
超级模型
可以高度自主地：
观察、生成候选、设计实验、执行评测

但不能因此自动获得：
改变主权、扩大权限、采用 R4 治理变化、批准 R5 架构变化的权力
```

相反，人类也不能跳过证据、实验、版本和影响记录，仅凭身份把未经验证的候选直接变成生产事实。

自主与人类主导的区别主要在提议和执行主体；采用纪律由风险、变更半径和权威来源决定。

## 十二、演进失败域

演进本身可能失败：

- 观察偏差：只看可测指标，忽略真实价值和副作用；
- 评测过拟合：优化基准而损害开放环境；
- 共同失败根：生产者、评价者与批准者共享同一偏差；
- 局部最优：一个面改善却破坏全局契约；
- 版本断裂：新旧对象、策略或任务无法共存；
- 权力漂移：候选在迭代中扩大授权；
- 影响遗留：回滚版本但不纠正派生结果；
- 演进停滞：某个不可变依赖阻止全系统适应；
- 时代错配：评价体系本身已经过时；
- 架构漂移：大量局部变化累积后实际系统不再符合架构基线。

这些失败进入同一个生存性框架：感知、遏制、降级、恢复、纠正与再次演进。

## 十三、全域演进不变量

1. 观察不等于修改，候选不等于采用，采用不等于生产生效；
2. 能力演进面协调全域变化，但不接管被演进对象的权威状态；
3. 任何生产版本都能追溯提议、实验、评测、决定、发布和作用域；
4. 自主演进和人类演进共享证据、版本、回归、回滚和影响纠正要求；
5. 变更半径越大，所需权威范围、验证广度和人类参与不得变小；
6. 演进不得静默扩大租户、数据、模型、Tool 或外部行动权限；
7. 新能力不得把历史上“当时可知”伪装成从未存在；
8. 回滚必须区分版本回滚、状态恢复和派生影响纠正；
9. 评测者与候选共享失败根时，不得冒充独立验证；
10. 不能自主演进的部分必须保持可由人类观察、替换和迁移；
11. 能力可以改变实现形态，稳定契约和架构不变量只能经相应半径的架构治理改变；
12. 演进能力本身也必须被观察、评测、限制、替换和回滚。

## 十四、对现有骨架的裁定

能力演进面继续作为独立一级面成立，因为它拥有稳定且内聚的“观察—候选—实验—评测—影响—建议”职责，并跨越所有其他面。

它没有膨胀为全域控制面：

```text
演进面提出与验证变化
智能治理面决定高影响采用
对象所有面确认领域语义
平台控制面发布期望状态
运行面实现并回报实际状态
数据底座保留证据和历史
人类保留大半径与主权变化的最终采用权
```

本轮没有发现拆分或取消能力演进面的理由，也没有新增一级面。十面稳定性保持。

后续一屏全景与一级稳定性复核已经完成，`Skeleton v0.3` 已闭合；见 [Skeleton v0.3 闭合与一级稳定性复核](../07-analysis-and-validation/skeleton-v0.3-closure-and-stability-review.md)。

## 十五、有意不展开

- 自治等级的数值和逐对象权限；
- 实验平台、特征开关、灰度和发布技术；
- 评测指标、数据集、统计显著性和因果归因；
- Schema 迁移、兼容协议和版本协商；
- 逐面 RACI 与审批矩阵；
- 基础设施迁移和供应商替换方案；
- 架构文档自动修改与代码生成机制。
