# 天机阁全局运行形态骨架

状态：Accepted

生效日期：2026-07-24

## 一、骨架定位

天机阁不是只在仙人发消息时运行的聊天系统。它必须容纳即时问答、复杂调查、长期监测、事件响应、批量加工、人类协作、能力演进、受控外部行动和灾难恢复。

运行形态描述“系统在什么触发和时间尺度下运转”，不是新的一级面，也不是实现工作流。本轮只确认形态是否齐全、能否挂入十面。

## 二、统一层级

```text
Mandate / Authority
为什么允许系统做这件事
        ↓
Mission / Incident / Evolution Goal
要达成什么、何时结束、谁负责
        ↓
Run
一次有边界的执行尝试
        ↓
Task / Agent / Tool
临时执行主体
        ↓
Product / Alert / State Change / External Effect
产生什么结果
```

这是骨架级分层：

- 长期授权和目标不依赖常驻 Agent 上下文；
- 一个长期目标可以产生多次 Run；
- Run 完成不必终止长期监测或案件；
- Trigger 只提出候选工作，不能创造无限授权；
- 后续专题再决定这些概念是否成为独立对象及其完整状态机。

## 三、十种运行形态

| 编号 | 运行形态 | 典型触发 | 时间尺度 | 主要结构特征 |
|---|---|---|---|---|
| M1 | 即时交互与快速查询 | 消息、API 查询 | 秒～分钟 | 检索与 Tool 优先，歧义时升级 Agent |
| M2 | 复杂调查与案件 | 高复杂度或高风险目标 | 分钟～月 | 持久案件、三省治理、六部协作、人类复核 |
| M3 | 持续监测与守望 | 长期授权、时间、来源变化 | 天～年 | 持久监测定义，Agent 按事件实例化 |
| M4 | 事件驱动响应 | 世界事件、Change、Risk、异常 | 毫秒～天 | 先筛选关联，再按风险升级调查和响应 |
| M5 | 周期批处理、回填与重建 | 计划、版本变化、修复 | 分钟～月 | Tool/Worker 主导的大规模加工和重算 |
| M6 | 多人、多 Agent 与跨租户协作 | 联合调查、专家复核、移交 | 小时～月 | 共享目标但不合并身份、权限和主权 |
| M7 | 主动情报与订阅交付 | 订阅、风险变化、周期简报 | 实时～周期 | 无同步提问时的授权交付、回执与更正 |
| M8 | 能力观察、实验与演进 | 质量、成本、失败、时代变化 | 小时～年 | 观察、实验、评测、发布与回滚 |
| M9 | 受控外部行动与补偿 | 有权决定或批准策略 | 秒～月 | 建议、决定、调用、现实结果和补偿分离 |
| M10 | 事故、降级与灾难恢复 | 服务、数据、模型、区域或安全事故 | 秒～月 | 隔离、最低能力、恢复、纠正和复盘 |

M9 在骨架中保留位置，不代表当前决定天机阁必须启用外部行动。

## 四、触发来源

```text
Human Trigger       人类请求、决定和纠正
Time Trigger        计划、到期和周期窗口
World Event Trigger 外部世界与业务系统事件
Internal Trigger    Change、Risk、质量、预算、权限和失败
Policy Trigger      Court Profile、平台和制度变化
Evolution Trigger   模型、Tool、评测和架构变化
Emergency Trigger   安全、区域、数据和人类紧急停止
```

不同触发源可以进入同一运行形态；同一触发也可能产生多个候选形态。

## 五、形态转换

```text
快速查询 ──复杂化──▶ 调查案件
持续监测 ──发现变化▶ 事件响应 ──扩大──▶ 调查 / 主动交付
调查案件 ──需会盟──▶ 协作案件
任意形态 ──需重算──▶ 批处理回填
任意形态 ──能力缺口▶ 能力演进
研判结果 ──获授权──▶ 外部行动
任意形态 ──重大事故▶ 灾难恢复 ──纠正影响▶ 回填 / 更正交付
```

转换必须保留原目标、责任、授权和结果关系，不能只发生在 Agent 对话中。

## 六、与十面的关系

所有运行形态仍由现有十面组合完成：

```text
体验与交付：人机交互 + 情报产品
情报生产：数据认知 + 情报研判 + 领域能力
治理与执行：智能治理 + 智能执行与运行
平台与知识：数据底座 + 平台控制
演进与适应：能力演进
```

第一版扫描没有发现需要新增第十一个一级面的运行形态。

## 七、骨架级不变量

- 长期目标属于持久系统状态，不属于常驻 Agent 记忆；
- 后台、批处理、恢复和演进不是绕过治理的特权通道；
- 简单形态可以减少 Agent，不能省略租户、权限、证据、预算和审计；
- 运行形态转换必须显式可追踪；
- Recommendation、外部 Command 与现实 Effect 不能混写；
- 灾难状态可以降低能力，不能取消人类停止权；
- 时间尺度改变执行方式，不改变权威与责任边界。

## 八、当前刻意不展开

- Mandate、Incident、Trigger 和 Action 是否成为独立领域对象；
- 各形态的状态机、超时、重试和补偿协议；
- Scheduler、队列、工作流和事件总线；
- 批量、并发、RTO/RPO 与部署拓扑；
- 外部行动的具体授权流程。
