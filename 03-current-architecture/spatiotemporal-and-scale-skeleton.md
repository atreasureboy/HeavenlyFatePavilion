# 空间、时间与规模骨架

状态：Accepted

记录日期：2026-07-24

## 一、这张骨架回答什么

天机阁不能只在“一个用户发起一次查询”的尺度上成立。它必须能够在不改变基本语义的前提下表达：

- 单用户、单租户、多租户与受控联合空间；
- 本地、区域、跨区域与全球信息环境；
- 一次交互、长期 Mission、持续守望与跨年知识演化；
- 小规模查询、热点事件与超大规模持续监测；
- 当前模型、未来更强模型与未知智能代际。

本骨架只确定尺度维度、结构变化点和不变量，不定义部署节点、容量数字、分区算法、复制协议或模型选型。

## 二、四条正交扩展轴

天机阁不能用一棵单独的层级树表达全部尺度。租户空间、地理辖域、时间跨度和工作规模是四条可以独立变化的轴。

```text
作用域轴：平台公共域 → 租户域 → 联合空间 → 用户工作空间 → Mission / Run
辖域轴：本地 ↔ 区域 ↔ 跨区域 ↔ 全球
时间轴：瞬时交互 → 长期任务 → 持续监测 → 跨年知识与演进
规模轴：单点查询 → 租户级工作负载 → 热点事件 → 全域持续感知
```

模型能力代际不是第五个业务空间，而是作用于四条轴和十个一级面的外部变化变量：

```text
当前模型能力 → 更强多 Agent 能力 → 未来超级模型能力
```

同一个 Mission 可以同时属于某个租户、跨越多个辖域、持续多年，并在热点时从普通负载跃迁为全域任务。四条轴不能彼此替代。

## 三、作用域空间

### 3.1 逻辑层级

```text
共享平台
├── 公共事实与公共能力基线
├── 租户逻辑朝廷 A
│   ├── 租户私有覆盖层
│   ├── 用户工作空间
│   └── Mission / Run
├── 租户逻辑朝廷 B
└── 经授权建立的联合空间
    ├── 明确参与方
    ├── 明确共享范围
    └── 可撤销的联合任务与产品
```

公共基线、租户覆盖、用户工作空间和联合空间可以引用相同的全局对象身份，但各自拥有独立的可见性、主张、研判、产品和处置权限。

### 3.2 空间不变量

- 逻辑朝廷不等于物理部署；一个共享平台可承载多个逻辑朝廷。
- 联合空间不是租户边界的消失，而是多个边界之间建立的有限交集。
- 公共基线不等于全球无条件公开；公开性仍受来源许可、辖域和主体权利约束。
- 平台可以聚合运行态势，但不能因此取得租户数据、目标或行动的主权。
- 任何跨空间结果都必须保留其来源作用域和允许传播的目标作用域。

## 四、地理与辖域空间

一份信息至少可能同时涉及：

```text
来源所在辖域
被研究主体所在辖域
资料允许存储与处理的辖域
产品允许交付的辖域
外部行动实际发生的辖域
```

这些位置可能完全不同。因此“区域”不是十面之外新增的业务面，而是横切于入口、数据、知识、研判、产品、治理和行动的辖域覆盖层。

当系统从本地扩展到跨区域时，宏观骨架出现三类结构：

1. **辖域覆盖层**：表达不同区域适用的来源、处理、保留、交付与行动约束；
2. **区域自治边界**：允许某个区域在外部连接中断时维持被授权的局部能力；
3. **联邦关系边界**：允许主权独立的天机阁实例或同行系统交换有限事实、证据、任务或产品。

联邦不等于合并。对方系统的身份、事实标准、权限和审计不能被默认继承。

## 五、时间骨架

### 5.1 五种时间跨度

```text
交互时刻：一次问答或即时告警
执行时段：一次 Run 的开始、变化与结束
任务时期：Mission / 案件 / 守望目标的长期存续
知识历史：事实、关系、事件、判断与更正的跨年演化
能力代际：模型、Tool、策略、组织与架构版本的时代更替
```

### 5.2 三种不可混淆的时间语义

- 现实何时成立或发生；
- 天机阁何时发现、记录或接受；
- 决定、产品或权限何时生效。

骨架要求保留这些差异，但本阶段不规定字段和存储实现。

### 5.3 时间不变量

- 长期知识不能依赖某个 Agent 的上下文窗口或临时记忆存活。
- 新资料不得覆盖旧结论存在过的事实；更正通过版本、血缘和状态演化表达。
- 当前最可信结论与历史上当时可知的结论必须能够区分。
- Mission 可以跨越多个 Run、模型版本和组织版本，而不丢失目标、责任与证据连续性。
- 能力升级不能静默改写过去的决策依据和产品责任。
- 跨年结论必须能够绑定当时的数据、规则、模型、Tool、授权和解释框架，使“当时可知”与“当前重释”均可回放。

## 六、规模骨架

### 6.1 规模不只等于数据量

天机阁的规模由多个因素共同形成：

- 租户、用户和联合参与方数量；
- 来源、文档、实体、关系和变化数量；
- 事件速度、任务并发与热点突发度；
- 关系图连接度、跨域关联跨度和历史深度；
- 不确定性、争议度、风险等级和审核强度；
- 模型、Tool、人工与外部系统的资源约束。

### 6.2 从规模增长得到的宏观结构

```text
工作可分解
→ 允许并行、分域与分层处理

知识可分治
→ 允许局部权威、全局身份和受控聚合并存

资源有优先级
→ 允许公平、限额、降级、背压和关键任务保障

故障有边界
→ 允许局部失效而不是整阁共同失效

结果可汇聚
→ 局部产物只有经过证据、作用域和治理检查才能成为更高层结论
```

这些是逻辑要求，不预先指定采用何种集群、队列、数据库或分区键。

### 6.3 规模不变量

- 规模可以改变拓扑、并发方式和资源分配，不能改变 Fact、Inference、Decision 与 Authority 的语义。
- 热点事件不能让单个来源、任务或租户无界占用全局能力。
- 分片产生的局部结论不能自动冒充全局结论。
- 降级可以减少新鲜度、覆盖度或推理深度，不能伪装成完整成功。
- 跨区域和跨租户聚合必须先经过作用域、证据与授权检查。

## 七、模型能力代际

随着模型智商提高，Agent 与 Tool 的边界会移动：

```text
当前：
高层规划、综合研判、反证审核由 Agent 承担；
确定性、高吞吐工作尽量 Tool 化。

未来：
更强模型可以合并更多认知步骤、承担更长任务并减少固定编排；
原有角色可能从多个实例收缩为更少的智能主体。
```

但模型能力增强不自动改变以下结构：

- 仙人作为目标、授权与最终责任来源；
- 规划、执行、审核三类权力的可区分性；
- 租户、辖域、数据和行动主权；
- 证据、事实、推断、决定与产品的语义分层；
- 预算、审计、撤销、纠正和停止能力；
- 数据底座对长期知识的独立承载；
- 能力演进必须经过观察、验证、治理和可回退发布。

未来可以合并执行角色，但不能因为“一个模型足够聪明”就静默合并全部权力。

## 八、对十面骨架的影响

S5 没有发现必须新增的一级逻辑面。

```text
四条尺度轴
× 十个一级逻辑面
× 七个横切治理维度
```

它们形成的是架构坐标系：

- 十面回答“哪类职责由谁拥有”；
- 四轴回答“职责在什么空间、时间和规模下发生”；
- 横切维度回答“无论处于哪个坐标都必须遵守什么约束”；
- 基础设施回答“这些逻辑结构最终由什么共同承载”。

区域、联邦和规模单元属于承载及边界视图，不应为了部署便利被误升格为新的业务职责面。

## 九、本阶段有意不展开

- 区域和节点部署拓扑；
- 数据分片、复制、一致性与路由算法；
- 容量数字、SLO、RTO 和 RPO；
- 热点检测、排队、公平与背压算法；
- 跨区域网络和存储技术选型；
- 具体的数据驻留、法规与授权规则表；
- 模型大小、上下文长度和 Agent 数量；
- 联邦协议、联合空间 Schema 和同步字段。

这些将在整体骨架稳定后进入部署、数据、运行、安全或容量专题。
