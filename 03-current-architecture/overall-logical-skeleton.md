# 天机阁总体一级逻辑骨架

状态：Accepted

生效日期：2026-07-24

## 一、总体结构

```text
天机阁
├── 体验与交付域
│   ├── 人机交互面
│   │   └── 皇帝交互投影
│   └── 情报产品面
├── 情报生产域
│   ├── 数据认知面：掌数、联结、察变
│   ├── 情报研判面：推势、卜算、警险
│   └── 领域能力面：六部与领域型官署
├── 治理与执行域
│   ├── 智能治理面：皇帝本体、三省与治理型官署
│   └── 智能执行与运行面
├── 平台与知识域
│   ├── 数据底座面
│   └── 平台控制面
└── 演进与适应域
    └── 能力演进面

共同承载底座：基础设施

横切维度：
多租户、身份与权限、证据与血缘、预算与资源、
风险与质量、审计与追踪、数据生命周期

宏观坐标与边界：
主体生态与分域主权、十种运行形态、七条全局流、
作用域/辖域/时间/规模四轴、生存性结构、负空间与未来替换
```

五个“域”只用于总图分组，不拥有状态或架构职责；十个“面”才是一级逻辑职责单元。

## 二、一级面职责

| 一级面 | 核心问题 | 主要责任 |
|---|---|---|
| 人机交互面 | 仙人如何与天机阁相处 | 皇帝交互投影、对话、多模态入口、主动通知和反馈 |
| 情报产品面 | 天机阁交付什么 | 档案、图谱、时间线、报告、趋势、情景和风险告警 |
| 数据认知面 | 天机阁如何认识世界状态 | 掌数、联结、察变 |
| 情报研判面 | 天机阁如何理解局势与未来 | 推势、卜算、警险 |
| 智能治理面 | 智能任务如何被治理 | 皇帝本体、三省、规划、统筹、审核、封驳和问责 |
| 领域能力面 | 天机阁拥有哪些专业能力 | 六部、领域知识、领域工具和跨领域协作 |
| 智能执行与运行面 | 一次任务如何真正运行 | Run、Task、Agent 实例、Tool 调用、调度、上下文和恢复 |
| 数据底座面 | 系统知识和记录如何持久存在 | 原始资料、证据、事实、关系、变化、研判、风险及其版本 |
| 平台控制面 | 系统长期应该如何运行 | 租户、配置、策略、目录、模板、预算和版本 |
| 能力演进面 | 系统如何持续适应时代 | 全系统自主与人类主导演进 |

## 三、关键边界

### 皇帝本体与交互投影

皇帝是同一租户级具身化智能中枢的两个视图：本体属于智能治理面，面向仙人的投影属于人机交互面。交互投影不是另一个 Agent。

### 智能治理与领域能力

治理面决定任务如何被规划、统筹和审核；领域能力面提供完成任务所需的专业判断。三省代表治理权力，六部代表专业能力。

### 平台控制与智能运行

平台控制面维护长期期望状态，智能执行与运行面维护具体任务的即时执行状态。Agent 模板属于控制面，依据模板形成的 Agent 实例属于运行面。

### 数据底座与基础设施

数据底座是一级逻辑能力面。基础设施不是一级逻辑能力面，而是全部逻辑面的共同计算、存储、网络和部署承载。

### 数据认知与数据底座

数据认知面负责“如何认识世界”，拥有掌数、联结和察变的处理语义；数据底座面负责“认识结果如何可靠存在”，拥有资料、事实、关系、变化和研判记录的持久状态、版本与供应。

### 六部与共享情报主干

“掌数—联结—察变—推势—卜算—警险”是共享情报生产主干。六部提供覆盖该主干的专业语义、规则、Agent 和 Tool，不各自复制整套数据、运行和控制平台。

## 四、架构不变量

- 皇帝不得被简化为聊天壳，也不得膨胀为亲自完成全部工作的超级 Agent；
- 数据认知结果与情报研判结果必须保持语义区分；
- 三省治理权与六部领域能力不得混写；
- 控制面的期望状态与运行面的即时状态必须能够关联但不能混为同一所有权；
- 多租户同时具有平台控制子域和全局上下文属性；
- 能力演进覆盖所有一级面和共同承载底座。
- 运行形态、全局流、尺度轴、生存防线和负空间不得被误升格为一级职责面；
- 十面可以由不同模型、Agent、Tool 和服务实现，但职责语义与权威边界不能静默改变。
