# 非功能与生存性骨架

状态：Accepted

记录日期：2026-07-24

## 一、这张骨架回答什么

天机阁不仅要在正常条件下完成任务，还要在模型误判、恶意输入、权限冲突、数据损坏、供应链失效、区域中断、资源枯竭和自身演进出错时，继续保持：

- 合法；
- 可信；
- 可控；
- 可停止；
- 可解释；
- 可恢复；
- 可纠正；
- 受人类最终支配。

本骨架定义质量属性所在位置、最低生存内核、防线阶段、全局责任和不可接受失败。它不计算 SLO，不设计安全规则、恢复算法或具体故障流程。

## 二、非功能不是“非业务”

对于天机阁，质量属性会直接改变情报产品能否成立：

```text
没有证据与一致性
→ “事实”不成立

没有权限、隐私与合规
→ “可以处理”不成立

没有可靠性与恢复
→ “长期掌握”不成立

没有解释、审计与纠正
→ “可以信任”不成立

没有停止权与人类主权
→ “可以治理”不成立
```

因此这些属性不是部署阶段附加的技术要求，而是全部十面、四条尺度轴和七个横切维度必须共同维持的生存条件。

## 三、四类完整性

### 3.1 主权与合法性完整性

覆盖：

- 人类主权；
- 身份、授权与委托；
- 租户隔离；
- 隐私、来源许可和合规；
- 可停止性与行动责任。

它回答：系统是否有权做这件事，谁能够叫停，谁承担最终责任。

### 3.2 认识与语义完整性

覆盖：

- 证据与血缘；
- 事实可信度；
- 数据和任务语义一致性；
- 不确定性表达；
- 可解释、可争议和可纠正。

它回答：系统凭什么知道，结论在不同节点和时间是否仍表示同一件事。

### 3.3 运行与连续性完整性

覆盖：

- 可靠性与可用性；
- 故障隔离；
- 安全韧性；
- 降级与业务连续性；
- 恢复、重建和影响纠正；
- 资源与供应链韧性。

它回答：部分能力失效时，系统能否限制损害、保存核心状态并以诚实方式继续。

### 3.4 演进与时代完整性

覆盖：

- 模型、Tool、策略、知识和架构版本；
- 变更验证与发布治理；
- 退化发现；
- 回滚与代际迁移；
- 自我演进的权限边界。

它回答：系统改变自身时，如何避免把更新本身变成不可控事故。

四类完整性相互制约。高可用不能成为绕过权限的理由，强一致不能以永久不可用为唯一结果，安全隔离不能销毁必要的责任证据，自我演进不能取消人类停止权。

## 四、最低生存内核

“最低生存内核”是灾难或严重退化时仍必须能够被保留或重建的一组逻辑能力，不是新组件、单一服务或第十一个一级面。

```text
最低生存内核
├── 人类控制入口
│   └── 观察、暂停、终止、接管和恢复授权
├── 身份、权力与政策根
│   └── 谁是谁、谁授权了什么、哪些边界绝不能越过
├── 隔离与紧急控制
│   └── 阻断传播、撤销能力、收回执行权和限制外部作用
├── 权威状态与证据根
│   └── 目标、事实、血缘、决定、审计和版本的持久锚点
├── 真实运行态势
│   └── 哪些能力可用、受损、未知、降级或正在恢复
└── 恢复与纠正协调
    └── 从可信点重建，并追踪和修正已传播影响
```

当最低内核中的身份权力、紧急停止或权威记录无法可信使用时，高影响写入、发布、自主演进和外部行动必须停止。系统可以保留有限只读或人工辅助能力，但不得假装完整运行。

## 五、六阶段生存防线

```text
1. 预防 Prevent
   在能力、来源、数据、模型、Tool 和行动进入前建立边界

2. 感知 Detect
   发现故障、攻击、漂移、冲突、污染、资源异常和未知状态

3. 遏制 Contain
   将问题限制在租户、区域、任务、能力版本或数据范围内

4. 延续 Continue
   用明确标记的降级形态维持最低可信能力和人类控制

5. 恢复 Recover
   从可信状态重建服务、数据、知识、权限和运行秩序

6. 纠正与演进 Correct & Evolve
   修正派生事实、产品与外部影响，并把事故转化为演进证据
```

这不是单向流水线。感知可能回到预防规则，恢复期间可能再次隔离，纠正可能触发重建，任何阶段都可以由人类停止。

## 六、失效域必须显式存在

系统必须在骨架层承认下列失效域：

```text
主体域：用户、Agent、服务、运营者或外部参与者
任务域：Mission、Run、Task、Tool 调用和外部行动
租户域：逻辑朝廷、用户空间和联合空间
知识域：来源、对象、事实、关系、研判和产品
能力域：模型、Tool、Skill、策略、工作流和版本
供应域：数据源、模型商、外部服务和人工协作
区域域：处理、存储、交付和行动所在区域
平台域：共享控制、数据底座和共同基础设施
```

隔离的目标是阻止一个失效域无条件扩散到其他域。域之间仍可能存在共同依赖，因此“已隔离”必须由运行证据证明，不能只由 Agent 宣称。

失效域也不能被默认视为彼此独立。多个来源、模型、Tool、区域或副本可能共享上游数据、供应商、模型族、身份系统或控制根；“独立性”本身需要依赖血缘和运行证据支持。

## 七、降级不是失败伪装

允许降级的维度包括：

- 覆盖范围；
- 数据新鲜度；
- 推理深度；
- 响应速度；
- 自动化程度；
- 可用来源、模型与 Tool；
- 产品表达和交付渠道。

不允许降级掉的底线包括：

- 租户与权限边界；
- 人类停止、暂停和接管能力；
- 证据与不确定性标记；
- 高影响动作的授权要求；
- 审计和责任连续性；
- 对受损、未知和不完整状态的诚实表达。

如果底线无法维持，正确状态是停止、隔离或等待有权人类，而不是输出一个看似正常的结果。

## 八、一致性采用“按语义分级”，不追求全局单一答案

骨架只确定以下原则：

- 权力、授权撤销、租户归属和不可逆动作需要足够强的控制一致性；
- 事实、关系和研判允许来源差异、版本并存和显式争议；
- 检索、索引、缓存和统计可以暂时滞后，但必须标识新鲜度和权威来源；
- 产品必须绑定生成时采用的事实、研判、权限和能力版本；
- 区域或系统分裂时，不确定的控制权不得按“宽松默认”继续扩张；
- 恢复一致性不仅修复存储，还要修复由旧事实或错误决定产生的派生影响。

具体一致性模型留给后续数据与分布式系统专题。

## 九、可解释性的对象不是只有模型答案

天机阁需要解释的至少包括：

```text
为什么接受这个目标
为什么拥有这项权限
为什么选择这些来源、模型、Tool 和路径
为什么接受或拒绝某个事实
为什么形成这项研判、趋势或风险
为什么发布、降级、停止或采取行动
为什么系统改变了自身能力
```

解释由目标、证据、血缘、决定、运行事件、版本和责任共同构成。自然语言理由可以帮助人类理解，但不能替代这些结构化依据。

## 十、人类主权与可停止性

### 10.1 人类控制层级

```text
观察
→ 限制范围或资源
→ 暂停新工作
→ 取消任务
→ 撤销能力或委托
→ 隔离租户、能力、区域或来源
→ 接管决定
→ 全局紧急停止
```

骨架不要求所有人拥有所有控制权，但必须存在明确、有权、可验证且不依赖被停止 Agent 自愿配合的控制路径。

### 10.2 主权不变量

- 皇帝和其他 Agent 的权力始终是派生权力；
- 自主运行、后台任务、恢复和演进不产生额外权限；
- 更聪明的模型不能扩大其委托范围；
- 外部行动责任不能转移给“模型建议”；
- 紧急停止后重新启动必须经过显式恢复授权；
- 停止系统不能同时抹去追责、纠正和恢复所需的记录。

## 十一、不可接受失败

以下不是普通质量下降，而是骨架必须预防、遏制或停止的失败：

1. 未经授权跨租户读取、传播、训练或行动；
2. 在无法证明身份、委托或适用政策时继续高影响执行；
3. 把无证据推断、冲突主张或模型输出静默提升为事实；
4. 隐瞒降级、缺失、争议、过期或恢复中的状态；
5. 无法由有权人类暂停、撤销、隔离或接管；
6. 权威状态、证据血缘或审计记录被静默覆盖、销毁或不可恢复污染；
7. 局部故障、恶意来源或供应链问题无边界扩散为全局污染；
8. 恢复了服务却没有纠正错误事实、产品、告警或外部影响；
9. 自我演进绕过评测、治理、版本记录、回滚和人类最终控制；
10. 为提高可用性、性能或成本效率而取消安全、主权和认识论底线。

“不可接受”不表示架构声称事故绝不会发生，而表示系统不能把这些状态当成正常成功继续扩散。

## 十二、全局责任分布

| 责任主体 | 生存性责任 |
|---|---|
| 仙人及其他有权人类 | 提供最终目标、批准、停止、接管和责任判断 |
| 人机交互面 | 保留最低控制入口，诚实呈现降级、未知和恢复状态 |
| 智能治理面 | 定义接受条件、封驳高风险结果、组织冲突和人类升级 |
| 智能执行与运行面 | 执行隔离、取消、限权、降级、恢复和真实状态回报 |
| 数据认知与数据底座面 | 维护语义、证据、权威状态、历史版本和纠正血缘 |
| 平台控制面 | 维护身份、政策、能力边界、期望状态和紧急控制 |
| 情报研判与产品面 | 表达不确定性、影响范围、失效状态和更正 |
| 领域能力面 | 识别领域特有的合规、风险、质量和恢复条件 |
| 能力演进面 | 从事故与退化中形成候选变化，并保证验证和回退 |
| 基础设施 | 提供共同承载、故障边界、备份恢复和可观测事实 |

没有任何单一“安全 Agent”“恢复 Agent”或“超级皇帝”能够独自承担全部责任。

## 十三、对现有骨架的裁定

S6 没有发现必须新增的一级逻辑面。

它补充的是覆盖现有架构的生存性视图：

```text
四类完整性
× 六阶段生存防线
× 八类失效域
× 十个一级逻辑面
× 四条尺度轴
```

最低生存内核由交互、治理、运行、数据底座、平台控制和基础设施共同形成，是跨面能力组合，不是新的集中权力中心。

## 十四、本阶段有意不展开

- SLO、错误预算、RTO、RPO 与可用性数字；
- 威胁模型、攻击树和安全控制清单；
- 加密、密钥、网络、沙箱和身份协议；
- 一致性等级、共识、复制与冲突解决算法；
- 备份、切换、重建、演练和取证步骤；
- 隐私法规、数据驻留和许可规则表；
- Kill Switch、接管和恢复的详细授权矩阵；
- 逐对象的解释 Schema 与更正协议。
