# TXT-0018：负空间与未来替换图

状态：Accepted

## 一、这张图回答什么

回答哪些结构不能错误合并、哪些实现可以随模型时代替换，以及未来超级模型出现后天机阁仍必须保留什么。

图中：

- `≠` 表示必须保持语义可区分；
- `×` 表示禁止组合；
- `──▶` 表示允许替换或演进；
- 方框表示逻辑层次，不表示物理组件；
- 本图省略具体替换方案和技术实现。

权威正文：[负空间、反架构与未来替换骨架](../negative-space-and-future-replacement.md)。

## 二、架构的稳定中心与可替换外壳

```text
┌────────────────────── 可替换外壳 ──────────────────────┐
│ Agent 数量 / 模型 / Tool / Skill / 工作流 / 服务边界   │
│ 皇帝交互形态 / 三省实例方式 / 六部 Agent / 部署与供应商 │
│                                                       │
│            能力增强、合并、拆分、替换                  │
│                         │                             │
│                         ▼                             │
│  ┌────────────────── 稳定中心 ────────────────────┐   │
│  │ 人类主权、目标、授权、停止和责任               │   │
│  │ 规划权 ≠ 执行权 ≠ 审核与接受权                 │   │
│  │ 证据 ≠ 主张 ≠ 事实 ≠ 推断 ≠ 决定 ≠ 现实效果   │   │
│  │ 租户、辖域、数据、产品与行动边界               │   │
│  │ 对象所有权、契约、版本、血缘、审计与纠正       │   │
│  │ 期望状态 ≠ 实际运行状态                        │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

外壳变化不应迫使稳定中心改变含义。

## 三、负空间地图

```text
[皇帝 / 交互]  × 事实接受权 / 无限权限 / 全部执行
[治理]         × 亲自执行全部任务 / 以权力改写事实
[运行]         × 创造目标 / 扩大授权 / 确认事实
[数据底座]     × 决定业务意义 / 把当前值当永恒真理
[研判]         × 把预测当事实 / 自行批准行动
[产品]         × 创造证据 / 隐藏不确定性与更正
[平台控制]     × 租户业务主权 / 领域判断
[能力演进]     × 自我批准 / 静默上线 / 改写历史

跨面协作
──必须经过──▶ 契约 + 权威 + 证据 + 作用域 + 审计
```

## 四、六种禁止闭环

```text
提出结论 ─▶ 选择证据 ─▶ 自我审核 ─▶ 自我发布 ─▶ 删除失败记录
                         × 自证闭环

模型更聪明 ─────────────────────────────────────▶ 扩大权限
                         × 智能即权力

能够调用 ───────────────────────────────────────▶ 有权调用
                         × 执行即授权

数据库当前值 ───────────────────────────────────▶ 不可争议真理
                         × 存储即真理

共享平台承载 ───────────────────────────────────▶ 租户数据主权
                         × 平台即租户

发现能力缺口 ───────────────────────────────────▶ 自行修改生产
                         × 演进即自我授权
```

## 五、超级模型时代

```text
当前模型时代
皇帝 + 三省 Agent + 部级 Agent + Tool 群
                    │
                    │ 模型能力增强
                    ▼
高级模型时代
更少 Agent + 更长任务 + 更多内部综合
                    │
                    │ 可能出现超级模型
                    ▼
未来形态
一个或少数模型可承载多个角色

但始终：

同一模型承载多个角色 ≠ 多种权力合并
一次推理跨越多阶段   ≠ 中间语义消失
拥有全局知识         ≠ 拥有全局权限
能够自我改进         ≠ 能够自我批准
```

## 六、默认不可信边界

```text
网页 / 文档 / API / 用户输入
模型 / Tool / Skill / 插件 / 供应商
其他租户 / 联合成员 / 同行与联邦节点
Agent 计划 / 记忆 / 总结 / 解释 / 置信度
缓存 / 索引 / 图谱 / 历史产品
人工主张 / 专家意见 / 平台运营输入
外部系统“成功”响应
能力候选 / 新版本 / 评测结果
                    │
                    ▼
身份 + 来源 + 作用域 + 权限 + 证据 + 版本 + 质量 + 审计
                    │
                    ▼
              获得有限可信地位
```

不默认信任不等于拒绝，而是不允许未经转换直接进入权威链。

## 七、替换前六问

```text
它是稳定能力，还是时代性载体？
权威状态由谁接管？
拒绝、反证和封驳还能否独立发生？
作用域、证据、版本和责任是否仍可追踪？
能否单独撤销、停止、替换和回滚？
是否把隔离失效域合并成全局失效？
```

任一问题无可靠答案，不能仅因模型更强或成本更低而合并。

## 八、有意省略

- 超级模型能力预测；
- 单模型内部角色隔离方式；
- 组件和供应商迁移路线；
- 详细安全与供应链控制；
- 合并后的组织和权限矩阵。
