# TXT-0022：能力演进作用全域图

状态：Accepted

## 一、这张图回答什么

回答能力演进如何覆盖十面、横切治理、基础设施和架构本身，同时不成为能够修改一切的超级权力中心。

图中：

- `──▶` 表示观察、候选或作用；
- `══▶` 表示采用或发布决定；
- `◀──` 表示实际结果和反馈；
- `×` 表示作用于全部对象；
- 本图省略实验、发布、迁移和审批细节。

权威正文：[能力演进作用全域骨架](../evolution-across-entire-architecture.md)。

## 三、五级变更半径

```text
R1 局部替换
模型 / Tool / Prompt / 来源
        │
        ▼
R2 能力组合
Agent-Tool 分工 / Workflow / 检索 / 评测
        │
        ▼
R3 跨面协同
全局流 / 对象转化 / 产品纠正 / 运行形态
        │
        ▼
R4 治理语义
三省职责 / 授权 / 租户 / 证据 / 风险标准
        │
        ▼
R5 架构骨架
十面 / 核心对象 / 契约 / 尺度轴 / 生存底线

半径越大
══▶ 权威范围更广 + 验证范围更广 + 人类采用责任更高
```

代码改动大小不等于变更半径；改变权限语义的小配置也可能属于 R4。

## 四、三层嵌套循环

```text
┌──────── 局部能力循环 ────────┐
│ 观察 → 候选 → 评测 → 限域采用 │
└──────────────┬───────────────┘
               │ 多面共同缺口
               ▼
┌──────── 跨面系统循环 ────────┐
│ 对象 / 契约 / 状态 / 横切影响 │
│ → 端到端回归 → 治理与发布     │
└──────────────┬───────────────┘
               │ 一级结构压力
               ▼
┌────────── 架构循环 ──────────┐
│ 问题空间扫描 → 架构候选       │
│ → 七门闭合 → 人类采用 → 基线  │
└──────────────────────────────┘
```

三个循环共享演进语义，不要求使用同一个工作流或同等自治程度。

## 五、采用权不能被覆盖权吞并

```text
系统 Agent / 人类 / 外部变化
──▶ 提议

能力演进面
──▶ 实验与验证

对象所有面
──▶ 领域验收

智能治理 / 有权人类
══▶ 高影响采用

平台控制
══▶ 生产期望状态

运行面
──▶ 实际生效

覆盖全域 ≠ 拥有全域
提议权 ≠ 验证权 ≠ 采用权 ≠ 发布权 ≠ 生效状态
```

```text
                      /    |    \

```

## 七、自主程度与权力半径分离

```text
未来超级模型可以高度自主：
观察 / 生成候选 / 设计实验 / 执行评测

但不能自动：
扩大权限 / 改变主权 / 自批生产
采用 R4 治理变化 / 采用 R5 架构变化
```

人类主导演进也必须保留证据、版本、回归、回滚和影响记录。

## 八、稳定性裁定

```text
能力演进面：继续保留独立一级面
演进范围：覆盖十面、横切、基础设施与架构
采用权：留在对象所有者、治理、平台和有权人类
新增一级面：0
十面稳定性：保持

Skeleton v0.3
→ 尚待一屏全景汇总与一级稳定性复核
```
