# TXT-0017：非功能与生存性总图

状态：Accepted

## 一、这张图回答什么

回答天机阁在故障、攻击、误判、资源枯竭、区域中断和自身演进失败时，依靠哪些宏观结构保持合法、可信、可控、可停止并最终恢复。

图中：

- 方框表示逻辑能力组合或状态；
- `──▶` 表示防线推进；
- `×` 表示横切作用；
- `◀──` 表示纠正反馈；
- 本图有意省略安全控制、恢复步骤、SLO 和实现技术。

权威正文：[非功能与生存性骨架](../nonfunctional-and-survivability-skeleton.md)。

最低生存内核不是一套独立平台，也不是新的一级面。它是多个现有面必须共同保住的最小逻辑能力集合。

## 三、失效域与扩散边界

```text
[主体域]    用户 / Agent / 服务 / 运营者 / 外部参与者
[任务域]    Mission / Run / Task / Tool / 外部行动
[租户域]    朝廷 / 用户空间 / 联合空间
[知识域]    来源 / 事实 / 关系 / 研判 / 产品
[能力域]    模型 / Tool / Skill / 策略 / 工作流 / 版本
[供应域]    数据源 / 模型商 / 外部服务 / 人工协作
[区域域]    处理 / 存储 / 交付 / 行动区域
[平台域]    共享控制 / 数据底座 / 共同基础设施

任一域发生故障
      │
      ├──▶ [感知]
      ├──▶ [限制授权和传播]
      ├──▶ [隔离受影响范围]
      ├──▶ [显式降级或停止]
      └──▶ [恢复 + 派生影响纠正]

禁止：局部故障 ──无边界──▶ 全局污染
```

## 四、允许降级与不可降级

```text
可以降级：
覆盖范围 / 新鲜度 / 推理深度 / 响应速度
自动化程度 / 来源数量 / 模型与 Tool / 交付渠道

────────────────── 生存底线 ──────────────────

不可降级：
租户与权限边界
人类停止与接管
证据、不确定性与受损状态标记
高影响动作授权
审计与责任连续性
对未知、不完整和恢复状态的诚实表达

底线无法维持
→ 停止 / 隔离 / 等待有权人类
≠ 伪装为正常成功
```

## 五、人类控制链

```text
[观察]
   └──▶ [限制范围 / 资源]
            └──▶ [暂停新工作]
                     └──▶ [取消任务]
                              └──▶ [撤销能力 / 委托]
                                       └──▶ [隔离失效域]
                                                └──▶ [人类接管]
                                                         └──▶ [紧急停止]

重新启动
──必须经过──▶ [可信状态确认 + 显式恢复授权]
```

控制链可以由不同有权主体分级拥有，但不能依赖被控制 Agent 的自愿配合。

## 六、系统恢复的完整含义

```text
服务重新在线
        │
        ▼
数据与权威状态恢复
        │
        ▼
权限、策略和运行秩序恢复
        │
        ▼
错误事实、关系和研判纠正
        │
        ▼
产品、告警和外部影响纠正
        │
        ▼
事故证据进入能力演进

只恢复服务 ≠ 天机阁已经恢复
```

## 七、不可改变的中心

```text
Availability ≠ Legitimacy
Security ≠ Secrecy Without Accountability
Consistency ≠ One Unquestionable Global Claim
Degradation ≠ Silent Success
Recovery ≠ Service Restart
Explanation ≠ Model-generated Rationale
Autonomy ≠ New Authority
Evolution ≠ Permission to Rewrite History
```

## 八、有意省略

- 量化的可靠性与恢复目标；
- 威胁模型、攻击路径和控制清单；
- 具体隔离、切换、备份和重建机制；
- 一致性、复制和冲突解决方案；
- 隐私、合规和授权规则表；
- 紧急停止与恢复的详细流程。
