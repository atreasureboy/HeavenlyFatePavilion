# TXT-0015：天机阁七条全局流分离图

状态：Accepted

## 这张图回答什么

一条普通的“系统箭头”背后可能包含哪些完全不同的语义；控制、数据、知识、授权、预算、审计和反馈分别从哪里到哪里。

## 一、七流总览

```text
┌─────────────────────────────────────────────────────────────┐
│ 1. 控制流                                                   │
│ 人类/制度/触发 → 治理 → 运行编排 → 各面执行 → 实际状态回报 │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 2. 数据流                                                   │
│ 外部来源 → 原始资料 → 加工产物 → 数据底座 → 检索/产品/输出 │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 3. 知识形成流                                               │
│ Snapshot → Evidence → Claim → Fact → World State            │
│          → Assessment → Forecast/Risk → Product             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 4. 决定与授权流                                             │
│ 原生权威 → 身份/策略/许可/委托 → 边界判定 → 动作 → 撤销复核│
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 5. 预算与资源流                                             │
│ 平台容量/租户配额 → Mission → Run/Task → 消耗 → 结算/重规划│
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 6. 审计与证据流                                             │
│ 行为/决定/读写 → trace/血缘/版本 → 审计复核 → 异常与问责信号│
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 7. 反馈与演进流                                             │
│ 用户/现实/质量/成本/失败 → 纠正与缺口 → 治理 → 发布/回滚    │
└─────────────────────────────────────────────────────────────┘
```

## 二、控制流与数据流不能混写

```text
控制流：
仙人 → 皇帝/中书 → 门下决定 → 尚书统筹 → 运行面 → 执行者
                                                        │
                                                        └──状态回报──▶ 治理

数据流：
Source → Document/Snapshot → 解析产物 → Evidence/Fact → 数据底座
                                                           │
                                                           └──供应──▶ 研判/产品
```

```text
“命令数据认知面调查”是控制流
“把 Snapshot 交给解析器”是数据流
“接受 Claim 为 Fact”是知识与决定流
```

## 三、数据流与知识流不能混写

```text
数据流关注：
载荷在哪里、产生什么副本、经过什么加工、保存在哪里

知识流关注：
对象具有什么语义、依据什么证据、谁验证、当前是否争议
```

```text
Document 已到达系统
          ≠
Document 已被接受为 Evidence / Fact
```

## 四、控制流与授权流不能混写

```text
控制流：谁提出目标、谁规划、谁要求执行
授权流：该主体是否有权对该作用域执行该动作

[Command] ───────────────┐
                         ├──同时满足──▶ [Allowed Action]
[Authorization Decision] ┘
```

皇帝、三省或高能力 Agent 发出的命令同样必须经过授权边界。

## 五、预算流如何约束控制流

```text
平台容量
   ↓
租户配额
   ↓
Mission Budget
   ↓
Run Reservation ──约束──▶ 控制流可创建的 Task
   ↓
实际消耗
   ↓
结算 / 释放 / Budget Pressure
   └────────────────────▶ 重规划或人类决定
```

预算只约束可执行规模，不授予数据或行为权限。

## 六、审计流观察所有流

```text
控制流 ─┐
数据流 ─┤
知识流 ─┤
授权流 ─┼──产生──▶ trace / lineage / decision / ledger
预算流 ─┤                          │
反馈流 ─┘                          ▼
                              审计与复核
                                  │
                                  └──问题信号──▶ 控制/反馈流
```

审计可以发现问题，不能绕过治理直接修改业务状态。

## 七、反馈如何回到系统

```text
用户评价 ─────────┐
现实结果 ─────────┤
新证据/事实纠正 ──┤
预测评分 ─────────┼──▶ Feedback / Evolution Evidence
质量/成本/失败 ───┤               │
时代与供应商变化 ─┘               ├──▶ 目标/知识/产品纠正
                                  └──▶ 能力候选
                                           │
                                           ▼
                                      治理与发布
                                           │
                                           └──▶ 下一轮控制流
```

## 八、七流叠加的单次任务

```text
仙人要求调查企业
├── 控制流：形成 Mission 并调度调查
├── 数据流：采集网页、文件和记录
├── 知识流：形成证据、事实、关系与风险
├── 授权流：限制私有数据、Tool 和受众
├── 预算流：预留并消耗模型、搜索和人力
├── 审计流：记录决定、调用、版本和发布
└── 反馈流：结果评价和后续事实推动纠正/演进
```

这七条线共同完成一个任务，但任何一条都不能替代另一条。

## 九、箭头语义与刻意省略

- `→` 表示该小图标题所声明的主要流语义；
- 同一次交互可以在不同视图中出现，但解释不同；
- 本图不定义消息类型、字段、组件、存储和网络；
- 不画具体同步/异步和物理数据路径；
- 不新增一级逻辑面。
