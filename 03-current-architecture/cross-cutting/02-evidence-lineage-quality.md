# 证据、血缘与质量

状态：Accepted

## 一、双链模型

证据与质量必须同时沿两条链传播：

```text
认知血缘链
Source → Document → Snapshot → Evidence → Claim → Fact
→ Entity / Relationship / Event / Change

研判与产品链
Fact / Disputed Claim → Assessment → Forecast → Risk
→ Recommendation → Intelligence Product / Alert
```

每个派生对象都保存输入引用、处理/模型/规则版本、生成主体、时间、作用域和质量结果。下游不能只保存最终文本。

## 二、证据要求档位

第一版支持四级 `Evidence Requirement`：

| 档位 | 适用 | 最低行为 |
|---|---|---|
| Overview | 探索、导航、低影响问答 | 可以使用未完全验证主张，但必须显式标记 |
| Standard | 常规情报产品 | 关键结论具有可追溯证据和基本交叉验证 |
| Strict | 尽调、敏感研判、高影响告警 | 强来源独立性、反证、时效与门下审核 |
| Expert | 受监管或重大争议 | 专家/人类裁定、完整证据包和不可抵赖记录 |

档位决定验证深度，不改变 Claim、Fact、Assessment 的类型边界。

## 三、质量剖面

质量不是单一分数。`Quality Profile` 至少包含：

- 来源可靠性；
- 证据完整性；
- 来源独立性；
- 新鲜度与时间适用性；
- 抽取和解析质量；
- 实体消歧置信度；
- 事实一致性与争议状态；
- 推理可解释性；
- 预测可校准性；
- 产品引用覆盖率。

领域能力面可以定义领域阈值；平台控制面维护可执行的质量政策版本；智能治理面决定高影响例外。

## 四、控制点

| 阶段 | 控制 |
|---|---|
| 来源准入 | 许可、可靠性、可用性与采集完整性 |
| 快照形成 | 内容哈希、时间、原件引用和解析版本 |
| Claim 提取 | Evidence 必须定位到具体片段或记录 |
| Fact 接受 | 验证规则、冲突检测、领域与治理审核 |
| 实体关联 | 不确定性、候选集合和禁止合并条件 |
| 研判 | 事实/假设分离、反证、失效条件和置信表达 |
| 预测 | 时间窗、基准、概率/区间和到期评分 |
| 产品发布 | 引用覆盖、有效版本、受众适配和更正机制 |
| 演进 | 基准集、回归评测、租户隔离和发布门 |

## 五、纠正传播

```text
新证据挑战 Fact
→ Fact 进入 UnderReview / Disputed / Retracted / Superseded
→ 血缘查询定位受影响的研判、预测、风险、告警和产品
→ 按影响等级创建重评任务
→ 受影响产品标记 CorrectionRequired 或 Withdrawn
→ 用户与下游收到可追踪的更正
```

纠正传播是事件驱动的影响分析，不是原地改写历史。

## 六、不变量

- Document、Evidence、Claim、Fact、Assessment 和 Recommendation 不得互相冒充。
- 没有 Evidence 的 Claim 不能提升为 Verified Fact。
- 事实状态由验证决定，不由租户偏好、模型自信或产品措辞决定。
- 任何研判必须区分输入事实、假设、推理和不确定性。
- 质量降级必须影响状态或产品标记，不能只写入内部日志。
- 上游撤回不能让下游继续无提示地保持“已验证”外观。
- 证据标准是 Mission 承诺的一部分；预算优化不得静默降低它。
- 来源、模型、Tool 或区域数量不能直接证明独立性；共享依赖与共同失效根必须进入血缘和质量判断。
- 对象跨作用域、辖域或系统传播后，来源限制、纠正义务和受影响关系不能从血缘中消失。

## 七、异常路径

```text
证据缺失       → EPI → Returned / EvidencePending
来源冲突       → EPI → Disputed Claim → 大理寺或人类裁定
消歧不足       → QLT → 保留候选，不合并实体
血缘断裂       → S3 → 隔离派生结果，重新构建或撤回
质量阈值不满足 → QLT → 重试、换源、降级或门下封驳
模型退化       → EVO/QLT → 停止版本扩散、回滚并重评受影响结果
```
