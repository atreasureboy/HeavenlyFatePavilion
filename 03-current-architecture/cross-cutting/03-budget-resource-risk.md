# 预算、资源与风险

状态：Accepted

## 一、预算的三层结构

```text
Tenant Budget / Quota
└── Mission Budget Envelope
    └── Run / Task Reservation and Consumption
```

预算至少覆盖：

- Token 与模型费用；
- Tool/API 调用费用；
- 计算、存储和网络；
- 时间与截止期；
- 并发槽位；
- 人类专家与审核资源；
- 外部数据许可或付费查询；
- 最大调查范围。

户部可以作成本解释、预测和“哭穷”建议；平台控制面的预算账本与运行时强制点才拥有扣减、预留和阻断权。

## 二、预算生命周期

```text
政策分配
→ Mission 估算与批准
→ Run 预留
→ Task 分配
→ 调用前检查
→ 实际计量
→ 结算/释放
→ 偏差分析与反馈
```

并行任务必须先预留再消费，避免每个子 Agent 都把同一剩余预算视为可用。重试和补偿同样计量。

## 三、预算不足的语义化响应

预算不足不直接等于失败：

1. 使用已有事实、缓存或确定性 Tool；
2. 减少无关搜索分支；
3. 调低模型等级但保持验收标准；
4. 缩小范围并明确影响；
5. 返回 `Degraded` 的部分结果；
6. 发出结构化 Budget Pressure Event，请求追加或重新排序；
7. 若最低证据或安全条件无法满足，则停止而不是伪造完整性。

## 四、风险分层

风险上下文至少由以下因素构成：

```text
数据敏感度
+ 动作可逆性
+ 外部影响
+ 证据不确定性
+ 受众与传播范围
+ 监管/地域约束
+ 模型与工具可信度
= Risk Tier
```

第一版使用四级任务风险：

| 等级 | 典型行为 |
|---|---|
| R0 | 低影响只读与公开资料导航，可采用简化治理路径 |
| R1 | 常规调查和内部产品，标准证据与抽样审核 |
| R2 | 敏感数据、高影响研判或外部告警，加强门下审核和工具限制 |
| R3 | 不可逆外部动作、重大合规或跨租户事件，必须显式人类批准 |

风险级别只可由授权规则降低；Agent 可以建议，不能自行宣布降级。

## 五、风险与成本的联合策略

```text
低风险 + 低复杂度 → 缓存 / Tool / 模板优先
低风险 + 高复杂度 → 并行 Tool + 按需领域 Agent
高风险 + 低复杂度 → 确定性校验 + 独立审核
高风险 + 高复杂度 → 多源调查 + 反证 + 门下 + 人类升级
```

节省 Token 的对象是执行方法和上下文规模，不是权限、证据、审核与审计承诺。

## 六、不变量

- 每个 Run 必须关联预算包和账本。
- 预算预留、消费、释放和追加必须可追踪且幂等。
- 超预算不能靠删除审计、跳过权限或降低未获批准的证据标准解决。
- 高风险任务不能仅因预算不足自动变成低风险任务。
- 低风险任务不必机械启动完整三省和全部部级 Agent。
- 模型、Tool 和人类资源都纳入同一 Mission 成本视图。
- 成本建议与成本强制权分离。

## 七、异常路径

```text
估算超预算     → 中书重规划 / 仙人追加 / 缩小目标
预留失败       → Run 保持 Scheduled，不创建不可供给任务
调用将超预算   → 运行时阻断，产生 BUD Exception
账本不一致     → S3 暂停相关消费，平台控制面对账
风险级别升高   → 重新授权、提高审核和预算，或取消路径
安全最低线冲突 → 安全与授权优先；预算不能作为绕过理由
```
