# 多租户、身份与授权

状态：Accepted

## 一、作用域模型

天机阁采用显式作用域层级：

```text
Platform
├── Public Scope
├── Tenant
│   ├── Tenant Shared Scope
│   ├── User Private Workspace
│   └── Restricted Project Scope
└── Collaboration Space
    └── 由多个租户显式授权形成，不等于租户合并
```

公共作用域也是一种有名称、有所有者、有准入规则的作用域，绝不能用空 `tenant_id` 表示。

## 二、数据组合规则

租户看到的世界状态是受策略约束的组合视图：

```text
合法公共基线
+ 租户私有覆盖层
+ 当前用户可见工作空间
+ 当前联合空间授权数据
- 撤回、屏蔽、地域和生命周期约束
= 当前请求可见视图
```

私有覆盖可以增加租户判断、标签和研判，但不能悄悄改写公共事实的身份与验证状态。若租户对公共事实提出异议，应创建有作用域的挑战或候选纠正。

## 三、主体与身份

主体至少包括：

- 平台运营者；
- Tenant Owner / Admin；
- 仙人及普通租户成员；
- 外部协作者和人类专家；
- 皇帝稳定身份；
- Agent Instance；
- Service / Worker；
- Tool、模型和外部系统身份。

人类身份、Agent 身份和服务身份必须分离。Agent 代表某主体执行，不继承该主体未显式委托的全部权力。

## 四、授权模型

有效授权由以下部分共同决定：

```text
主体身份
∩ 当前租户和数据作用域
∩ 角色与属性策略
∩ 显式能力授权
∩ 委托链
∩ 资源与风险条件
∩ 动作对象的当前状态
= 本次允许动作
```

授权不是一句“可以访问”的布尔值，而是对 `subject + action + resource + scope + conditions` 的判定。

委托链必须满足：

- 委托者确实拥有被委托能力；
- 子委托不扩大权限；
- 委托带有租户、用途、期限、预算和可再委托条件；
- 撤销和到期能够传播到未完成的 Run；
- 最终动作能追溯到人类、系统政策或合法自动授权来源。

## 五、强制点

| 边界 | 必须检查 |
|---|---|
| 通政司/交互入口 | 租户、会话、主体与渠道绑定 |
| 跨面契约 | 发送者身份、接收面、作用域和委托链 |
| 数据查询与写入 | 行/对象/字段作用域、用途和生命周期 |
| 检索与索引 | 结果级权限过滤，禁止先召回后靠 Agent 隐去 |
| 缓存 | Key 必须绑定作用域、权限策略版本和失效条件 |
| Agent/Tool/模型网关 | 能力令牌、参数范围、数据出境和预算 |
| 产品生成与分发 | 受众、内容引用、渠道和再传播权限 |
| 演进与评测 | 训练/评测数据用途授权和租户隔离 |

## 六、不变量

- 任一对象必须有显式作用域；公共不是空作用域。
- 跨租户共享必须由有名称的共享政策或联合空间授权，禁止隐式推断。
- 平台运营权不自动产生租户业务数据使用权。
- Agent 不得通过再委托获得其发起者没有的权限。
- 检索、向量索引、缓存、日志和模型输入同样受租户边界约束。
- 权限检查必须在副作用之前完成。
- 权限改变后，长时运行任务必须在关键副作用点重新判定。

## 七、异常路径

```text
作用域缺失/冲突 → CTX 异常 → 拒绝并返回入口或平台控制面
身份可信度不足 → POL 异常 → 重新认证或降低可执行动作
委托链断裂     → POL 异常 → 停止子任务，撤销未使用能力令牌
跨租户命中     → S4 隔离事件 → 阻断、保全审计、人工调查
策略版本过期   → Deferred → 刷新策略后重新判定，不沿用旧许可
```
