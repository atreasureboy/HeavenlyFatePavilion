# 皇帝与三省映射

状态：Accepted

## 一、总体映射

| 机构 | 主要一级面 | 核心能力 | 基础形态 |
|---|---|---|---|
| 皇帝 | 智能治理面；在人机交互面投影 | 全局统筹、Intent→Mission、关系治理、最终解释 | Stable Identity + Agent Role + Interaction Projection |
| 中书省 | 智能治理面 | Mission 起草、Plan 设计、验收与证据条件 | Agent Role + Planning Tools |
| 尚书省 | 智能治理面 | 执行统筹、跨部编排、优先级和结果汇集 | Agent Role + Workflow View |
| 门下省 | 智能治理面 | 独立审议、反证、封驳、降级和发布复核 | Agent Role + Verification Tools + Deterministic Gates |

## 二、皇帝

### 逻辑身份

皇帝是租户级稳定逻辑身份，承担：

- 天机阁对仙门的统一人格；
- 长期关系和责任连续性；
- 全局 Mission、运行和情报态势视图；
- 主动提醒和升级；
- 最终解释和人类介入协调。

### 技术分解

```text
皇帝
├── 稳定身份记录                         [平台控制 / 数据底座]
├── Court Profile 绑定                   [平台控制]
├── 皇帝交互投影                         [人机交互]
├── 皇帝治理 Agent Role                  [智能治理]
├── 按需运行实例                         [智能运行]
├── 权威对象查询与态势视图               [数据底座 / 产品]
└── 决定、解释与审计记录                 [智能治理 / 数据底座]
```

### 不拥有

- 全部数据的唯一副本；
- 无限权限和无限预算；
- 绕过三省的默认权力；
- Scheduler、数据库或 Policy Engine；
- 每个领域的全部专业知识；
- 永久常驻的大模型进程。

## 三、中书省

### 能力映射

```text
Intent 解释与 Mission 形成
验收、证据、预算和风险条件定义
Plan 设计、分解和版本化
候选六部与能力选择
替代方案和调查路径设计
```

### 技术形态

- 中书省稳定 Agent Role；
- 按 Mission 实例化的规划 Agent；
- 计划模板、能力目录查询和估算 Tool；
- Plan 和起草依据的持久记录。

### 非职责

- 不直接执行 Task；
- 不直接抓取资料；
- 不自行批准自己的 Plan；
- 不把规划假设写成 Fact；
- 不拥有 Agent Template 和能力目录。

## 四、尚书省

### 能力映射

```text
执行统筹
跨部编排
优先级和资源申请
运行状态解释
动态改道与降级建议
结果汇集和奏报
```

### 技术形态

- 尚书省稳定 Agent Role；
- 面向 Mission 的统筹 Agent 实例；
- 对执行图、Run 状态和能力目录的治理视图；
- 向运行面发出版本化 Execution Request。

### 与 Scheduler 的边界

```text
尚书省
→ 判断调用哪些能力、为何调整路径、何时升级

Scheduler
→ 排队、租约、并发、重试、Worker 分配和状态机
```

尚书省不亲自实现队列和重试；Scheduler 也不能自行改变 Mission 目标。

## 五、门下省

### 能力映射

```text
Plan 独立审议
证据标准检查
反证和替代解释
事实与研判边界检查
质量降级
封驳与退回
发布前复核
```

### 技术形态

- 门下省稳定 Agent Role；
- 按高影响任务实例化的审核 Agent；
- 证据覆盖、类型校验、来源独立性和一致性 Tool；
- 不可绕过的审核状态与 Decision 记录。

### 与其他审查主体的边界

```text
门下省：对计划和结果作治理审核
刑部：提供法规、合规和风险领域知识
大理寺：处理事实和主张冲突
都察院：持续审计系统行为和质量
```

## 六、三省并非固定流水线

```text
高影响新调查
→ 中书起草 → 门下审议 → 尚书统筹 → 门下复核

低风险已验证查询
→ 皇帝按治理策略读取权威事实并回答

持续监测触发
→ 既有 Mission Template → 运行面执行
→ 异常或高风险结果升级三省
```

是否实例化某省 Agent 由 Mission 类型、风险、证据和治理策略决定；相应权力和审计语义始终存在。
