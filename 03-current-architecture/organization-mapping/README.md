# 天机阁组织—技术映射

状态：Accepted

## 一、用途

本目录将“皇帝—三省—六部—公共官署”的叙事组织映射到十面能力树、Agent 角色、确定性服务、策略引擎和数据系统。

## 二、五层映射模型

```text
叙事机构
→ 逻辑职责与权力
→ 所属一级面和能力
→ Agent / Tool / Service / Store / Policy 形态
→ 运行实例和持久状态
```

五层不能混写。例如：

```text
尚书省 ≠ Scheduler
工部 ≠ 基础设施本身
国史馆 ≠ 一种数据库产品
枢密院 ≠ 一个安全 Agent
皇帝身份 ≠ 永久常驻模型进程
```

## 三、映射规则

- 官制是组织与治理视图，不是完整技术分层；
- 一个机构可以协调多个能力，但每个能力仍只有一个主要所有面；
- 一个机构可以由多个技术组件共同实现；
- 同一技术服务可以被多个机构使用，但不能因此改变能力所有权；
- Agent 只承担开放式理解、判断、反证和综合；
- 状态机、权限强制、记账、存储、调度和审计优先确定性化；
- 机构名称保留叙事价值，正式技术语义必须另行声明；
- 暂不启用的职责保留为 `Reserved`，不强行赋予当前系统。

## 五、实现形态

| 形态 | 含义 |
|---|---|
| Stable Identity | 长期存在的逻辑身份和审计主体 |
| Agent Role | 可按需实例化的复杂认知角色 |
| Tool / Worker | 确定性处理或专用模型执行 |
| Service | 稳定系统能力和协议边界 |
| Policy Engine | 不可绕过的规则和策略强制 |
| Data System | 权威状态、版本、索引和血缘 |
| Human Role | 人类决定、专家复核和责任主体 |

一个机构通常是多种形态的组合，而不是单一进程。
