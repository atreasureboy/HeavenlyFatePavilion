# 六部映射与部级能力模板

状态：Accepted

## 一、六部共同模板

六部是领域能力包，不是六套独立平台。

```text
Ministry Capability Package
├── 领域使命与边界
├── 领域本体和术语
├── 领域来源与证据标准
├── 部级 Agent Role
├── 领域 Tool / Skill / Model
├── 领域认知扩展
├── 领域研判框架
├── 领域质量与评测
├── 领域产品模板
└── 与其他部和共享主干的契约
```

每一部都使用共享的运行时、数据底座、认知主干、研判主干、控制面和产品能力。

## 二、六部总览

| 部 | 领域使命 | 部级 Agent | Tool 倾向 | 特殊状态 |
|---|---|---|---|---|
| 吏部 | 人物、组织、身份、履历与关系 | 身份争议和人物综合 | 消歧、履历、关系、变化 | Agent 任免职责 Reserved |
| 户部 | 商业、市场、资源、机会与成本 | 商业解释和资源建议 | 指标、评分、计量、账簿 | 预算顾问，不是强制点 |
| 礼部 | 观点、传播、舆情、叙事与文化 | 观点演变和叙事解释 | 抓取、聚类、热度、传播 | 混合 |
| 兵部 | 时政、地缘、安全、冲突与影响 | 局势和影响链研判 | 事件、政策、制裁、风险 | 混合 |
| 刑部 | 法规、合规、争议、风险与裁定知识 | 规则空白与高风险解释 | 法规检索、规则引擎、检测 | Tool 偏重 |
| 工部 | 技术、产品、工程、来源与工具知识 | 技术路线和异常解释 | 技术检索、工程分析 | 平台工程职责需映射分离 |

## 三、吏部

### 当前启用

- 人物和组织本体；
- 身份解析、同名消歧和实体合并专业规则；
- 履历、任职、关系与变化解释；
- 人物和机构综合画像；
- 人物来源与证据标准。

### 默认形态

```text
吏部主官 Agent
+ 身份解析 Tool
+ 履历时间线 Tool
+ 关系和任职变化 Tool
+ 人物领域索引与规则
```

### Reserved：Agent 任免

Agent 注册、模板、启停和能力版本当前属于平台控制面，不由业务吏部掌握。未来若出现真正的 Agent 官员选拔、考核、升迁和组织设计需求，再评估“平台吏部”或独立治理能力。

## 四、户部

### 领域职责

- 商业、融资、价格、招聘和市场指标；
- 机会与利益关系分析；
- 付款方、资源方和商业逻辑；
- 项目资源价值和投入产出解释。

### 资源治理叙事职责

户部同时作为资源顾问和账簿叙事：

```text
平台控制面
→ 拥有预算、配额、计量和强制上限

户部 Tool
→ 读取账簿、分析消耗、预测资源压力

户部主官 Agent
→ 解释成本、提出调整建议、向皇帝“哭穷”

智能治理面 / 仙人
→ 决定是否追加、降级或调整目标
```

“哭穷”正式语义是结构化 Budget Pressure Event，不是 Agent 的情绪化自由发挥。

### 非职责

- 不绕过平台策略直接增加预算；
- 不成为 Token 计量的唯一权威服务；
- 不因掌握商业领域而拥有所有资源分配权。

## 五、礼部

### 当前启用

- 博客、新闻、社交内容和公开表达领域知识；
- 观点、立场、叙事、情绪和传播关系；
- 人物观点时间线；
- 叙事聚类、传播路径和热度变化；
- 多语言与文化语境解释。

### 默认形态

礼部主官 Agent 负责语义解释；抓取、聚类、时间线、热度和传播统计由 Tool 或专用模型完成。

礼部不拥有渠道接入和产品分发，二者分别属于人机交互面和情报产品面。

## 六、兵部

### 当前启用

- 时政、地缘、国家、地区和安全领域本体；
- 冲突、制裁、政策和安全事件；
- 局势、影响链、升级路径和外溢判断；
- 区域风险与持续监测标准；
- 跨国、跨领域联合研判。

### 默认形态

兵部主官 Agent 负责局势综合和影响解释；事件采集、时间线、政策查询、制裁匹配和基础评分由 Tool 完成。

兵部的“战事”是情报领域语义，不自动赋予对外行动或攻击能力。

## 七、刑部

### 当前启用

- 法规、政策、合规、争议和风险领域本体；
- 法规检索、版本对比和适用性；
- 敏感信息、合规条件和规则冲突；
- 高风险结论与规则空白解释；
- 事实争议的领域意见。

### 默认形态

```text
确定性法规与策略 Tool
+ 规则引擎
+ 冲突和敏感检测
+ 高风险刑部 Agent
```

### 与门下和大理寺的边界

- 刑部提供领域知识和风险意见；
- 门下省决定任务或结果是否通过治理审核；
- 大理寺处理 Claim / Fact 冲突的裁定流程；
- 枢密院执行不可绕过的权限和策略。

## 八、工部

### 领域职责

- 技术、产品、工程、工具链和技术组织领域知识；
- 技术路线、架构、产品演进和工具生态分析；
- 采集、解析和索引方案的专业建议；
- 工程异常与技术线索解释。

### 平台工程叙事职责

“工部建设系统”的叙事可以覆盖多个技术面，但不改变技术所有权：

```text
采集与解析能力      → 数据认知面
Agent / Tool 运行   → 智能执行与运行面
数据存储与索引      → 数据底座面
Tool / Model 目录   → 平台控制面
计算、网络和部署    → 基础设施
```

工部可以作为这些能力的组织管理或建设叙事，但不能在逻辑架构中吞并它们。

### 默认形态

工部领域 Tool 和 Service 为主；只有技术路线解释、复杂诊断和新方案设计使用 Agent。

## 九、跨部协作

```text
尚书省
→ 创建联合调查契约
→ 指定主责部和参与部
→ 各部输出带领域边界的结果
→ 跨部综合由治理与研判能力完成
→ 门下省审核是否越过各部证据边界
```

联合调查不把六部上下文无控制地合并成一个超级 Prompt。
