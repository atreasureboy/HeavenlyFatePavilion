# 天机阁十面输入输出契约

状态：Accepted

生效日期：2026-07-24

## 一、目的

本文为十个一级逻辑面建立第一版边界契约，固定每个面的：

- 接受输入；
- 产生输出；
- 权威状态；
- 上游和下游依赖；
- 拒绝、退回或降级条件；
- 失败反馈方向。

这些是逻辑契约，不规定同步或异步协议、消息中间件、API 风格和物理服务数量。

## 二、跨面交互类型

一级面之间只通过可识别的契约类型协作，不以无类型自然语言、共享数据库写入或隐式模型上下文代替契约。

```text
Command
请求接收方执行某项有边界的动作

Query
请求读取权威状态或计算视图，不改变业务状态

Result
对 Command 或 Query 的结构化结果

Event
已经发生的事实、状态变化或观察

Decision
有权主体作出的批准、拒绝、封驳、裁定或采用决定

Feedback
对目标、结果、事实、研判、产品或能力的结构化评价与纠正
```

Command 表达请求，不等于接收方必须执行；Event 表达已经发生，不得伪装成命令；Decision 必须来自具有相应决定权的主体。

## 三、通用契约信封

每次跨面交互必须能够解析以下语义：

```text
Plane Contract Envelope
├── contract_id
├── contract_type
├── contract_name / schema_version
├── sender_plane / sender_subject
├── receiver_plane
├── tenant_scope
├── actor_context
├── mission_id / run_id / task_id
├── court_profile_version
├── payload_refs
├── preconditions
├── expected_result
├── evidence_requirement
├── authorization_context
├── budget_context
├── risk_context
├── quality_context
├── lifecycle_context
├── deadline / priority
├── idempotency_key
├── trace_id / causation_id
└── failure_route
```

并非每次交互都需要物理携带所有字段，但所有必需语义必须可解析且不能静默丢失。

## 四、统一响应与失败语义

```text
Accepted
接收并承诺处理

Completed
已完成并产生符合契约的 Result

Rejected
输入不合法、无权、越界或不属于本面责任

Returned
信息、证据、预算或验收条件不足，退回补充

Deferred
等待依赖、时间窗、人类决定或外部条件

Degraded
无法满足完整质量，但在显式降级条件下返回有限结果

Failed
处理失败，附可分类原因、已完成副作用和重试建议

Cancelled
经授权终止
```

任何失败都必须返回结构化原因和原始契约引用。不得只记录“Agent 失败”或把异常文本吞入聊天记录。

## 五、人机交互面契约

### 5.1 接受输入

- 仙人的消息、目标、问题、资料、决定和反馈；
- 外部渠道的消息、回执和交互事件；
- 情报产品面的 Product、Alert 和交付状态；
- 智能治理面的 Mission 状态、Decision 和人类介入请求；
- 平台控制面的租户交互配置与皇帝人格版本。

### 5.2 产生输出

- Intent；
- Feedback；
- Human Decision；
- 用户资料接收引用；
- 向智能治理面的目标解释请求；
- 向情报产品面的呈现、订阅和分发偏好；
- 对外回复、通知、追问和交付确认。

### 5.3 权威状态

- 会话与渠道状态；
- 皇帝交互投影状态；
- 消息和交付回执；
- 用户显式表达的交互偏好。

长期事实、Mission 和情报产品不由本面拥有。

### 5.4 依赖

- 平台控制面解析租户、身份和交互配置；
- 智能治理面解释目标和发起 Mission；
- 情报产品面提供可交付对象；
- 数据底座面提供会话与交互记录的持久化。

### 5.5 拒绝或退回

- 无法解析主体或租户；
- 消息缺少完成高影响决定所需的明确性；
- 请求需要的决定权不属于当前主体；
- 产品或告警缺少可呈现版本；
- 渠道不支持所要求的内容或确认机制。

### 5.6 失败反馈

交互解析失败退回用户澄清；身份或策略问题交平台控制面；Mission 解释问题交智能治理面；交付失败交情报产品面并产生可重试事件。

## 六、情报产品面契约

### 6.1 接受输入

- 已审核的 Fact、Assessment、Forecast、Risk 和 Recommendation 引用；
- 智能治理面的发布、限制、撤回和更正 Decision；
- 人机交互面的受众、渠道、语言和呈现要求；
- 平台控制面的产品模板、订阅和租户品牌配置；
- 数据底座面的权威对象版本和血缘。

### 6.2 产生输出

- Intelligence Product；
- Alert；
- 产品草稿、审核包和发布版本；
- 分发请求和交付状态；
- 更正、撤回和替代关系；
- 产品质量和使用反馈事件。

### 6.3 权威状态

- 产品定义、版本和发布状态；
- Alert 的投递、确认和跟踪状态；
- 产品与底层对象的引用关系；
- 订阅实例与分发记录。

### 6.4 依赖

- 数据底座面供应权威对象和版本；
- 智能治理面提供发布决定和限制；
- 人机交互面及外部渠道完成交付；
- 平台控制面提供模板和订阅策略。

### 6.5 拒绝或退回

- 关键结论缺少证据或审核状态；
- Fact、Assessment、Forecast、Risk 被混写；
- 引用版本已失效或正在争议；
- 产品要求超出已批准结论；
- 受众、作用域或分发渠道不明确。

### 6.6 失败反馈

内容问题退智能治理或研判面；数据版本问题退数据底座面；渠道问题退人机交互面；已发布产品受事实更正影响时创建重新评估和更正任务。

## 七、数据认知面契约

### 7.1 接受输入

- Mission、Plan 和认知 Task；
- Source、Document、Snapshot 和既有 Fact；
- 领域能力面的本体、解析规则、来源策略和质量标准；
- 平台控制面的来源、Tool、模型和处理策略版本；
- 研判面发起的补证、重新联结和变化验证请求。

### 7.2 产生输出

- Snapshot 处理结果；
- Evidence；
- Claim 和 Verification Package；
- Entity、Relationship、Event 和 Change；
- Fact 候选、争议包和纠正建议；
- 数据质量、来源健康和认知失败事件；
- 反向补充采集或人工消歧请求。

### 7.3 权威状态

本面拥有认知形成语义和处理规则的应用结果，不直接拥有底层持久化实现。权威对象版本写入数据底座面。

### 7.4 依赖

- 智能执行与运行面执行采集、解析、Tool 和模型调用；
- 数据底座面供应并保存资料和认知对象；
- 领域能力面提供领域语义；
- 智能治理面或指定验证主体接受、争议或退回高影响 Fact 候选。

### 7.5 拒绝或退回

- Source 作用域、许可或版本不明；
- Snapshot 无法定位或完整性不足；
- Claim 缺少 Evidence；
- 实体消歧置信度不足且无法安全合并；
- 变化缺少前态、后态或时间语义；
- 请求要求把模型输出直接写成 Fact。

### 7.6 失败反馈

采集和执行失败交运行面；领域歧义交领域能力面；证据不足交治理面或上游 Mission；冲突无法裁定时产生 Disputed Claim，不强制输出唯一 Fact。

## 八、情报研判面契约

### 8.1 接受输入

- 已验证 Fact 和明确标记的 Disputed Claim；
- Entity、Relationship、Event、Change 和 Signal；
- Mission 的研判目标、时间范围和验收条件；
- 领域能力面的领域知识、指标、模型和解释框架；
- 历史 Assessment、Forecast、Risk 及结果反馈。

### 8.2 产生输出

- Signal；
- Assessment；
- Forecast；
- Risk；
- Recommendation；
- 假设、反证、失效条件和不确定性；
- 补证 Mission 或认知请求；
- 研判质量和校准事件。

### 8.3 权威状态

本面拥有研判形成语义、假设、模型输入输出关系和研判状态；持久版本由数据底座面保存。

### 8.4 依赖

- 数据底座面提供权威事实和历史研判；
- 数据认知面补充证据、关联和变化；
- 领域能力面提供专业解释；
- 智能治理面审核高影响研判和发布用途；
- 运行面执行模型、工具和情景计算。

### 8.5 拒绝或退回

- 输入只有未经验证 Claim，却要求确定性 Assessment；
- 时间范围、目标或基准不明确；
- 预测缺少假设、区间或失效条件；
- 风险缺少对象、可能性、影响或触发条件；
- 要求将 Recommendation 当成 Decision；
- 证据冲突足以使结论无法校准。

### 8.6 失败反馈

证据缺口退数据认知面并可创建新 Mission；领域不足退领域能力面；模型或计算失败交运行面；高不确定性结果向治理面申请降级、专家复核或停止发布。

## 九、智能治理面契约

### 9.1 接受输入

- Intent 和 Feedback；
- Court Profile、Policy、Budget 和能力目录；
- 领域能力说明；
- Run、Task 和执行状态；
- Fact、争议、Assessment、Forecast、Risk 和产品草稿；
- Evolution Candidate 和评测结果；
- 人类 Decision。

### 9.2 产生输出

- Mission；
- Plan；
- Decision；
- 审核、封驳、退回、降级和升级决定；
- 执行编排要求；
- 证据和验收标准；
- 人类介入请求；
- 事实争议、产品发布和演进采用的治理记录。

### 9.3 权威状态

- Mission、Plan 和 Decision；
- 治理议程、审议意见和责任链；
- 批准的验收标准、风险条件和升级路径。

### 9.4 依赖

- 人机交互面提供原始意图和人类决定；
- 平台控制面提供长期政策与能力目录；
- 领域能力面提供专业可行性；
- 运行面报告实际执行；
- 数据底座面保存治理记录；
- 其他各面提供待审对象。

### 9.5 拒绝或退回

- Intent 无法形成可验证 Mission；
- Plan 缺少证据、预算、风险或验收条件；
- 请求超出当前能力、作用域或决定权；
- 执行结果不能证明满足 Plan；
- 发布或演进候选缺少独立验证；
- 三省意见冲突尚未裁定。

### 9.6 失败反馈

目标问题退人机交互面；能力问题退领域或平台控制面；执行问题退运行面；证据问题退认知或研判面；无法内部裁定时升级仙人或人类专家。

## 十、领域能力面契约

### 10.1 接受输入

- Mission、Plan 和领域问题；
- 领域相关 Source、Fact、世界状态和历史研判；
- 认知面与研判面的专业能力请求；
- 平台控制面的领域能力版本；
- 其他部的联合研判请求。

### 10.2 产生输出

- 领域本体、术语和对象扩展；
- 领域来源、规则、Tool、Skill 和模型选择建议；
- 部级 Agent 研判结果；
- 领域质量标准和验收规则；
- 跨部依赖和联合研判包；
- 领域能力缺口与演进证据。

### 10.3 权威状态

- 领域本体和规则的逻辑版本；
- 领域能力说明；
- 领域来源与质量标准；
- 部级能力模板实例。

正式发布版本由平台控制面管理，领域对象记录由数据底座面保存。

### 10.4 依赖

- 数据底座面供应领域对象；
- 认知和研判面提供共享主干；
- 运行面执行领域 Agent 和 Tool；
- 平台控制面提供能力版本和预算；
- 智能治理面决定跨部任务与高影响结论。

### 10.5 拒绝或退回

- 问题不属于本部领域且无合理协作路径；
- 所需领域语义或来源不存在；
- 请求要求复制通用平台能力；
- 跨部冲突没有治理主体；
- 领域结论超出证据和专业边界。

### 10.6 失败反馈

错配任务退智能治理面重新分部；领域数据缺口退认知面；执行失败交运行面；跨部冲突交尚书省统筹或门下、大理寺式治理能力裁定。

## 十一、智能执行与运行面契约

### 11.1 接受输入

- 已批准 Plan 和执行图要求；
- 平台控制面下发的 Agent Template、Workflow、Policy、Budget 和版本；
- 各业务面的 Command、Query 和 Task；
- Tool、模型、Worker 和外部服务能力描述；
- 暂停、取消、接管和恢复 Decision。

### 11.2 产生输出

- Run、Task 和 Execution Event；
- Agent、Tool、模型和 Worker 调用结果；
- Artifact；
- 实际预算、延迟、质量和资源状态；
- 重试、补偿、降级和失败报告；
- 人类接管和治理升级请求。

### 11.3 权威状态

- Run 和 Task 的即时执行状态；
- Agent 实例、上下文和 Workspace 生命周期；
- 调度、租约、重试、取消和恢复状态；
- 执行事件和调用链。

### 11.4 依赖

- 平台控制面提供期望状态；
- 智能治理面提供批准范围和停止条件；
- 数据底座面保存执行记录和读取业务对象；
- 基础设施提供计算、网络、队列、沙箱和可观测能力。

### 11.5 拒绝或退回

- Plan 未批准或版本不一致；
- Context Envelope 不完整；
- Tool、模型、凭证或能力未注册；
- 预算、并发、深度或时间限制不足；
- 请求要求运行面自行扩大目标、权限或风险；
- 幂等和补偿条件不满足。

### 11.6 失败反馈

资源和技术失败回报调用面及平台控制面；目标或授权冲突升级智能治理面；部分结果必须标记完成度和副作用；不可恢复失败终止 Run 或进入显式降级状态。

## 十二、数据底座面契约

### 12.1 接受输入

- 各面提交的有类型对象、版本和血缘；
- Query、索引、订阅和历史读取请求；
- 更正、撤回、失效和生命周期 Decision；
- 平台控制面的作用域、保留和数据策略；
- 外部资料的原始内容引用和快照。

### 12.2 产生输出

- 权威对象 ID、版本和读取结果；
- Snapshot、Evidence、Fact、世界状态、研判和产品的供应视图；
- 血缘、双时态、历史和差异；
- 索引更新、订阅事件和变更通知；
- 冲突、完整性、保留和纠错传播事件。

### 12.3 权威状态

- 所有持久核心对象的权威记录；
- 对象版本、作用域、血缘和双时态；
- 索引、事件日志、归档和删除状态；
- 公共底座与租户覆盖关系。

### 12.4 依赖

- 业务面提供对象形成语义；
- 平台控制面提供租户和生命周期策略；
- 基础设施提供存储、复制、备份和恢复；
- 智能治理面提供争议裁定和高影响更正决定。

### 12.5 拒绝或退回

- 对象类型、Schema 或版本不受支持；
- 作用域、租户或血缘缺失；
- 调用方试图越过对象所有者直接改写语义；
- 写入违反版本、双时态或不可变规则；
- 删除请求与保留、审计或传播要求冲突；
- 查询无法证明访问作用域。

### 12.6 失败反馈

Schema 问题退对象形成面；作用域问题交平台控制面；争议和更正冲突交智能治理面；一致性或基础设施失败通知调用方并进入恢复、降级或只读策略。

## 十三、平台控制面契约

### 13.1 接受输入

- 平台运营者和租户管理员的配置 Intent 与 Decision；
- 智能治理面的批准、限制和能力采用决定；
- 运行面的实际状态、容量、成本和失败；
- 能力演进面的已批准变更候选；
- 身份提供者、模型、Tool 和连接器的能力元数据。

### 13.2 产生输出

- Court Profile；
- Tenant、Identity、Policy 和 Budget 配置；
- Agent Template、Workflow、Tool、Skill 和 Model Catalog；
- 来源、连接器和凭证引用；
- 版本化期望状态；
- 发布、灰度、回滚和生效事件。

### 13.3 权威状态

- 租户与成员配置；
- 平台和租户策略；
- 能力目录及其版本；
- 预算、配额和路由策略；
- 配置发布与生效状态。

### 13.4 依赖

- 智能治理面提供采用和高影响变更决定；
- 能力演进面提供已验证候选；
- 运行面回报实际状态；
- 数据底座面保存版本和审计；
- 外部供应商提供能力元数据。

### 13.5 拒绝或退回

- 配置缺少所有者、作用域或批准；
- 版本依赖不兼容；
- 策略相互冲突；
- 预算、模型或 Tool 不可用；
- 变更无法回滚或缺少评测依据；
- 请求试图直接改写运行实例状态。

### 13.6 失败反馈

采用问题退智能治理面；能力质量问题退能力演进面；实际状态偏差交运行面协调；发布失败进入停止、回滚或保留旧版本状态。

## 十四、能力演进面契约

### 14.1 接受输入

- 全系统质量、成本、延迟、失败和审计事件；
- 用户 Feedback 和人类改进设想；
- Forecast 评分和风险复盘；
- 模型、Tool、来源和外部技术变化；
- 架构与组织能力缺口；
- 平台控制面的当前版本和约束。

### 14.2 产生输出

- Evolution Evidence；
- Capability Gap；
- Capability Change Candidate；
- Experiment、Evaluation 和 Regression Result；
- 推荐采用、拒绝、灰度或回滚的候选包；
- 对智能治理面的变更审议请求。

### 14.3 权威状态

- 能力观察和缺口记录；
- 实验、评测、基线和对抗结果；
- 变更候选及其版本；
- 发布后观察和回滚证据。

生产期望状态仍由平台控制面拥有。

### 14.4 依赖

- 所有一级面提供运行和质量证据；
- 数据底座面保存实验血缘；
- 智能治理面审核变更；
- 平台控制面发布批准版本；
- 运行面提供沙箱和实验执行。

### 14.5 拒绝或退回

- 候选没有明确能力缺口或评测目标；
- 实验不可隔离或无法复现；
- 质量提升以不可接受的成本、风险或退化为代价；
- 评测集被污染或与生产目标失配；
- 候选要求绕过治理直接修改生产；
- 缺少回滚和重新评估条件。

### 14.6 失败反馈

实验失败保留证据而不发布；评测不充分退候选生成；治理拒绝后归档原因；发布后退化触发平台回滚并形成新的 Evolution Evidence。

## 十五、关键跨面契约

| 契约 | 发送方 | 接收方 | 核心载荷 |
|---|---|---|---|
| Intent Submission | 人机交互 | 智能治理 | Intent、主体、目标、上下文 |
| Mission Approval | 智能治理 | 运行与相关业务面 | Mission、Plan 版本、验收条件 |
| Execution Request | 业务面或治理面 | 智能运行 | Task、能力要求、预算、停止条件 |
| Evidence Package | 数据认知 | 智能治理或研判 | Claim、Evidence、验证状态 |
| Intelligence Assessment | 情报研判 | 智能治理 | Assessment、Forecast、Risk、反证 |
| Publication Request | 智能治理 | 情报产品 | 已批准对象、受众、限制 |
| Product Delivery | 情报产品 | 人机交互 | Product / Alert、渠道和确认要求 |
| Desired State Release | 平台控制 | 智能运行 | 版本化模板、策略、目录和预算 |
| Actual State Report | 智能运行 | 平台控制 | 实际版本、容量、成本和偏差 |
| Evolution Proposal | 能力演进 | 智能治理 | 候选、实验、评测、风险和回滚 |

## 十六、跨面不变量

- 每个跨面请求必须有明确发送方、接收方和契约版本；
- Command 不等于授权，授权语义必须显式可解析；
- Event 不得伪装成 Command；
- 任何面都不能直接写入另一个面的权威语义状态；
- 可以共享对象引用，不能通过共享数据库绕过所有权；
- 自然语言可以是 payload，但不能是唯一契约结构；
- Contract Envelope 必须传播租户、主体、任务、权限、预算、风险和追踪语义；
- 接收方可以拒绝不属于自身职责或不满足前置条件的请求；
- Degraded Result 必须声明缺失能力、质量影响和允许用途；
- 失败不能丢失已发生副作用、重试状态和责任主体；
- 同步或异步传输不改变契约语义；
- 跨面重试必须具有幂等或显式补偿语义。

## 十七、尚未展开

- 每个契约的完整字段 Schema；
- 奏折、旨意、封驳等叙事协议映射；
- 角色与授权规则；
- 超时、重试和补偿的具体策略；
- 契约兼容性与版本迁移协议；
- 跨租户联合调查契约；
- 外部 Action 和补偿契约；
- 服务级目标和容量数字。
