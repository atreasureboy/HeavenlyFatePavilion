# 演进与适应域能力树

状态：Accepted

## 一、能力演进面

核心问题：天机阁如何发现自身不再适配，并安全地改变能力。

```text
能力演进面
├── 1. 运行效果、质量、成本与失败观察能力      [T]
├── 2. 模型、Agent 与外部时代变化观察能力      [M]
├── 3. 能力缺口、退化、机会与影响识别能力      [A]
├── 4. 改进假设与候选方案生成能力              [A]
├── 5. 沙箱、仿真、数据集与实验设计能力        [M]
├── 6. 离线评测、在线评测与回归能力            [T]
├── 7. 对抗、红队、偏差与失败模式验证能力      [M]
├── 8. 候选比较、权衡与治理提交能力            [A]
├── 9. 灰度、实验发布与回滚验证能力            [T]
├── 10. 发布后监测、归因与保留判断能力         [M]
├── 11. 人类主导演进与架构迭代能力             [A]
└── 12. 自主演进编排与自治等级管理能力         [M]
```


## 三、演进闭环

```text
观察
→ 形成 Evolution Evidence
→ 识别 Capability Gap
→ 生成 Change Candidate
→ 沙箱与实验
→ 评测、对抗和回归
→ 智能治理面审议
→ 平台控制面发布
→ 运行面灰度执行
→ 发布后观察
→ 保留 / 修改 / 回滚
```

## 四、能力边界

- 观察不等于自动修改；
- 候选不等于批准版本；
- 评测提高不等于整体能力提高；
- 自主演进不等于无限自治；
- 人类主导演进和系统自主演进共享证据、实验、版本与回滚框架；
- 任何不能自主演进的部分仍必须能够由人类演进。

能力树说明演进面“能做什么”；它如何作用于十面、横切治理、基础设施和整体架构，以及变更半径与采用权如何分离，见[能力演进作用全域骨架](../evolution-across-entire-architecture.md)。
