# 天机阁十面能力树

状态：Accepted

## 一、用途

本目录将十个一级逻辑面展开为类型一致的二级能力树，为后续官署映射、组件设计、场景验证和演进评估提供稳定挂载点。

## 二、分类规则

每个二级节点必须表达“系统能够做什么”，而不是：

- 一个组织名称；
- 一个数据对象；
- 一个具体服务或数据库；
- 一段固定时序；
- 一个质量指标；
- 一项横切约束。

例如：

```text
正确：实体身份解析能力
不是：Entity 表
不是：吏部
不是：Neo4j
不是：先查数据库再调用模型
```

组织、对象、组件和流程可以映射到能力节点，但不能替代能力分类。

## 三、默认实现形态

| 标记 | 含义 |
|---|---|
| `A` | Agent-led：以复杂理解、判断、反证或综合 Agent 为核心 |
| `M` | Mixed：Agent 与确定性 Tool、规则、模型共同完成 |
| `T` | Tool-led：以确定性服务、脚本、规则、Worker 或存储为核心 |

标记表示默认倾向，不是永久技术限制。能力演进可以改变实现形态，但不得改变能力契约。

## 五、共同约束

- 二级能力只能有一个主要所有面；
- 其他面可以调用或扩展能力，不能复制所有权；
- 六部属于领域能力面，但可以向认知、研判和产品能力注入领域扩展；
- 数据底座提供状态能力，不承担认知和研判语义；
- 平台控制面定义长期期望状态，运行面负责即时执行；
- 横切维度作用于能力，不作为二级能力重复列入所有树；
- 新能力优先挂入现有节点；无法归属时才重新评估树结构。
