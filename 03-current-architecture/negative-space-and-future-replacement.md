# 负空间、反架构与未来替换骨架

状态：Accepted

记录日期：2026-07-24

## 一、这张骨架回答什么

成熟架构不仅说明“有什么”，还必须说明：

- 每个一级面明确不能拥有什么；
- 哪些职责、状态和权力不能合并；
- 哪些看似方便的组合会把天机阁变成反架构；
- 哪些结构只是当前模型能力下的实现形态；
- 未来超级模型出现后，哪些节点可以减少，哪些语义仍必须分开；
- 哪些外部能力和内部智能不能被默认信任。

本骨架定义禁止边界与替换边界，不设计迁移步骤、模型方案或具体技术替代。

## 二、负空间的四种类型

```text
职责负空间
→ 某个面明确不负责什么

权力负空间
→ 某个主体无论多聪明都不能自行取得什么权力

语义负空间
→ 哪些对象、状态和全局流不能互相冒充

信任负空间
→ 哪些输入、供应方、模型和外部结果不能默认视为可信
```

负空间不是“暂时没设计”，而是为了防止权力集中、语义污染和时代性实现反向吞并架构而主动留下的边界。

## 三、十个一级面的负职责

| 一级面 | 明确不属于它的责任 |
|---|---|
| 人机交互面 | 不拥有租户主权，不确认事实，不以对话历史代替长期知识 |
| 情报产品面 | 不创造证据，不静默改变事实或研判，不承担外部行动最终状态 |
| 数据认知面 | 不因完成清洗和关联就拥有业务决定权，不把相关性自动提升为因果 |
| 情报研判面 | 不把预测当事实，不自行授权行动，不隐藏不确定性 |
| 智能治理面 | 不亲自执行全部任务，不通过组织权力改写事实，不成为无限权限中心 |
| 领域能力面 | 不复制共享对象主干、平台政策和运行内核，不因专业性取得跨域主权 |
| 智能执行与运行面 | 不创造目标、授权和事实，不因能够调用 Tool 就拥有调用权 |
| 数据底座面 | 不决定业务意义、合法性和行动，不把存储状态当作认识论真理 |
| 平台控制面 | 不拥有租户业务目标和数据使用权，不直接冒充运行实例或领域判断 |
| 能力演进面 | 不批准自身变更，不静默改写历史，不绕过验证、治理和回滚 |

这些负职责不阻止协作，但任何跨面协作都必须通过契约、权威和证据关系发生。

## 四、必须保持可区分的结构

以下结构可以由同一个模型、进程或产品界面承载，但逻辑语义、权威记录和审计身份必须保持可区分：

```text
人类目标        ≠ Agent 解释
规划权          ≠ 执行权          ≠ 审核与接受权
控制流          ≠ 授权流          ≠ 数据流
数据处理        ≠ 事实接受        ≠ 情报研判
事实            ≠ 推断            ≠ 建议            ≠ 决定
建议            ≠ 外部命令        ≠ 现实效果
公共基线        ≠ 租户覆盖        ≠ 联合空间
逻辑朝廷        ≠ 物理部署
期望状态        ≠ 即时运行状态
Agent 上下文    ≠ 长期知识        ≠ 审计记录
服务恢复        ≠ 数据恢复        ≠ 影响纠正
能力候选        ≠ 已批准版本      ≠ 生产生效版本
```

“可区分”不等于永远使用不同模型或服务；它表示系统仍能分别授权、拒绝、记录、替换、停止和追责。

## 五、禁止的权力组合

### 5.1 自证闭环

同一主体提出结论、选择证据、审核自己、批准发布并删除失败记录。

结果：系统无法形成反证、纠正和责任。

### 5.2 智能即权力

模型因为能力强、置信度高或拥有全局上下文而自行扩大权限。

结果：认知能力被错误转换为政治、组织、数据或行动主权。

### 5.3 执行即授权

能够调用数据、Tool 或外部系统，就被认为有权调用。

结果：运行能力绕过平台政策、租户委托和外部责任。

### 5.4 存储即真理

某个数据库中的当前值被视为不可争议事实，历史、来源、冲突和作用域被覆盖。

结果：数据便利吞并认识论。

### 5.5 平台即租户

平台运营、共享基础设施或公共索引被用来推导租户数据和目标的使用权。

结果：共同承载变成越权集中。

### 5.6 演进即自我授权

能力演进面发现缺口后直接修改生产模型、策略、组织或知识结构。

结果：自我迭代成为绕过治理的后门。

## 六、典型反架构

| 反架构 | 表面吸引力 | 实际破坏 |
|---|---|---|
| 万能皇帝超级 Agent | 路径短、体验统一 | 目标、规划、执行、审核、事实和权限集中 |
| 三省机械串行 Prompt | 容易画流程 | 把权力制度退化为固定模型调用链 |
| 所有官署都 Agent 化 | 叙事对称 | 高成本、低确定性、不可强制 |
| 所有智能都 Tool 化 | 易测试、易控制 | 无法处理开放式规划、反证和跨域判断 |
| 聊天记录即系统状态 | 开发简单 | 长期目标、权限、知识和恢复不可依赖 |
| 单库共享即跨面协作 | 查询方便 | 绕过所有权、契约、作用域和审计 |
| 向量检索结果即事实库 | 技术统一 | 相似性替代证据、身份、版本和争议 |
| 模型自信即事实等级 | 输出直接 | 置信表达替代验证制度 |
| 一个安全 Agent 负责安全 | 看似智能 | 硬边界依赖 Agent 自觉，形成单点 |
| 默认信任供应商输出 | 集成快速 | 外部模型、Tool、来源和服务污染全链 |
| 自我演进直接上线 | 迭代迅速 | 能力批准自身，无法回滚和追责 |
| 为高可用取消治理 | 服务不中断 | 系统在失去合法性和可信性后继续扩散 |
| 多 Agent 数量冒充独立判断 | 看似充分讨论 | 共享模型、检索、来源或评价标准形成伪多样性 |

反架构不是指某项技术永远不能使用，而是指它被错误地赋予了超过自身语义的架构地位。

受治理闭环与自证回路必须区分：前者允许反馈改变后续状态，但保留外部权威、拒绝、分歧、审计和停止；后者让结果成为自身唯一的证据、授权或评价。

## 七、默认不可信边界

以下主体或产物都不能凭身份直接进入权威链：

- 网页、文档、API、消息和用户提交内容；
- 外部模型、Tool、Skill、插件、开源组件和供应商服务；
- 其他租户、联合空间成员、同行系统和联邦节点；
- Agent 的计划、记忆、工具选择、总结、置信度和自然语言解释；
- 缓存、索引、统计、知识图谱和历史产品；
- 平台运营者、领域专家和人工复核者的主张；
- 外部系统返回的成功状态；
- 能力演进产生的新版本和评测结果。

“不默认信任”不等于全部拒绝，而是要求按对象类型经过身份、来源、作用域、权限、证据、版本、质量和审计转换后，才能获得有限地位。

人类也不是事实无误的来源；人类拥有相应主权和责任，不代表其每项事实主张免于证据与纠正。

## 八、时代性结构与稳定结构

### 8.1 可随模型时代替换或收缩

- Agent 实例数量和常驻方式；
- 三省是否分别实例化为三个模型调用；
- 六部尚书是否需要独立 Agent；
- 皇帝的交互形态、人格投影和上下文组织方式；
- 固定工作流、动态编排和自主规划的比例；
- Tool、专用模型、通用模型和人工之间的任务分配；
- 模型、向量检索、图处理、规则引擎和搜索实现；
- 服务边界、运行框架、数据产品和部署拓扑；
- 区域承载、联邦连接和供应商组合。

### 8.2 不随模型智商自动消失

- 人类目标、授权、停止和最终责任来源；
- 规划、执行、审核三类权力的可区分性；
- 租户、辖域、数据、事实、产品和行动主权边界；
- Document、Snapshot、Evidence、Claim、Proposition、作用域化 Fact Aggregate、Assessment、Forecast、Recommendation、Decision 与 Effect 的语义层次；
- 权威对象所有权、契约、版本、血缘和审计；
- 期望状态与实际运行状态的分离；
- 长期知识对临时 Agent 上下文的独立性；
- 外部输入、供应链和同行系统的信任边界；
- 变更经过观察、评测、批准、发布、回滚和纠正的演进纪律。

稳定的是问题、语义和制衡，不是当前组织实例和技术数量。

## 九、未来超级模型下的裁定

未来单一模型可能具备当前多个 Agent 的综合能力，并在一次上下文中完成规划、调查、反证和表达。天机阁允许减少实例和调用，但必须满足：

```text
同一模型承载多个角色
≠ 多种权力变成一种权力

一次推理完成多个阶段
≠ 中间语义和决定记录可以消失

模型拥有全局知识
≠ 模型拥有全局数据与行动权限

模型能够自我改进
≠ 模型能够批准自身进入生产
```

三省未来可以从“三个子 Agent”演变为一个或多个模型内部的独立治理角色、不同决策上下文或外部确定性控制，但规划、执行、封驳仍要能够独立授权、形成反证、拒绝、审计和由人类介入。

如果一种未来实现无法证明这些权力仍可区分，它不是架构简化，而是制衡消失。

## 十、替换判断框架

任何节点准备合并、删除或由超级模型接管时，只在骨架层询问六个问题：

1. 它代表的是稳定能力，还是当前时代的实现载体？
2. 它拥有的权威状态将由谁接管？
3. 合并后原有拒绝、反证和封驳是否仍能独立发生？
4. 作用域、证据、版本、审计和责任是否仍可追踪？
5. 能否单独暂停、撤销、降级、替换和回滚？
6. 失败时是否会把原本隔离的失效域合并成全局失效？

只要其中任何一项没有可靠答案，就不能仅以模型更强或成本更低为理由合并。

## 十一、对现有骨架的裁定

S7 没有发现必须新增的一级逻辑面。

它确认当前架构需要同时维护两张互补地图：

```text
正空间地图
→ 十面、能力、对象、流、运行形态和生存结构

负空间地图
→ 非职责、禁止组合、信任边界和不可替换语义
```

十面仍是职责骨架；三省六部是可演进的组织治理映射；Agent、Tool、服务和基础设施是可替换实现；主权、语义、契约、证据和制衡是不随实现替换而消失的稳定中心。

## 十二、本阶段有意不展开

- 超级模型的具体能力假设与产品路线；
- 单模型多角色的隔离和反证实现；
- 组件、服务、数据库与供应商迁移方案；
- 未来组织合并的逐项 RACI；
- 零信任、安全供应链和联邦协议；
- 反架构的量化风险模型与检测规则；
- 详细替换顺序、兼容期和数据迁移。
