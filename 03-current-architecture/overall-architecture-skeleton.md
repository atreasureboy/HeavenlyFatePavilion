# 天机阁整体架构骨架

状态：Accepted

版本：Skeleton v0.1

生效日期：2026-07-24

## 一、骨架目的

本文是天机阁从整体到局部展开的总骨架。它固定：

- 总图分组；
- 十个一级逻辑面；
- 第一批二级能力域；
- 三条核心闭环；
- 一级面之间的控制、数据与反馈关系；
- 横切维度的表达方式；
- 后续局部架构的挂载位置。

本骨架不是部署图、服务清单或实现计划。二级能力域是后续深化的稳定挂载点，不意味着已经确定具体组件数量、技术选型或 Agent 数量。

当前成熟度是“一级骨架已建立，整体骨架正在闭合”，不能解释为所有接口、对象、状态和横切关系已经完善。完整性缺口见[整体架构骨架完整性审计](../07-analysis-and-validation/skeleton-completeness-assessment.md)。

本文中的二级树用于总体阅读；当前权威、类型一致的完整能力分类见[十面二级能力树](./capability-trees/README.md)。

## 二、五域、十面、一底座、七横切

```text
天机阁
│
├── 体验与交付域
│   ├── 人机交互面
│   └── 情报产品面
│
├── 情报生产域
│   ├── 数据认知面
│   ├── 情报研判面
│   └── 领域能力面
│
├── 治理与执行域
│   ├── 智能治理面
│   └── 智能执行与运行面
│
├── 平台与知识域
│   ├── 数据底座面
│   └── 平台控制面
│
└── 演进与适应域
    └── 能力演进面

共同承载底座：基础设施

七个横切维度：
多租户、身份与权限、证据与血缘、预算与资源、
风险与质量、审计与追踪、数据生命周期
```

“域”只用于总图分组和讲解，不拥有运行状态，也不新增架构责任。一级面才是逻辑职责和后续设计所有权的基本单位。

## 三、体验与交付域

### 3.1 人机交互面

核心问题：仙人如何与天机阁建立持续、统一、可理解的关系。

二级能力域：

```text
人机交互面
├── 皇帝交互投影
├── 对话与会话
├── 多模态交互
├── 意图与偏好表达
├── 主动通知与打断
├── 反馈、纠正与追问
├── 人类决策与介入入口
└── 渠道与接入适配
```

边界：

- 皇帝交互投影不等于皇帝治理本体；
- 本面不生产权威事实，不自行完成领域研判；
- API 和消息渠道属于交互适配，具体任务执行属于运行面。

默认形态：皇帝主 Agent + 确定性交互服务。

### 3.2 情报产品面

核心问题：天机阁以什么稳定形式交付已经形成的情报。

二级能力域：

```text
情报产品面
├── 人物、机构与项目档案
├── 图谱与关系视图
├── 事件与变化时间线
├── 查询回答与调查卷宗
├── 日报、周报与专题报告
├── 态势与趋势产品
├── 情景推演产品
├── 风险告警与跟踪
└── 产品版本、订阅与分发
```

边界：

- 产品组织和呈现不改变事实或研判等级；
- 翰林院式写作能力可以润色，但不能扩大已经审核的结论；
- 产品必须保留证据、时间、置信度和生成版本。

默认形态：模板和确定性生成优先，复杂叙事使用受约束 Agent。

## 四、情报生产域

### 4.1 数据认知面

核心问题：天机阁如何从异构资料形成可理解的世界状态。

二级能力域：

```text
数据认知面
├── 掌数
│   ├── 来源发现与准入
│   ├── 获取、解析与标准化
│   ├── Claim 与证据形成
│   └── 数据质量与可用性
├── 联结
│   ├── 实体解析与消歧
│   ├── 身份、关系与事件关联
│   ├── 跨源、跨域与跨时关联
│   └── 关联置信度与证据
└── 察变
    ├── 文档、事实与语义 Diff
    ├── 实体、关系与事件变化
    ├── 变化聚合与传播
    └── 异常度、重要性与变化关联
```

边界：

- 本面拥有“形成认识”的处理语义，不拥有权威状态的持久化实现；
- 相似性只产生关联候选，不能直接等同于身份或事实；
- 变化检测结果仍需证据、时间和版本语义。

默认形态：高吞吐部分以 Tool、规则和专用模型为主，歧义解析与复杂关联按需使用 Agent。

### 4.2 情报研判面

核心问题：天机阁如何从事实、关系和变化理解局势、未来与风险。

二级能力域：

```text
情报研判面
├── 推势
│   ├── 态势综合
│   ├── 影响链与结构变化
│   ├── 跨域解释
│   └── 支持证据、反证与不确定性
├── 卜算
│   ├── 趋势预测
│   ├── 情景树与关键变量
│   ├── 反事实与失效条件
│   └── 概率、区间与持续校准
└── 警险
    ├── 风险识别与分级
    ├── 触发、合并与升级
    ├── 影响范围与应对建议
    └── 持续跟踪、解除与复盘
```

边界：

- Assessment、Forecast 和 Risk 不得伪装成 Fact；
- 研判必须能够反向提出补充掌数、重新联结和验证变化的任务；
- 建议不自动产生外部行动。

默认形态：领域 Agent 综合判断，确定性统计、预测工具和规则引擎提供支撑，门下省式审核独立存在。

### 4.3 领域能力面

核心问题：共享情报主干需要哪些专业语义、规则和判断能力。

二级能力域：

```text
领域能力面
├── 吏部：人物、组织、身份与履历
├── 户部：商业、资源、市场、机会与成本
├── 礼部：观点、传播、舆情与叙事
├── 兵部：时政、地缘、安全与影响
├── 刑部：法规、合规、风险与事实争议
├── 工部：技术、产品、工程与采集能力
├── 跨部联合研判
└── 领域扩展与专业官署
```

每个部可以拥有：

- 领域本体和术语；
- 领域数据源和准入规则；
- 部级 Agent；
- Tool、Skill、规则与专用模型；
- 领域质量标准；
- 领域数据产品。

六部是覆盖共享情报主干的专业能力，不分别复制数据底座、运行时、平台控制或整套“掌数—警险”流水线。

## 五、治理与执行域

### 5.1 智能治理面

核心问题：复杂智能任务如何获得规划、统筹、审核、裁定与责任归属。

二级能力域：

```text
智能治理面
├── 皇帝智能中枢本体
├── 中书省：目标理解、规划与任务起草
├── 尚书省：执行统筹与跨部编排
├── 门下省：审核、反证、封驳与降级
├── 治理议程与任务契约
├── 冲突裁定与升级
├── 人类介入与最终决定
└── 监察、问责与治理记录
```

边界：

- 三省是相互约束的治理权力，不是固定的三个流水线步骤；
- 尚书省决定如何编排，不亲自取代运行时调度器；
- 门下省进行语义和风险审核，不取代确定性校验服务；
- 皇帝协调全局，但不成为绕过三省和平台规则的超级权限主体。

默认形态：皇帝与三省使用高级 Agent；规则、任务契约、审计和状态流转尽量确定性化。

### 5.2 智能执行与运行面

核心问题：治理决定如何变成可隔离、可观测、可恢复的具体执行。

二级能力域：

```text
智能执行与运行面
├── Run、Task 与执行图
├── Agent 实例与生命周期
├── Tool、Skill 与模型调用
├── Context、Memory 与 Workspace
├── 调度、队列与 Worker
├── 并发、幂等、重试与补偿
├── 超时、取消、循环与死锁控制
├── 故障隔离、恢复与降级
└── 执行事件、状态回报与人类接管
```

边界：

- 本面拥有即时执行状态，不拥有模板、策略和长期配置的权威定义；
- Agent 实例不是 Agent 模板；
- 运行时执行治理决定，但不能自行扩大任务目标和权限。

默认形态：确定性运行内核 + 按需 Agent；不以 Agent 模拟队列、状态机、重试器和资源计量器。

## 六、平台与知识域

### 6.1 数据底座面

核心问题：资料、事实、关系、变化和研判如何可靠、可追溯地存在并被供应。

二级能力域：

```text
数据底座面
├── 文渊阁：原始资料与快照
├── 国史馆：事实、主张与证据
├── 实体、关系与知识图谱
├── 事件、时间线与变化历史
├── 研判、预测、风险与产品记录
├── 索引、检索与数据供应
├── 版本、双时态与血缘
├── 分区、复制、一致性与缓存
└── 保留、归档、删除与纠错传播
```

边界：

- 数据底座持有状态，不决定事实如何被认知或趋势如何被研判；
- Agent Memory 不是情报事实库；
- 原始资料、Evidence、Claim、Fact、Inference 和 Product 必须分层。

默认形态：数据库、对象存储、搜索、图、向量、时序和事件系统；不以 Agent 充当数据库。

### 6.2 平台控制面

核心问题：多租户天机阁长期应该以什么配置、策略和能力组合运行。

二级能力域：

```text
平台控制面
├── 租户、成员与 Court Profile
├── 身份、角色与策略定义
├── Agent、Tool 与 Skill 目录
├── 模型目录、路由与供应商策略
├── 工作流模板与任务类型
├── 预算、配额与资源政策
├── 来源、连接器与凭证配置
├── 功能版本、发布与生效状态
└── 平台级配置、策略与生命周期
```

边界：

- 控制面拥有长期期望状态，运行面拥有即时执行状态；
- 控制面下发版本化配置，运行面回报实际状态；
- 多租户控制是本面的子域，租户上下文则贯穿所有一级面。

默认形态：确定性控制服务和策略引擎为主，Agent 可辅助生成候选配置但不直接成为权威控制存储。

## 七、演进与适应域

该域只有一个能力演进面，但其作用范围覆盖其他九面和基础设施，而不是只在本域内部生效。

### 7.1 能力演进面

核心问题：天机阁如何在 Agent、模型、数据与组织范式变化时持续保持适配。

二级能力域：

```text
能力演进面
├── 能力与时代变化观察
├── 缺口、退化与机会发现
├── 改进候选生成
├── 沙箱、仿真与实验
├── 评测、对抗与回归
├── 版本、灰度、发布与回滚
├── 自主演进
├── 人类主导演进
└── 模型、Agent、工具、数据、组织与架构全域演进
```

边界：

- 能力演进改变系统能力，普通运维维持既定能力；
- 自主演进不是无限自我修改；
- 不能自主改变的部分仍必须允许人类持续演进。

默认形态：评测与版本系统确定性优先，Agent 用于发现、设计和分析候选，正式采用仍进入治理与控制路径。

## 八、共同承载底座

基础设施不属于十个一级逻辑面，但必须为它们提供共同承载：

```text
基础设施
├── 计算与加速资源
├── 网络、网关与服务发现
├── 存储与备份介质
├── 消息、队列与流处理设施
├── 容器、沙箱与隔离
├── 部署、配置分发与密钥设施
├── 可观测性基础设施
├── 单区、多区、多区域与边缘节点
└── 容灾、容量与业务连续性
```

逻辑架构只声明依赖和质量要求；具体拓扑在部署与基础设施视图中展开。

## 九、三条核心闭环

### 9.1 需求与治理闭环

```text
仙人
→ 皇帝交互投影
→ 皇帝治理本体
→ 中书省规划
→ 门下省审议
→ 尚书省统筹
→ 运行面执行
→ 门下省复核
→ 情报产品
→ 皇帝解释
→ 仙人反馈
```

这是一条逻辑治理路径，不要求每个低风险任务机械经过所有 Agent。

### 9.2 情报生产闭环

```text
目标
→ 掌数
→ 联结
→ 察变
→ 推势
→ 卜算
→ 警险
→ 情报产品
→ 反馈与新目标
```

任何阶段都可以反向触发补充收集、重新关联、反证和修正。六部以领域能力覆盖整个主干。

### 9.3 控制、运行与演进闭环

```text
平台控制面下发期望状态
→ 智能执行与运行面实例化并执行
→ 运行状态、质量、成本和失败证据回报
→ 能力演进面发现缺口并验证候选
→ 智能治理面审核变化
→ 平台控制面发布新版本
```

## 十、横切维度矩阵

| 横切维度 | 集中所有者 | 全局传播要求 |
|---|---|---|
| 多租户 | 平台控制面 | 请求、任务、数据、索引、缓存、模型调用、产品和审计 |
| 身份与权限 | 平台控制面与后续安全专题 | 人类、Agent、服务、Tool、数据和动作 |
| 证据与血缘 | 数据底座面 | 认知、研判、产品、审核和演进评测 |
| 预算与资源 | 平台控制面 | 治理计划、执行图、模型调用、领域任务和租户账簿 |
| 风险与质量 | 智能治理面及质量体系 | 来源、事实、推断、预测、产品、模型和版本 |
| 审计与追踪 | 数据底座与平台治理能力 | 用户意图、治理决定、执行事件、数据变化和发布 |
| 数据生命周期 | 数据底座面 | 来源准入、加工、供应、产品、保留、删除和纠错 |

横切维度可以有集中管理者，但不能被理解为只在一个一级面中生效。

## 十一、视图规则

- 职责树：表达“谁拥有哪类责任”；
- 关系图：表达一级面之间的依赖、反馈和多对多协作；
- 时序图：表达一个场景中的先后、并发、退回和升级；
- 状态机：表达 Run、事实、研判、告警和版本的生命周期；
- 横切矩阵：表达租户、安全、证据、预算、质量和审计如何贯穿；
- 部署图：表达基础设施、节点、区域、网络和数据副本。

不得用一张树同时冒充组织图、数据流图、控制流图和部署图。

## 十二、下一层展开顺序

整体骨架建立后，按以下顺序增加设计分辨率：

1. 系统上下文与仙人—皇帝—租户模型（已建立，见[系统上下文与边界](./system-context.md)）；
2. 情报领域语言和数据状态分层（第一版核心对象主干已建立，见[核心对象主干](../04-domain-design/core-object-spine.md)）；
3. 数据认知与情报研判主干；
4. 三省治理协议与六部领域能力模板；
5. 控制面与运行面状态模型；
6. 数据底座的逻辑数据架构；
7. 横切维度与架构不变量；
8. 能力演进闭环；
9. 端到端场景验证；
10. 部署、容量、可靠性与成本视图。

后续发现的新能力原则上先挂入现有十面和二级能力域。只有出现无法归属且职责稳定的新问题时，才重新评估一级骨架。

十个一级面的第一版输入、输出、权威状态、拒绝条件和失败路由见[十面输入输出契约](./plane-contracts.md)。

皇帝、三省、六部和公共官署到十面能力及技术形态的正式映射见[组织—技术映射](./organization-mapping/README.md)。

任务、知识、研判、风险、产品与能力版本的生命周期，以及统一异常分类和路由，见[核心状态机与异常路由](../08-reference-models/state-machines/README.md)；面向阅读的总图见[状态机与异常路径总图](./text-diagrams/TXT-0010-state-machines-and-exceptions.md)。
