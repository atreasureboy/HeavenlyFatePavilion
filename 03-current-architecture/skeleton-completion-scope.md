# 整体架构骨架完善范围与阶段边界

状态：Accepted

生效日期：2026-07-29

## 一、阶段裁定

天机阁当前仍处于“整体架构骨架完善阶段”。

此前完成并封板的是外层一级骨架：

```text
外部边界
+ 十层定位
+ 五域十面
+ 组织权力
+ 全局流
+ 横切约束
+ 生存与演进位置
```

它证明所有宏观问题已有归属，不等于每个一级面的内部骨架、关键系统骨架和跨面连接都已达到可阅读、可推演的完整程度。

因此采用：

```text
外层骨架完成
≠ 整体骨架完善阶段完成
≠ 专题详细设计完成
```

## 二、为什么仍属于骨架

天机阁不是先实现最小系统再扩张，而是先从顶点向下建立完整结构树。只要当前工作仍在回答以下问题，就属于骨架完善：

- 一个一级面内部由哪些稳定二级系统构成；
- 每个系统拥有何种职责、权力和非职责；
- 系统之间通过哪些类型的流与契约连接；
- 关键对象、状态和异常位于哪里；
- 正常、失败、取消、恢复和演进路径是否闭合；
- 安全、预算、证据、审计和多租户约束落在哪些结构节点；
- 未来提高分辨率时从哪个稳定位置继续展开。

这类设计即使涉及 Runtime、IPC、数据版本或调度，仍然可能只是系统级骨架，而不是实现细节。

## 三、骨架的四级分辨率

```text
G0 外层定位骨架【已完成】
边界、主体、十层、十面、主权、全局流、横切约束
        │
        ▼
G1 一级面内部系统骨架【进行中】
每个面的二级系统、职责、权威、输入输出和非职责
        │
        ▼
G2 关键机制骨架【待逐项闭合】
对象族、协议族、状态族、调度、隔离、资源、故障和恢复主干
        │
        ▼
G3 全局连接与压力闭合【待完成】
跨面正常链、异常链、权力链、资源链和演进链共同验证
        │
        ▼
专题详细设计
字段、算法、选型、参数、部署、内部流程与实现方案
```

G0 的封板用于防止无限增加一级面；G1—G3 仍然是从整体到局部搭骨架，而不是把某个局部写到实现级。

## 四、本阶段必须补齐的系统骨架

| 一级面 | 本阶段至少需要形成的骨架 |
|---|---|
| 人机交互 | 皇帝会话、身份/租户入口、授权确认、解释与接管 |
| 情报产品 | 产品编排、版本、发布、分发、纠正与反馈 |
| 数据认知 | 采集、解析、实体关联、Diff、Change、知识供应 |
| 情报研判 | Signal、Assessment、Scenario、Forecast、Risk、Recommendation |
| 智能治理 | 中书规划、尚书调度、门下审核、争议与升级 |
| 领域能力 | 六部能力边界、领域知识、共享能力与跨部协作 |
| 智能执行与运行 | Runtime Kernel、Agent/Tool 执行、容器、IPC、调度、故障恢复 |
| 数据底座 | 原始资料、事实/知识、索引、血缘、版本、历史与租户覆盖 |
| 平台控制 | 身份、策略、租户、模型/Tool 注册、配置、预算与期望状态 |
| 能力演进 | 观察、实验、评测、采用、发布、回滚与影响半径 |

每个面不要求立即拥有完整字段和算法，但必须有一张可展开的内部结构树。

## 五、当前允许与禁止的设计深度

### 允许

- 确定稳定系统、子系统和能力组；
- 区分职责、权力、对象所有权和协作边；
- 建立对象类别、协议类别和状态主干；
- 建立正常、异常、取消、退化和恢复骨架；
- 从 Windows、三省六部等成熟体系提炼可迁移的结构原则；
- 用文字架构图帮助形成完整心智模型。

### 暂不进入

- 完整消息字段、数据库 Schema 和 API 定义；
- 具体算法、阈值、评分公式和 Prompt；
- 数据库、队列、框架、云服务和模型供应商选型；
- 物理部署节点、容量数字和精确 SLO；
- 单个官署的细粒度岗位与每一步内部操作；
- 为了显得详细而提前固化未来实现。

边界判断不是“是否提到了协议或 Runtime”，而是“当前是在确定稳定结构，还是已经选择具体实现”。

## 六、Windows 学习在本阶段的位置

W1—W10 不是独立的实现专题，而是对“智能执行与运行面”进行骨架扫描：

```text
Windows 机制
→ 提炼结构问题
→ 形成天机阁候选运行骨架
→ 与十面、三省六部和全局流对齐
→ 暂不固化 API、进程模型或技术选型
```

学习结果继续保持 `Seed`。完成 Windows 扫描后，应先汇总为一张运行系统候选骨架，再决定是否进入正式迭代采纳，不能逐篇直接写入当前架构。

## 七、本阶段的完成门槛

只有同时满足以下条件，才可以宣布整体骨架完善阶段完成：

1. 十个一级面均有稳定、可阅读的二级系统骨架；
2. 皇帝、三省六部与技术系统的映射在二级结构上闭合；
3. 数据、知识、控制、授权、资源、审计和演进能贯穿二级系统；
4. Runtime、数据底座、平台控制和能力演进等关键系统具有机制主干；
5. 多租户、权限、证据、预算、质量、审计和生命周期能投影到全部关键系统；
6. 正常、冲突、取消、断连、退化、灾难与恢复路径在系统级连通；
7. 每个未深化问题都有唯一归属、入口和未来展开方向；
8. 连续多轮跨视角扫描不再发现缺失的稳定系统族；
9. 一张整体文字架构图能够从仙人一直展开到关键二级系统；
10. 用户明确确认骨架已经达到预期完整度。

第 10 条不可由 Codex、审计文档或自动检查代替。

## 八、阶段纪律

```text
先扩全系统的同一层
→ 再检查跨系统连接
→ 再向下一层整体展开
→ 不单点钻深
```

如果一次研究开始进入字段、算法或选型，应抽取其中的结构结论后暂停细节。若发现新的一级职责缺口，则按 Skeleton v1.0 的变更纪律重新打开 G0；否则继续在 G1—G3 完善。
