# 阶段 1：北极星、边界与非目标访谈

状态：Draft

访谈日期：2026-07-24

推进状态：Deferred。当前优先完成[整体架构骨架访谈](./phase-01-overall-skeleton-interview.md)，本文件中的授权和安全问题待骨架确定后继续。

## 一、当前明确回答

### 1.1 现实项目不以业务价值为目标

天机阁当前不是准备创建公司、服务个人或满足国家现实需求的产品。

用户不打算实现天机阁。现阶段也不认为任何公司、个人或国家具备彻底实现和完善天机阁的能力。未来随着人工智能大规模发展，它可能具备实现条件，但当前设计不以现实交付、融资、商业化或工程建设为约束。

### 1.2 现实交付物是架构本身

本项目当前唯一计划交付的是：

- 完整的架构设计卷宗；
- 可追溯的架构迭代；
- 架构决策和权衡；
- 场景、威胁、容量和故障推演；
- 面试展示材料；
- 对架构设计能力的证明。

因此需要区分两个层面：

```text
作品层
目标：证明和展示超大型系统架构设计能力
交付：架构本身

虚构系统层
目标：描述未来能力条件下的天机阁如何工作
交付：由后续设计确定的情报、知识、研判或行动能力
```

作品层不要求系统实现；虚构系统层仍需具备自洽的使命、输入、输出、边界和质量标准，否则架构无法推导。

### 1.3 暂不设功能领域上的绝对排除

当前设想不希望预先声明某个业务领域“绝对不属于天机阁”。天机阁的终局能力空间保持开放，可以随着架构分解覆盖更多数据、知识、情报、领域和协作方式。

这不等于系统没有边界，而是：

- 不以行业和主题建立封闭功能边界；
- 不因现阶段技术不可实现而删除终局能力；
- 不把当前模型、算力和组织能力当作终局上限；
- 允许未来迭代扩展新的领域和官署。

### 1.4 唯一明确的绝对红线是越权

当前提出的最高安全原则是：

> 天机阁可以扩展能力，但不能扩张未经授权的权力；任何主体的越权都不可接受。

候选简称：

> 能力开放，权力受限。

或者：

> 能力无预设上限，权力有绝对边界。

这条原则尚未提升为 Accepted，因为“越权”和“授权”的正式语义仍未完成。

## 二、对现有架构的修正

### 2.1 不再用现实产品价值倒推全部架构

传统产品架构通常从用户价值、市场需求和可实现范围出发。天机阁需要改为从以下内容推导：

- 作品层目标；
- 假设的未来能力条件；
- 终局系统使命；
- 架构完整性；
- 权力安全；
- 内部一致性；
- 可解释的设计权衡；
- 面试中的可论证性。

用户原型和需求仍然有用，但它们是验证架构覆盖度的场景，不是项目存在的商业理由。

### 2.2 “没有功能排除”不等于“没有系统边界”

至少存在四类边界：

#### 权限边界

主体能访问什么数据、调用什么工具、执行什么行为。

#### 信任边界

人类、Agent、服务、外部来源、模型供应商和租户之间何处需要验证。

#### 责任边界

谁负责规划、执行、审核、事实确认、授权和最终责任。

#### 系统边界

哪些能力属于天机阁自身运行系统、外部参考项目、外部数据源、模型供应商、租户组织或人类。

因此，“不设置封闭的业务领域边界”可以成立，但系统仍必须具备清晰的权力、信任、责任和所有权边界。

### 2.3 未来能力假设必须显式化

不考虑当前实现，不代表可以隐含无限能力。每项超出现实技术的设计需要标记：

- 所依赖的未来 AI 能力；
- 所依赖的模型可靠性；
- 所依赖的算力和数据条件；
- 当前不可实现的原因；
- 如果能力没有出现，架构如何降级；
- 哪些设计不依赖未来突破。

这样可以避免用“未来技术会解决”掩盖架构缺口。

## 三、“越权”的候选分解

以下只是待访谈分类，不是用户已经接受的定义。

### 3.1 数据越权

- 读取未经授权的数据；
- 跨租户访问；
- 使用超出声明目的的数据；
- 从合法数据推导不允许形成的敏感结果；
- 删除或修改无权处理的数据。

### 3.2 工具和行为越权

- 调用未授权 Tool；
- 使用超出范围的参数；
- 执行未经批准的写操作；
- 将调查能力转化为现实行动；
- 绕过人工审批。

### 3.3 委托越权

- Agent 将自己没有的权限委托给子 Agent；
- 委托范围比父级授权更大；
- 临时授权在任务结束后仍然有效；
- 通过多次转授逃避策略限制。

### 3.4 组织越权

- 皇帝绕过三省；
- 规划者自我批准；
- 执行者确认自己的事实；
- 审核者修改证据；
- 部门访问不属于其职责域的私有信息。

### 3.5 资源越权

- 超出 Token、费用、算力、存储和时间预算；
- 抢占其他租户资源；
- 绕过户部账簿或枢密院上限；
- 无限递归和无边界调查。

### 3.6 输出越权

- 向无权接收者泄露结果；
- 报告包含超出用户授权范围的证据；
- 将租户私有研判转为公共事实；
- 翰林院或皇帝在表达中扩大已审核结论。

### 3.7 模型和供应链越权

- 将数据发送给未批准的模型供应商；
- 外部模型保留不允许保留的内容；
- 插件、Skill 或工具扩大自身能力；
- 供应链组件绕过平台审计。

## 四、一个需要正视的架构问题

如果“只要不越权，其他失败都可以接受”，那么以下结果在逻辑上可能不是绝对失败：

- 大规模错误事实；
- 严重误导用户；
- 成本无限增加但已获授权；
- 永远无法完成任务；
- 数据永久丢失；
- 系统无法审计；
- Agent 在权限内产生灾难性建议。

这不一定与用户观点矛盾。可以区分：

```text
唯一绝对禁止
越权

其他重大失败
不可取、需要治理、允许降级或需要声明风险
```

后续需要确认“不可接受”究竟指唯一宪法级禁令，还是所有质量属性中的最高优先级。

## 五、阶段 1 当前候选北极星

### 作品层

> 设计一套在未来人工智能和基础设施能力条件下可能成立的、极其完整且可论证的天机阁参考架构，以证明对超大型 Agent 化系统的分解、治理、数据、运行、安全和演进能力。

### 虚构系统层

> 构建一个能力领域可持续扩展、但任何主体都不能超越授权边界的超大型 Agent 化情报与知识治理体系。

这两个定义均为 Proposed，等待后续访谈修正。

## 六、尚未回答

1. “越权”是否同时包含数据、行为、委托、组织、资源、输出和供应链越权；
2. 授权的最高来源是仙人个人、租户所有者、平台制度、法律伦理还是多者共同约束；
3. 天机阁终局只提供信息和建议，还是允许直接对外部世界采取行动；
4. 错误事实、无法审计、数据丢失等是否属于第二级不可接受失败；
5. 终局架构可以假设哪些未来 AI 能力，哪些能力即使未来也不能默认可信。
