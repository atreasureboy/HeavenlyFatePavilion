# 候选终局架构地图

状态：Proposed

## 一、目标

本地图定义天机阁终局参考架构需要覆盖的完整问题空间。它不是部署图，也不是组件清单，而是后续所有专题设计的总索引。

现有顶层目录主要解决材料的生命周期管理；本地图解决系统本身应由哪些架构板块组成。

## 二、三层骨架

### 第一层：架构宪法

定义不可被局部设计随意改变的内容：

- 项目目的和非目标；
- 系统边界；
- 人类主权；
- 伦理和合法数据边界；
- 权力分立原则；
- 证据驱动原则；
- 多租户隔离原则；
- Agent 与确定性系统的分工原则；
- 核心质量属性和架构不变量。

### 第二层：终局架构全景

定义系统必须覆盖的全部架构板块及相互关系。

### 第三层：纵向验证切面

选择少量复杂场景，从用户意图一直贯穿到数据、运行、安全、成本、审计和故障恢复，以验证第二层并非互不相连的专题集合。

## 三、终局架构板块

### A. 世界、主体与租户

- 天界平台；
- 仙门租户；
- 仙人用户；
- 皇帝租户级交互主体；
- 平台运营者、租户所有者、成员和外部协作者；
- 单租户、企业多用户及跨租户会盟；
- 人类最终授权和责任边界。

### B. 朝廷治理与权力体系

- 皇帝的统筹权与非无限权限；
- 中书省规划权；
- 尚书省执行和资源编排权；
- 门下省审核、反证和封驳权；
- 六部专业职责；
- 直属官署；
- 任免、授权、用印、奏报、升级和问责；
- Agent、策略引擎、服务和 Worker 的官职映射。

### C. 情报产品与用户能力

- 主动调查；
- 持续监测；
- 人物、企业、项目和事件档案；
- 时间线；
- 专题空间；

- 风险告警；

### D. 情报领域与知识语义

- Entity、Event、Relationship；
- Signal、Assessment、Inference 和 Recommendation；
- Intelligence Product；
- 身份消歧、事实版本和双时态；
- 公共事实与租户私有判断；

## 四、首批纵向深切面

建议用以下场景优先贯穿全部板块：

1. 对存在大量同名候选人的人物进行证据级调查；
2. 持续监测一家企业并发现重大经营或人员变化；
3. 多个高可信来源给出互相冲突的事实；
4. 恶意网页通过提示词注入操纵调查链；
5. 突发事件造成全平台采集、搜索和研判洪峰；
6. 租户删除私有资料及其全部派生结果；
7. Token 预算即将耗尽，户部触发预算压力和降级流程；
8. 皇帝或高级 Agent 行为异常，人类收回控制权。

## 五、骨架完成判据

终局骨架的第一阶段不要求每一板块达到同等深度，但必须做到：

- 每个板块有清晰边界、职责和非职责；
- 每项核心状态有唯一权威所有者；
- 每条跨板块调用有身份、权限、预算和审计语义；
- 每项关键结论可以追溯到输入、证据和决定；
- 每个质量属性至少有一个可验证场景；
- 每个重要设计都说明假设和重新评估条件；
- 至少两条纵向深切面能够贯穿全系统；
- 不存在只能靠“Agent 自己判断”解释的关键控制机制。

## 六、当前判断

推荐采用：

> 全域骨架先行，局部深度迭代。

先构建完整的问题空间和浅层架构基线，再通过纵向场景逐步加深。这里的“迭代”不是从小产品扩建，而是在固定全局坐标系内不断提高设计分辨率，并允许验证结果反向修正骨架。
