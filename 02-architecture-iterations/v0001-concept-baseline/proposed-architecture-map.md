# 候选终局架构地图

状态：Proposed

## 一、目标

本地图定义天机阁终局参考架构需要覆盖的完整问题空间。它不是部署图，也不是组件清单，而是后续所有专题设计的总索引。

现有顶层目录主要解决材料的生命周期管理；本地图解决系统本身应由哪些架构板块组成。

## 二、三层骨架

### 第一层：架构宪法

定义不可被局部设计随意改变的内容：

- 项目目的和非目标；
- 系统边界；
- 人类主权；
- 伦理和合法数据边界；
- 权力分立原则；
- 证据驱动原则；
- 多租户隔离原则；
- Agent 与确定性系统的分工原则；
- 核心质量属性和架构不变量。

### 第二层：终局架构全景

定义系统必须覆盖的全部架构板块及相互关系。

### 第三层：纵向验证切面

选择少量复杂场景，从用户意图一直贯穿到数据、运行、安全、成本、审计和故障恢复，以验证第二层并非互不相连的专题集合。

## 二点一、四个必备观察视角

终局架构地图中的每一个重要节点都必须同时接受四种检查：

1. **业务数据视角**：它在收集、清洗、整理、分配和管理中承担什么责任；
2. **Agent 经济性视角**：为什么需要或不需要 Agent，如何在不降低功能的前提下控制 Token；
3. **宏观分解视角**：它在顶层职责树中的父节点、子节点和边界是什么；
4. **租户用户视角**：不同租户、用户、权限、风险和产品需求如何影响它。

树负责表达职责和所有权，图负责表达依赖和数据流，矩阵负责表达多租户、安全、预算、证据和质量等横切关系。终局架构不强制使用严格二叉树。

## 三、终局架构板块

### A. 世界、主体与租户

- 天界平台；
- 仙门租户；
- 仙人用户；
- 皇帝租户级交互主体；
- 平台运营者、租户所有者、成员和外部协作者；
- 单租户、企业多用户及跨租户会盟；
- 人类最终授权和责任边界。

### B. 智能治理体系

- 皇帝的统筹权与非无限权限；
- 中书省规划权；
- 尚书省执行和资源编排权；
- 门下省审核、反证和封驳权；
- 治理型直属官署；
- 任免、授权、用印、奏报、升级和问责；
- Agent、策略引擎、服务和 Worker 的官职映射。

### C. 人机交互

- 皇帝交互投影；
- 持续对话与长期关系；
- 多模态入口；
- 主动通知、提醒和告警交互；
- 用户反馈与纠正；
- API、消息渠道和协作界面。

### C2. 情报产品

- 主动调查；
- 持续监测；
- 人物、企业、项目和事件档案；
- 时间线；
- 专题空间；
- 趋势和机会雷达；
- 风险告警；
- 日报、周报和专题报告；
- 可追溯的交付与产品版本。

### C3. 领域能力体系

- 吏部人物与机构能力；
- 户部商业、资源与机会能力；
- 礼部观点、传播与舆情能力；
- 兵部时政、地缘与安全能力；
- 刑部法规、风险与事实裁定能力；
- 工部技术、采集与工程能力；
- 跨部协作与领域型公共官署。

### D. 情报领域与知识语义

- Source、Document、Snapshot；
- Evidence、Claim、Fact 和 Disputed Claim；
- Entity、Event、Relationship；
- Signal、Assessment、Inference 和 Recommendation；
- Intelligence Product；
- 身份消歧、事实版本和双时态；
- 公共事实与租户私有判断；
- 来源信誉、证据等级和结论置信度。

本领域需要支撑两个一级智能面及其六项核心能力：

- 数据认知面：掌数、联结、察变；
- 情报研判面：推势、卜算、警险。

两面相互反馈：研判可以反向提出新的掌数、联结和察变任务，认知结果也会持续修正态势、预测和风险。

### E. 数据获取与加工体系

- 来源发现和准入；
- 抓取、接收和上传；
- 原始资料保存；
- 清洗、解析、去重和语言处理；
- 实体和关系抽取；
- 身份解析和实体合并；
- Claim 生成与证据绑定；
- 事件聚类、变化检测和趋势计算；
- 数据许可、保留、删除和纠错传播。

本体系不能止于数据加工。它需要连接到：

- 跨来源、跨实体和跨领域关联；
- 文档、事实、实体、关系、事件和观点 Diff；
- 变化聚合与变化关联；
- 当前态势和影响链推断；
- 趋势预测和情景推演；
- 风险形成、升级、告警和解除；
- 新情报反向触发的收集与验证闭环。

### F. 智能执行与运行时

- Agent 身份、模板和实例；
- Run、Task、Session 和 Context；
- 规划、调度、调用和消息传递；
- Tool、Skill、Memory 和 Workspace；
- 按需实例化和模型路由；
- Agent 调用树、预算传播和深度限制；
- 进程式隔离、能力句柄和系统调用；
- 超时、取消、循环、死锁、崩溃和恢复；
- 人类介入与控制权回收。

本架构面由天机阁独立定义。AgentOS 及其他 Agent Runtime 只作为外部参考或未来部署适配目标。

### H. 身份、安全与信任

## 四、首批纵向深切面

建议用以下场景优先贯穿全部板块：

1. 对存在大量同名候选人的人物进行证据级调查；
2. 持续监测一家企业并发现重大经营或人员变化；
3. 多个高可信来源给出互相冲突的事实；
4. 恶意网页通过提示词注入操纵调查链；
5. 突发事件造成全平台采集、搜索和研判洪峰；
6. 租户删除私有资料及其全部派生结果；
7. Token 预算即将耗尽，户部触发预算压力和降级流程；
8. 皇帝或高级 Agent 行为异常，人类收回控制权。

## 五、骨架完成判据

终局骨架的第一阶段不要求每一板块达到同等深度，但必须做到：

- 每个板块有清晰边界、职责和非职责；
- 每项核心状态有唯一权威所有者；
- 每条跨板块调用有身份、权限、预算和审计语义；
- 每项关键结论可以追溯到输入、证据和决定；
- 每个质量属性至少有一个可验证场景；
- 每个重要设计都说明假设和重新评估条件；
- 至少两条纵向深切面能够贯穿全系统；
- 不存在只能靠“Agent 自己判断”解释的关键控制机制。

## 六、当前判断

推荐采用：

> 全域骨架先行，局部深度迭代。

先构建完整的问题空间和浅层架构基线，再通过纵向场景逐步加深。这里的“迭代”不是从小产品扩建，而是在固定全局坐标系内不断提高设计分辨率，并允许验证结果反向修正骨架。
