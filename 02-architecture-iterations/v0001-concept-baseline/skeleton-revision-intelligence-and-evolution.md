# 骨架修订：数据认知、情报研判与全域演进

状态：Accepted into Baseline

记录日期：2026-07-24

## 一、本轮修订

本轮对第一版整体骨架作出三项重要修订：

1. 数据关联、数据 Diff 和变化关联不是普通的数据整理细节，而是天机阁最困难、最核心的智能能力；
2. 天机阁不仅保存数据，还要推断大势、卜算趋势、告警风险；
3. 数据认知与情报研判是两个相互反馈、职责不同的一级架构面；
4. 能力演进不是普通运维能力，而是覆盖全系统的独立一级架构面；
5. AgentOS 是另一个项目提供的参考，不是天机阁当前架构的依赖或组成部分。

## 二、天机阁的智能业务主干

候选业务主干从简单数据流水线升级为：

```text
需求与监测目标
        ↓
掌数：收集、清洗、整理、管理
        ↓
联结：实体、关系、事件、证据跨域关联
        ↓
察变：Diff、变化识别、变化聚合和变化关联
        ↓
推势：从事实与变化推断当前态势和影响链
        ↓
卜算：形成趋势、情景和概率化未来判断
        ↓
警险：识别风险、触发告警并持续跟踪
        ↓
查询、图谱、档案、报告、告警和研判产品
        ↓
反馈与新的监测目标
```

这不是严格的单向流水线。关联、察变、推势、卜算和警险会反向触发新的数据收集、验证和调查。

## 三、六项核心能力

### 3.1 掌数

掌握数据不是简单存储，而是形成可信、可追溯、可持续管理的数据底座。

包括：

- 来源发现与准入；
- 数据收集；
- 原始资料保存；
- 清洗和标准化；
- 结构化整理；
- 事实和证据管理；
- 数据分配；
- 生命周期管理。

### 3.2 联结

联结负责回答“哪些数据实际上描述同一主体、同一关系、同一事件或同一变化”。

包括：

- 实体解析；
- 同名消歧；
- 身份合并；
- 关系图谱；
- 跨来源证据关联；
- 跨领域关联；
- 人物、机构、项目、地点、事件和观点之间的关联；
- 历史与当前状态关联；
- 公共事实与租户私有资料的受控关联。

联结不等于向量相似。相似性只是候选生成手段，正式关联需要身份、时间、证据和置信度语义。

### 3.3 察变

察变负责从持续更新的数据中发现“什么发生了变化”。

包括：

- 原始文档 Diff；
- 结构化字段 Diff；
- 语义 Diff；
- 实体状态变化；
- 关系变化；
- 职位、项目、产品、政策和观点变化；
- 多个微小变化聚合成事件；
- 同一变化在不同来源中的传播；
- 变化之间的时间和影响关联；
- 变化的重要性和异常度。

Diff 不能只比较文本。天机阁需要同时比较：

```text
内容变化
事实变化
实体变化
关系变化
事件变化
观点变化
趋势变化
```

### 3.4 推势

推势负责基于事实、关系、事件和变化形成当前态势判断。

包括：

- 影响链推断；
- 关联与因果候选区分；
- 跨领域综合；
- 事件升级判断；
- 结构性变化识别；
- 当前大势和局势解释；
- 支持与反对证据；
- 不确定性表达。

推势结果属于 Assessment 或 Inference，不能直接伪装成 Fact。

### 3.5 卜算

“卜算”是叙事名称，正式技术语义是趋势预测、情景推演和概率化判断。

包括：

- 趋势外推；
- 情景树；
- 先行指标；
- 预测区间；
- 可能事件；
- 关键变量；
- 反事实分析；
- 预测失效条件；
- 随新证据持续修正。

卜算必须保留假设、模型、输入、时间点和置信区间，不得将未来判断写成已经发生的事实。

### 3.6 警险

警险负责将变化、态势和预测转化为可操作的风险信号。

包括：

- 已发生风险；
- 正在形成的风险；
- 预测风险；
- 异常告警；
- 风险等级；
- 影响范围；
- 证据和触发条件；
- 告警去重与合并；
- 风险升级和解除；
- 后续持续监测。

## 四、三省六部采用混合结构

当前采纳为骨架候选的是混合结构：

- 皇帝和三省属于智能治理与统筹层；
- 六部属于专业领域能力层；
- 公共官署根据职责分布在数据、运行、控制、验证和产品区域；
- 三省六部不包办确定性数据流水线；
- 情报生产体系也不绕开三省六部的规划、综合和审核能力。

因此，官制不是一棵覆盖所有技术组件的组织树，而是作用于情报生产和智能决策的治理与领域结构。

## 五、能力演进面

### 5.1 定位

天机阁不能是一成不变的静态系统。未来模型能力、数据规模、领域知识和用户需求都会变化，能力演进必须成为一级架构面。

能力演进覆盖全部系统对象，而不只有模型：

```text
模型
Agent
Prompt / Context Policy
Skill
Tool
Workflow
领域本体和 Schema
来源和采集器
检索与关联策略
验证规则
风险模型
评测集
组织与官署能力
平台控制与多租户机制
数据与基础设施架构
天机阁整体架构
```

### 5.2 两种演进模式

```text
能力演进
├── 自主演进：系统自行观察、提出、实验、验证并在治理许可下采用变化
└── 人类主导演进：由人类发现时代变化、修订设计、验证并推动升级
```

现阶段或未来任何时点，某部分不能自主演进，不代表它可以停止演进。自主程度可以逐步提高，但跟随 Agent 时代持续演进是架构生存条件。

### 5.3 通用闭环

```text
观察
→ 发现能力缺口或性能退化
→ 生成改进候选
→ 沙箱实验
→ 评测与对抗验证
→ 审核和版本化
→ 灰度发布
→ 持续监测
→ 保留或回滚
```

### 5.4 一级子域

- 能力观察；
- 模型和 Agent 演进；
- Tool 与 Skill 演进；
- 工作流演进；
- 数据和知识结构演进；
- 来源适配演进；
- 评测与仿真；
- 版本、发布和回滚；
- 架构适应性。

### 5.5 与普通运维的区别

普通运维保持系统按既定能力运行；能力演进面负责改变系统的能力本身。

人类架构演进与系统自主演进是同一能力演进面的两种驱动方式。二者共享观察、候选、实验、验证、版本和回滚语义，但拥有不同的发起主体与治理路径。

## 六、AgentOS 的边界修订

AgentOS 是独立项目。天机阁可以借鉴其思想，例如：

- Run 和 Task；
- Agent 通信；
- Tool 与 Skill；
- Memory 与 Workspace；
- Scheduler 与 Worker；
- Event Log；
- 沙箱和隔离；
- 多租户上下文。

但天机阁当前架构：

- 不依赖 AgentOS 的实现；
- 不继承 AgentOS 的具体接口；
- 不把 AgentOS 画成内部层级；
- 不要求与 AgentOS 同时演进；
- 需要独立定义自己的智能执行与运行需求。

未来可以通过适配层部署在 AgentOS 或其他运行平台上，但那属于部署映射，不属于当前逻辑骨架。

## 八、待继续访谈

已确认：

- 数据底座是独立一级面；
- 基础设施不是一级逻辑面，而是所有逻辑面的共同承载底座；
- 皇帝是红后、EVA、贾维斯式具身化智能中枢，其本体位于治理面，在交互面形成统一投影。

后续骨架深化：

1. 为十个一级面分别建立完整二级能力树；
2. 裁定公共官署应归入哪个职责面，避免按历史名称机械归类；
3. 能力演进的变更采用权如何与三省和人类主权衔接，留待治理专题深化。
