# v0001：概念基线

状态：Draft

## 本轮目标

建立天机阁第一版概念骨架，明确：

- 仙人、皇帝、三省、六部和百官的技术映射；
- 人类主权与 Agent 权限边界；
- 高级 Agent 与确定性工具的分工；
- 单租户朝廷如何扩展成多租户平台；
- 天机阁自身智能运行系统与 AgentOS 等外部参考项目的边界；
- 原始资料、证据、主张、事实和研判的基本关系。

## 当前输入

- 最初的天机阁总体架构设想；
- 三省六部作为 Agent 治理体系的类比；
- Windows 进程与操作系统作为多 Agent 运行模型的类比；
- “仙人—皇帝—朝廷”的人机关系；
- 多仙门、多仙人和租户级逻辑朝廷；
- 少数高级官员使用 Agent，其余尽可能采用脚本、工具、Worker 和规则。
- 架构讨论采用对话驱动的持续沉淀机制：有价值的新见解必须在产生当轮归档，并保持思路、迭代、决策和当前架构之间的成熟度边界。
- 候选设计方法采用“全域骨架先行，局部深度迭代”：不从 MVP 扩建终局，而是先定义完整问题空间，再逐步提高各区域的设计分辨率。
- 从实际业务、Agent 经济性、宏观分解和多租户用户需求四个视角修复骨架，避免架构只从官制类比出发。
- 阶段 1 访谈确认现实交付物是架构本身而非实现；虚构系统暂不预设封闭功能领域，并提出“能力开放、权力受限”的最高原则候选。
- 当前第一阶段优先目标调整为整体架构骨架：先确定根节点、一级架构面、二级能力域和横切维度，再进入安全、权限及其他局部专题。
- 业务主干增加数据关联、Diff 与变化关联、推势、卜算和风险告警；三省六部采用混合结构；数据认知与情报研判拆为两个一级面；新增覆盖全系统的能力演进面；AgentOS 降为外部参考项目。
- 皇帝采用红后、EVA、贾维斯式“具身化智能中枢”定位：本体属于朝廷治理面，在交互产品面形成统一投影；数据底座固定为独立一级面；基础设施降为所有逻辑面的共同承载底座。
- 用户交互与情报产品拆分为人机交互面和情报产品面；朝廷治理与领域协作拆分为智能治理面和领域能力面；平台控制与智能运行按长期期望状态和即时执行状态划界。
- 七个横切维度采用统一的权威、上下文、强制点、控制证据、失败与演进模型；多租户、权限、硬预算、审计和生命周期等约束由确定性机制执行，Agent 负责规划、解释、审核和例外建议。
- 第一批九个端到端场景已经覆盖十面、七维横切、主要对象状态和正常/异常路由，使 `Skeleton v0.1` 达到逻辑骨架闭合里程碑；后续转入局部专题深度设计和定量验证。
