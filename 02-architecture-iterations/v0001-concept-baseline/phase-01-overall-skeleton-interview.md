# 阶段 1：整体架构骨架访谈

状态：Draft

启动日期：2026-07-24

## 一、阶段目标

当前第一阶段只建立天机阁的整体架构骨架。

本阶段采用从整体到局部的方式，先确定：

- 根节点；
- 一级架构面；
- 二级能力域；
- 各架构面之间的基本关系；
- 哪些概念是层级节点；
- 哪些概念是贯穿全局的横切维度；
- 后续每个局部专题应该挂在哪里。

本阶段不深入：

- 越权和授权细节；
- 安全策略；
- Agent 状态机；
- 数据库选型；
- 消息协议；
- Token 计算公式；
- 单个官署的内部设计；
- 故障恢复算法。

这些内容必须先在整体骨架中获得位置，之后再分别展开。

## 二、第一阶段完成物

### 整体架构根图

从天机阁根节点展开到一级架构面和二级能力域。

### 视图规则

明确：

- 树用于表达什么；
- 分层图用于表达什么；
- 横切矩阵用于表达什么；
- 数据流和控制流如何单独表达。

### 顶层关系

至少说明：

- 用户需求如何进入系统；
- 情报生产如何运转；
- 三省六部治理作用于什么对象；
- AgentOS 承载什么；
- 数据底座保存什么；
- 多租户如何贯穿；
- 最终结果如何输出。

### 局部专题索引

后续任何设计问题都能放入一个明确的一级或二级节点，不需要临时创造新的顶层分类。

## 三、当前候选一级骨架

以下只作为访谈起点：

```text
天机阁
├── 用户与产品面
├── 情报生产面
├── 智能治理面
├── 运行与数据面
└── 平台控制面
```

候选横切维度：

```text
多租户
身份与权限
证据与血缘
预算与资源
风险与质量
审计与追踪
数据生命周期
```

这套划分尚未被接受。第一轮访谈需要判断五个架构面是否正确，以及三省六部、AgentOS 和多租户应该怎样放置。

## 四、第一轮访谈问题

### 问题 1：情报生产主干

天机阁最核心的主干是否就是：

```text
需求 / 目标
→ 数据收集
→ 数据清洗
→ 数据整理
→ 数据分配
→ 数据管理
→ 查询、监测、报告和其他输出
→ 反馈
```

如果不是，缺少什么或顺序哪里不对？

### 问题 2：三省六部的位置

三省六部更接近哪一种：

1. 整个天机阁的最高层，所有业务和基础设施都在其下；
2. 情报生产主链上的智能治理与决策层；
3. 与情报生产、运行平台并列的独立架构面；
4. 三者混合：皇帝和三省是治理层，六部是领域业务层，公共官署分散在数据与控制面。

### 问题 3：一级架构面

候选的五个一级架构面是否合理：

- 用户与产品面；
- 情报生产面；
- 智能治理面；
- 运行与数据面；
- 平台控制面。

哪些应该合并、拆开、改名或新增？

### 问题 4：AgentOS 与多租户

AgentOS 应该是：

- 天机阁内部最底层；
- 天机阁之外的通用运行基座；
- 逻辑上外部、总图中仍作为底座展示；
- 未来直接成为天机阁的一部分。

多租户应当是：

- 一个独立一级分支；
- 平台控制面的子能力；
- 贯穿所有架构面的横切维度；
- 同时具有控制面和横切属性。
