# v0001 开放问题

状态：Draft

## Q-0001：三省是否必须始终由 Agent 实现

三省代表三种权力，但权力主体不必等于每个任务都调用大模型。需要确定：

- 中书省是否可以对模板化任务跳过 Agent；
- 尚书省 Agent 与 Workflow Engine 如何分权；
- 门下省能否对低风险结果只执行确定性验证；
- 什么风险等级强制进入三省 Agent。

## Q-0002：尚书省、钦天监与 AgentOS Scheduler 如何分工

当前三者都涉及“调度”：

- 尚书省负责业务级动态编排；
- 钦天监负责定时监测、异常发现和触发；
- AgentOS Scheduler 负责运行时排队、租约、重试和资源调度。

需要建立统一任务模型，防止三套调度状态互相覆盖。

## Q-0003：门下省、刑部、大理寺与都察院如何分工

四者均涉及审核或裁定，候选区分是：

- 门下省：对任务计划和最终结论行使独立审核权；
- 刑部：提供法规、合规和风险领域能力；
- 大理寺：处理事实主张之间的冲突；
- 都察院：持续审计系统行为和质量。

需要用同一争议事实场景验证是否仍有职责重叠。

## Q-0004：户部与枢密院如何处理成本治理

候选区分是：

- 户部负责计量、预算、成本预测和资源建议；
- 枢密院负责不可绕过的调用策略和上限强制执行；
- 皇帝或仙人负责超预算授权；
- 尚书省负责在已批准预算内选择执行和降级路径。

需要明确谁能冻结任务、谁能申请增拨、谁能批准增拨。

## Q-0005：吏部人物情报与 Agent 任免是否属于同一边界

吏部同时可能承担：

- 对天下人物、机构和任职关系的情报业务；
- 对朝廷内部 Agent Registry、能力和任免的治理职责。

需要判断这是一个双重职责官署，还是应拆成业务吏部与平台级 Agent Registry。

## Q-0006：皇帝和翰林院谁拥有最终表达权

候选区分是：

- 翰林院负责报告结构、模板、引用和渠道适配；
- 皇帝负责结合当前仙人的目标进行最终解释和对话；
- 门下省负责确保表达没有改变已审核结论。

需要设计防止润色阶段改变事实语义的机制。

## Q-0007：“核心常驻 Agent”应如何正式命名

模型进程不应持续运行。候选术语包括：

- 稳定注册 Agent；
- 核心逻辑 Agent；
- 常设 Agent 身份；
- 按需实例化的常设官职。

需要在术语表中选择不会误导运行模型的正式名称。

## Q-0008：部级 Agent 是否应默认参与每次任务

候选原则是优先使用数据库、Tool、规则和专用模型，只有遇到歧义、冲突和跨域综合时才升级到部级 Agent。

需要定义：

- 升级条件；
- 风险阈值；
- 预算阈值；
- Tool 结果是否足以直接进入门下审核；
- 部级 Agent 被跳过时由谁形成部门奏报。
