# v0002 影响分析

状态：Draft

## 直接影响

| 区域 | 预期影响 |
|---|---|
| 数据认知面 | 明确采集、抽取、关联、消歧和变化识别的输出类型 |
| 情报研判面 | 明确推断、预测、风险和建议不能被降格成 Fact |
| 数据底座面 | 明确权威对象、版本、血缘和纠正传播需求 |
| 情报产品面 | 明确引用、快照、撤回、更正和影响通知语义 |
| 智能治理面 | 明确哪些对象需要审核、封驳或事实裁定 |
| 领域能力面 | 领域本体必须扩展共享对象，而不是另建不兼容主干 |

## 后续依赖

本轮将约束数据与存储架构、Contract Envelope、核心状态机、审核与事实裁定、多租户知识覆盖、搜索与图谱、事实撤回以及质量审计。

## S7 新增影响

| 区域 | 候选约束 |
|---|---|
| 情报产品面 | 逻辑产品、内容版本、发布授权、Rendering、分发和送达必须可分别表达 |
| 数据底座面 | 需要固定版本、有类型的依赖图，以及作用域安全的反向影响查询 |
| 智能治理面 | 发布、更正、限制、撤回与 Impact Case 关闭需要独立决定和审核 |
| 人机交互面 | 送达、确认、消费、Feedback 与纠正通知不能合并 |
| 智能执行与运行面 | 图查询和规则先裁剪，Agent 只复核语义不确定或高影响分支 |
| 平台控制面 | 分发副作用前重新强制身份、用途、许可、地域与产品有效状态 |
| 能力演进面 | 产品错误、血缘缺失、未送达纠正和用户反馈可形成演进证据候选，但不得自动部署 |

S7 暴露的主要架构代价是：

- 依赖边过粗会造成错误级联，过细会形成高昂建模成本；
- 完整接收者追踪与隐私最小化存在张力；
- 动态产品的历史可复现会带来检查点和保留成本；
- 外部下载和二次派生无法被绝对召回，必须保留主权边界与剩余风险；
- Product、Edition、Release、Impact Case 和各种过程记录若全部升格，会产生对象膨胀。

因此 S9 必须对这些候选重新执行对象准入测试，物理数据架构则需要证明依赖图查询、增量失效和租户隔离可以同时成立。

## S8 新增影响

| 区域 | 候选约束 |
|---|---|
| 数据底座面 | 支持二时态 Revision、认识记录、版本图、watermark、检查点和可重建等级 |
| 平台控制面 | 将 ownership、visibility、authority、purpose、jurisdiction、retention 分别判定并版本化 |
| 数据认知面 | 不得把采集、可用、验证和接受时间合并；迟到资料不能倒写记录历史 |
| 情报研判面 | Assessment / Forecast 显式固定 world as-of、knowledge cutoff 和输入 Revision |
| 情报产品面 | Product Edition 保存知识截点、选择策略和可复现 Manifest |
| 人机交互面 | “当前”“当时”“按今天所知回看”必须转化为不同 Query Context |
| 智能执行与运行面 | 历史回放、缓存失效和查询包构建必须确定性执行，Agent 不直接扫描全历史 |
| 领域能力面 | 提供时间精度、角色、辖域和 Authority Domain 对命题的适用规则 |

S8 暴露的主要架构代价是：

- 认识时间不能压成单列，会增加权威域—对象关系和查询复杂度；
- 跨作用域版本不是全序，通用“取最大版本号”接口失效；
- 检查点过密会导致存储爆炸，过疏会降低历史重建强度；
- 当前授权与历史行为回放之间需要双重策略门；
- 删除、许可到期和模型不可执行会使 Exact replay 不总是可得；
- 缓存键维度明显增加，但省略任一关键维度都可能产生错误或泄露。

这些代价是天机阁能够诚实回答“谁在什么时候基于什么知道什么”的必要成本。物理实现可优化，但不能消除语义坐标。

## S9 新增影响

| 区域 | 候选约束 |
|---|---|
| 智能治理面 | Governance Case、Decision、Transition 和权力分离成为跨对象治理内核 |
| 数据底座面 | 原子保管 Revision、Transition、Mandatory Edges 和 Outbox，但不取得语义接受权 |
| 平台控制面 | Authority Mandate 必须可判定操作、对象、作用域、用途、风险、时间和委托深度 |
| 智能执行与运行面 | 所有关键状态变化使用统一 Transition Envelope，外部副作用使用 Saga |
| 数据认知面 | Mention 正式进入核心候选；Fact 晋升必须经过 Claim / Verification / Acceptance |
| 情报研判面 | 高影响自审按认知失效根阻断；Forecast 评分主体与生成主体分离 |
| 情报产品面 | Edition 内容生命周期和 Release 发布授权分离；血缘等级成为发布门 |
| 能力演进面 | 生产失败、血缘断裂和越权拒绝可形成 Evolution Evidence，但不能自动改能力 |

S9 暴露的主要架构代价是：

- 一等支撑记录数量增加，需要避免将其误建成同等重量的业务聚合；
- Mandate 和状态向量检查会增加每次关键提交的控制成本；
- 固定 Revision 的边数量较大，需要后续数据架构证明增量查询和分层存储；
- 认知独立性无法只用 principal 不同判断，需要追踪共同模型、数据、Prompt 和 Tool 失效根；
- Edition / Release、Fact / Epistemic Record 等逻辑拆分会要求现有状态机建立兼容投影；
- 无法一次性把全部领域特例固化为通用状态机，必须保留类型化扩展。

这些是把“Agent 自觉遵守”升级为“架构可强制证明”的必要代价。S10 必须验证统一模型不会因概念税反而降低可解释性。

## 主要风险

- 对象数量过多，形成概念税；
- 为追求形式完美而脱离情报场景；
- 将逻辑对象直接等同于数据库表；
- 过早统一所有领域本体；
- 置信度数字产生虚假精确；
- 版本和时间语义过重，无法解释其架构收益。

## 控制原则

每增加一种正式对象，至少证明它具有独立的身份、生命周期、权威所有者、审计或纠正需求，以及两个以上跨面消费者。否则优先作为属性、关系或视图。
