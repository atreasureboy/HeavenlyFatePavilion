# Heavenly Fate Pavilion

中文名：天机阁企业级智能情报平台

## ⭐ 最高优先级设计启发

天机阁的架构设计有两个需要贯穿始终的核心思想来源。

### ⭐ 三省六部：Agent 协作与治理体系

中国古代的三省六部制度可以被理解为一套成熟的多主体协作与权力治理体系。将其中承担职责的人替换为 Agent，这套制度便能自然映射为多 Agent 系统：

- 中书省负责规划、拟定方案与形成任务目标；
- 尚书省负责执行编排、资源调度与跨部门协作；
- 门下省负责审核、反证、封驳与风险控制；
- 六部负责具有明确边界的专业领域能力；
- 其他官署承担事实归档、冲突裁定、监察审计、安全治理、持续监测和产品输出。

这个映射的重点不是使用古代名称包装普通工作流，而是继承其职责分离、权力制衡、专业分工、逐级委托、审核纠错和责任追溯思想。三省六部将作为天机阁上层 Agent 治理与领域协作体系的重要思想来源。

### ⭐ Windows：主 Agent 与子 Agent 的系统模型

Windows 及现代操作系统可以被视为目前最成熟、最稳定的大规模协作系统之一。如果把进程类比为子 Agent，把正在使用计算机的人类视为主 Agent，那么操作系统已经长期解决了大量与多 Agent 系统高度相似的问题：

- 主体身份与安全令牌；
- 进程创建、调度、暂停和终止；
- 用户态与内核态的权力边界；
- 进程隔离和虚拟地址空间；
- 线程、作业与进程树；
- 句柄、对象和能力访问；
- 系统调用与受控工具调用；
- 进程间通信与同步；
- 优先级、配额、公平性和资源治理；
- 异常、超时、死锁、崩溃与恢复；
- 服务、守护任务和事件驱动执行；
- 文件系统、注册表、日志与持久状态；
- 驱动、插件和外部设备的信任边界；
- 人类作为最终控制者对整个系统进行观察、授权和干预。

因此，天机阁不应只从现有多 Agent 框架中寻找答案。现代操作系统尤其是 Windows 的进程模型、对象模型、安全模型、调度机制、IPC、资源管理、故障隔离和人机控制关系，将为天机阁的智能执行与运行架构持续提供设计启发。

这两个思想来源分别回答两个不同层面的问题：

```text
三省六部
→ Agent 之间如何分工、制衡、审核、委托和问责

Windows / 现代操作系统
→ Agent 如何创建、隔离、调度、通信、访问资源并安全退出

人类
→ 系统的主 Agent、最终授权者和最终责任主体
```

后续所有专题设计都应主动检查：相关问题是否已经在组织治理制度或成熟操作系统中出现过，以及其中哪些机制可以经过重新抽象后用于 Agent 系统。

### ⭐ 红后、EVA 与贾维斯：皇帝的智能中枢形态

皇帝不是普通聊天机器人，也不只是把请求转交给三省的薄入口。其体验与系统地位更接近虚构作品中的红后、EVA 或贾维斯：一个始终代表整座天机阁与仙人交互、理解全局状态、协调内部能力并统一呈现结果的具身化智能中枢。

这些类比用于提炼“统一人格、全局态势感知、持续陪伴、主动响应和系统级协调”，不意味着照搬虚构系统中的无限控制权。皇帝仍通过三省六部、平台策略和运行系统行使能力，而不是亲自承担全部执行。

## 项目性质

本项目是一套用于深入研究和展示大型系统架构设计能力的虚拟企业级架构，不以完成工程实现为目标。

项目当前不以公司、个人或国家的现实业务价值为存在理由，也不计划实现。现实交付物是架构卷宗、迭代记录、决策、推演和面试呈现。天机阁系统本身则被作为未来人工智能能力条件下的参考架构对象进行设计。

天机阁面向多租户环境，对公开信息、合法授权数据、用户提交资料及租户内部合法数据进行持续采集、清洗、整理和管理，并进一步完成跨域关联、Diff 与变化关联、态势推断、趋势卜算和风险告警。

项目的核心不只是多 Agent 协作，而是研究以下问题如何构成一套自洽、可信、可审计并可演进的复杂系统：

- 海量异构信息的采集、加工和版本管理；
- Document、Evidence、Claim、Fact、Inference 与 Intelligence Product 的严格分层；
- 实体消歧、事件演化、关系构建和证据追溯；
- 公共情报底座与租户私有覆盖层；
- 三省六部式的规划权、执行权与审核权分离；
- Agent、传统程序、专用模型和人工专家的协作边界；
- 分布式运行、并发控制、故障恢复和成本治理；
- 身份、权限、数据安全、来源许可和完整审计；
- 架构决策、容量推演、失败模式与长期演进。

## 项目定位

> 一套面向复杂企业智能业务的、证据驱动且可审计的多 Agent 情报平台架构。

AgentOS 是独立的参考项目，不是天机阁当前架构的组成部分或依赖。天机阁可以借鉴其中关于 Run、Task、Worker、Agent 通信、Tool、Memory、调度、沙箱和事件日志的设计思想，但必须独立定义自身的智能执行与运行架构。

天机阁负责将原始资料转化为可验证、可追溯的事实、关系、变化、态势、趋势、风险和情报产品。数据认知面负责“掌数、联结、察变”，情报研判面负责“推势、卜算、警险”，二者形成持续反馈闭环。

天机阁通过覆盖全系统的能力演进面保持时代适配性：能够自主演进的部分由系统观察、实验和验证，暂时不能自主演进的部分由人类持续升级。演进范围包括模型、Agent、Tool、Skill、工作流、知识结构、来源、评测、组织职责、平台机制、基础设施和整体架构。

数据底座是独立一级架构面；基础设施是所有逻辑架构面的共同承载底座，不与业务和智能能力并列为一级逻辑面。

当前一级逻辑骨架由十个职责面构成：人机交互、情报产品、数据认知、情报研判、智能治理、领域能力、智能执行与运行、数据底座、平台控制和能力演进。平台控制面维护长期期望状态，智能执行与运行面承载具体任务的即时执行状态。

## 核心设计原则

```text
Document ≠ Evidence
Evidence ≠ Claim
Claim ≠ Verified Fact
Fact ≠ Inference
Inference ≠ Recommendation
Agent Memory ≠ Intelligence Database
```

所有重要结论必须能够追溯到来源、原始资料、证据片段、处理过程、审核状态和生成主体。

三省不是三个固定流水线步骤，而是三种相互约束的权力：

- 中书省拥有规划权；
- 尚书省拥有执行与资源编排权；
- 门下省拥有审核、反证与封驳权。
