# 天机阁外层架构骨架终局完成审计

状态：Accepted

审计日期：2026-07-29

审计对象：项目原始设想至情报语义基线 v1 的全部外层架构

## 一、审计结论

天机阁外层架构骨架通过终局完成审计。

这里的“外层骨架完成”有严格含义：

> 对任何后续设计问题，都能先确定它处于哪个外部边界、一级职责面、组织权力、对象家族、全局流、运行形态、坐标与横切约束、生存域和演进半径；尚未细化的内容都有唯一主归属、协作边和升级出口。

它不表示百万字架构已经写完，也不表示数据库、协议、算法、部署和六部内部设计已经完成。它证明这些未来细节不再需要从零发明顶层位置。

## 三、原始设想追踪审计

### 3.1 “天机阁掌数据”

```text
采集
→ 清洗
→ 整理
→ 关联
→ Diff
→ 版本化管理
→ 作用域化供应
```

归属已经分开：

- 数据认知面拥有采集、解析、关联、实体解析和变化认知；
- 数据底座面拥有资料、Revision、血缘、索引、历史和权威保管；
- 平台控制面拥有来源、许可、租户、策略和长期期望状态；
- 工部提供确定性采集、解析、ETL、索引和运行工具；
- 领域能力面提供“如何理解该数据”的专业语义。

不存在用“一个数据库”吞并全部职责的问题。

### 3.2 “联结数据、推断大势、卜算趋势、告警风险”

```text
Evidence / Fact / World Model
→ Signal
→ Assessment
→ Scenario / Forecast
→ Risk
→ Recommendation
→ Product Edition / Alert
```

数据认知与情报研判已经拆面，事实、推断、预测、风险、建议、决定和行动具有明确权力断点。

### 3.3 “三省六部混合制”

- 皇帝提供统一人格、全局态势和协调，不成为无限权限超级 Agent；
- 中书、尚书、门下分别表达规划、执行统筹和审核封驳权；
- 六部是领域能力包，不是六套重复平台；
- 高层规划、跨域判断、反证和综合默认由 Agent 承担；
- 强制校验、策略、存储、高吞吐和可重复处理默认由 Tool / Script / Service 承担；
- 未来超级模型可以合并运行实例，不能静默合并权力、记录和独立验证。

### 3.4 “多仙人即多租户”

正式模型不是简单复制多套天机阁：

```text
Shared Platform
→ Tenant Control Domain
→ Tenant Logical Court / Emperor Identity / Court Profile
→ Public Baseline + Tenant Overlay + Mission Workspace
→ current authorization constrained view
```

共享平台、逻辑朝廷、知识覆盖、租户隔离和联合空间都有稳定位置。

### 3.5 “天机阁必须跟随 Agent 时代演进”

能力演进覆盖模型、Agent、Tool、Skill、工作流、知识结构、组织职责、平台机制、基础设施和架构本身。提议、实验、评测、采用、发布和实际生效权分离；高半径变更必须由有权人类采用。

### 3.6 “唯一绝对边界是不可越权”

越权不是单一安全模块，而是贯穿：

- 外部主权和责任边界；
- 派生、分域、限时、可撤销的内部权力；
- Contract / Transition Envelope；
- 决定、接受、发布和行动的权威分离；
- 确定性 Policy / Transition Guard；
- 审计、撤销传播、停止路径和人类接管。

## 四、结构闭合证明

### 4.1 十层定位闭合

`L0～L9` 共十层：

```text
L0 定位与不可变前提
L1 外部上下文与主权
L2 一级职责
L3 组织治理映射
L4 情报语义与对象
L5 全局运行与协作
L6 坐标与横切治理
L7 生存、负空间与信任边界
L8 全域能力演进
L9 验证与版本闭合
```

层回答“从哪一种架构问题看”；十面回答“哪个稳定职责拥有”；六条主线回答“怎样跨面连接”。三者正交，不互相冒充。

### 4.2 十面归属闭合

十个一级面连续经过 v0.2、v0.3、v1.0 和 v0002 语义专题均未要求增删。v0002 引入的 Mention、Scenario、Governance Case、Product Edition、Epistemic Record 和 Semantic Edge Record 均能稳定归入既有面。

### 4.3 连接闭合

每个面都具有：

- 接受输入与产生输出；
- 权威状态与非职责；
- 上下游依赖；
- 拒绝、退回和失败反馈；
- 对应横切上下文；
- 正常场景和异常场景。

不存在只有节点没有边、只有正向流没有退路的一级面。

### 4.4 冲突闭合

统一冲突阶梯为：

```text
确定性前置校验
→ 中书提出替代 Plan
→ 尚书报告执行与资源事实
→ 门下独立封驳或有条件通过
→ 专业争议交六部 / 刑部
→ 事实争议交大理寺 Governance Case
→ 系统性质量或越权交都察院 / 枢密院
→ 仍不可裁定、超授权或高影响分歧升级仙人 / 有权人类
```

皇帝负责维持议程、呈现分歧和执行最终有效决定，不因“总协调”身份自动取得被保留给人类的原生权力。

## 五、外层骨架允许停止扩张的理由

停止扩张不是因为想不到更多名词，而是因为新问题现在只有三种结果：

1. 可以稳定挂入现有十层、十面和六条主线；
2. 属于横切约束、运行形态、领域内部或实现分辨率；
3. 真正挑战现有一级职责或主权，需要按基线变更纪律重新打开。

目前不存在第四种“没有位置但又不值得重开骨架”的问题。

## 六、仍未完成但不属于外层骨架的工作

- 物理数据架构、Schema、索引和存储选型；
- Contract / Event / Transition 的完整协议；
- Agent Runtime、调度、沙箱和模型路由；
- 角色—权限—动作矩阵与各辖域规则；
- 容量、成本、SLO、多区域和灾难恢复参数；
- 六部和公共官署的内部三级结构；
- 领域本体、证据等级和算法；
- 外部 Action、联合调查和现实效果责任细节；
- 面试叙事、案例与视图压缩。

这些项目全部已有主归属、协作接口和升级路径，因此是“往骨架里填”，不是“继续长外层骨架”。

## 七、重新打开条件

只有出现以下证据之一，才重新进入外层骨架阶段：

1. 一个稳定问题族无法归入十面、横切维度、外部边界或基础设施；
2. 两个一级面无法再维持独立权威；
3. 新主体拥有现有主权模型无法表达的原生权力；
4. 新对象或流必须跨越现有边界才能成立；
5. 新 Agent 代际使现有权力分离机制在语义上失效；
6. 多个独立压力场景反复暴露同一顶层断点。

重新打开必须经过新迭代、ADR、影响分析、压力场景和人类采用。

## 八、最终裁定

> 天机阁的外层骨架已经完善。下一阶段应停止无边界扩张，转为选择专题并从整体位置向内部提高分辨率。

此裁定建立在可追踪证据上；未来可被新证据推翻，但不能因局部设计偏好被静默绕过。
