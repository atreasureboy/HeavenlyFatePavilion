# Skeleton v0.2 集中闭合复核

状态：Accepted

复核日期：2026-07-24

## 一、复核结论

`Skeleton v0.2` 达到“第二轮宏观骨架闭合”。

本结论表示：

- S2～S7 发现的宏观问题都能落入现有一级职责、外部边界或横切结构；
- 十个一级逻辑面不需要增加、删除或重划；
- 新增视图与对象、契约、状态、横切治理和场景主干没有发现结构性矛盾；
- 当前缺口已经从“整片一级结构未知”下降为“场景覆盖和专题分辨率不足”。

本结论不表示：

- 整体骨架已经达到 `Skeleton v1.0`；
- 已经完成协议、Schema、算法、部署、容量或安全细节；
- 已经证明不存在尚未发现的宏观问题；
- 所有未来模型形态都已被验证。

因此正式裁定为：

```text
Skeleton v0.1
→ 第一轮内部闭合

Skeleton v0.2
→ 广度扫描后的第二轮宏观闭合

下一阶段
→ Skeleton v0.3 全局视图闭合与宏观压力场景
```

### 2.2 为什么不新增一级面

候选结构逐项裁定：

| 候选 | 不升格为一级面的原因 |
|---|---|
| 主体生态与主权 | 表达系统外主体和权力来源，不是内部单一职责 |
| 持续监测、批处理、协作、恢复 | 是多个一级面组合形成的运行形态 |
| 七条全局流 | 是跨面关系语义，不拥有业务状态 |
| 作用域、辖域、时间和规模 | 是架构坐标轴，不是职责所有者 |
| 区域与联邦 | 是承载、外部关系和策略边界 |
| 安全、隐私、合规 | 是横切约束及领域知识，不应集中成万能安全面 |
| 最低生存内核 | 是多面共同维持的能力组合 |
| 人类主权 | 是天机阁权力的外部来源，不是内部系统组件 |
| 外部行动 | 最终行动权属于外部主体；天机阁内部只拥有治理、编排和记录 |
| 超级模型 | 是未来实现载体，不是架构职责 |

任何候选一旦升格，都会混淆“谁拥有职责”和“职责处于什么环境、以什么形态运行”。

## 三、升级后的整体骨架表达

`Skeleton v0.2` 之后，天机阁不能再只用“十面树”表达。完整宏观坐标为：

```text
外部主体与主权边界
        │
        ▼
五个视觉域 / 十个一级职责面
        ×
三省六部与公共官署组织映射
        ×
十种全局运行形态
        ×
七条全局流
        ×
作用域、辖域、时间、规模四轴
        ×
多租户、权限、证据、预算、质量、审计、生命周期七维治理
        ×
四类完整性 / 六阶段生存防线 / 八类失效域
        ×
负职责 / 禁止组合 / 默认不可信 / 未来替换边界
        │
        ▼
共同基础设施承载
```

其中只有十个面拥有一级逻辑职责。其余结构分别回答组织、关系、运行、环境、约束、生存和演进问题。

## 五、七道完整性门复核

### G1：顶层覆盖——通过

已覆盖：

- 系统内外主体、权力来源和对抗主体；
- 即时、长期、后台、协作、演进、行动和恢复形态；
- 空间、时间、规模、区域与未来模型；
- 生存底线、负职责和禁止组合。

没有发现稳定且独立、必须拥有权威状态的新一级问题族。

### G2：二级覆盖——通过（骨架级）

S2～S7 的主要能力可落入已有二级能力树：

- 主体交互与产品交付；
- 数据加工、情报研判和领域扩展；
- 治理、运行、隔离、恢复和人类接管；
- 数据供应、平台策略与能力演进。

新增内容主要是关系视图和横切约束，不应为了“图上出现”重复创建能力节点。后续仍可补二级能力名称，不影响一级闭合。

### G3：接口闭合——通过（骨架级）

七条全局流已经把 Command、Data、Knowledge、Decision、Budget、Audit 和 Feedback 的主要语义分开；十面契约定义了输入、输出、拒绝和失败方向。

联邦、联合空间、外部行动和紧急控制仍缺详细契约，但其调用方向、权力来源和拒绝位置已经存在，不构成一级接口断裂。

### G4：对象闭合——通过（保留候选对象）

现有主干可以承载目标、运行、资料、证据、事实、关系、变化、研判、风险、产品和演进证据。

S2～S7 暴露了 `Mandate`、`Trigger`、`Incident`、`Action`、`Effect`、`Authority Conflict` 等候选对象。当前只要求其语义位置存在；是否成为独立对象留给下一分辨率，不阻塞宏观闭合。

### G5：状态闭合——通过（保留细化项）

已有治理执行、知识研判、风险产品和能力演进状态机能够表达：

- 长期目标与临时执行；
- 退回、争议、降级、取消、纠正和回滚；
- 模型退化、权限撤销和灾难恢复入口。

事故、外部行动、联邦协作和恢复影响的详细生命周期尚未定义，但均有状态所有者和异常路由。

### G6：横切闭合——通过

七个横切维度已经通过统一 Context、强制点、证据、失败和演进模型作用于十面。

S5 的辖域覆盖、S6 的生存底线和 S7 的信任边界没有要求新增横切维度；它们分别扩展现有生命周期、权限、风险质量、审计和多租户语义。

### G7：场景闭合——骨架级通过，形成下一轮压力场景清单

现有九个场景已覆盖正常调查、监测、冲突、预算、撤权、跨租户、更正和模型回滚。

S2～S7 仍需要下一轮宏观压力场景：

1. 跨辖域来源、处理、交付规则冲突；
2. 外部联邦节点返回污染事实；
3. 热点事件造成全域资源与认知拥塞；
4. 区域中断后最低生存内核运行；
5. 恶意来源、Tool 或模型供应链联合污染；
6. 超级模型合并角色后的权力可区分性；
7. 外部行动成功响应但现实效果失败；
8. 自我演进导致跨年知识解释变化。

这些是 `Skeleton v0.3` 的宏观压力验证输入。它们不暴露新的一级面，因此 G7 达到“骨架级通过”，但还不是最终通过。

## 六、闭合不变量

本轮复核固定以下宏观不变量：

1. 五域只作视觉分组，十面才拥有一级职责；
2. 组织、运行形态、全局流、尺度轴、横切维度和生存防线不得冒充一级职责面；
3. 一个结构可以跨越全部十面，但跨越不等于集中所有权；
4. 人类主权属于系统权力来源，不属于任何内部 Agent；
5. 基础设施共同承载全部面，但不取得业务和认识论权威；
6. Agent、Tool、服务和模型可以替换，能力契约与权威语义不能静默改变；
7. 规模、区域、时间和模型智商可以改变拓扑，不能改变授权与事实语义；
8. 规划、执行、审核可以由同一模型承载，但必须保持可独立授权、拒绝、审计和接管；
9. 恢复必须覆盖服务、状态、权限秩序和派生影响纠正；
10. 新宏观结构必须先回答它是职责、关系、坐标、约束、状态还是承载，再决定放置位置。

## 七、剩余缺口的层级

### 不再属于一级骨架缺口

- Schema、字段和 ID；
- 状态转移细节；
- Agent 编排和 Tool 协议；
- 数据库、队列、缓存和模型选型；
- 部署、容量、SLO、RTO/RPO；
- 安全控制和合规规则表；
- 具体组织 RACI。

### 仍属于整体骨架阶段

- 用八个压力场景验证 S2～S7；
- 建立能力演进作用全域图；
- 检查新增视图之间是否存在循环权威和单点认知；
- 进行至少另一轮宏观扫描，验证一级面继续稳定；
- 汇总形成可一屏阅读的 `Skeleton v0.3` 全局视图。

## 八、阶段裁定

```text
十面裁定：保留 10 个，不增、不减、不重划
七门裁定：G1、G6 通过；G2～G5、G7 骨架级通过
轮次裁定：Skeleton v0.2 第二轮宏观闭合
细节裁定：继续禁止进入局部专题深挖
下一步：Skeleton v0.3 宏观压力场景与全局视图闭合
```
