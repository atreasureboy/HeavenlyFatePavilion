# Skeleton v1.0 正式就绪评审

状态：Accepted

评审日期：2026-07-24

评审对象：天机阁整体架构骨架

## 一、评审结论

`Skeleton v1.0` 正式通过。

本次评审确认：

```text
一级职责：十面完整且连续三轮稳定
一级分组：五域仅作视觉分组，不形成隐藏权威
共同承载：基础设施不冒充逻辑职责
一级关系：权力、情报、对象、运行、生存、演进六条主线可分别阅读
外部边界：主体、主权、辖域与信任来源已有位置
横切约束：四轴七维能够覆盖范围变化和全局治理
异常闭合：拒绝、封驳、降级、隔离、纠正、回滚和人类接管均有路由
未来适配：模型能力变化可以替换实现，不静默改写职责与权威
```

因此，天机阁结束“整体骨架扩展与完善”阶段，建立 `Skeleton v1.0` 基线。

这是一份架构设计基线，不是软件发布，也不表示系统已经可以实现。

## 二、评审方法

本轮不是继续寻找更多名词，而是对现有骨架执行五类证明：

1. **必要性**：删除某个一级面是否会留下无法被其他面合法承担的稳定问题族；
2. **充分性**：已知宏观问题是否都能归入一级面、横切维度、外部边界或共同承载；
3. **互斥性**：两个一级面是否拥有不可区分的核心问题和权威状态；
4. **连接性**：职责之间是否存在输入、输出、拒绝、失败与纠正路径；
5. **演进性**：未来模型、规模和组织变化是否只能通过破坏骨架才能容纳。

通过标准不是“所有细节已经写完”，而是：

> 任何尚未完成的工作都有稳定归属，且不再阻塞一级架构成立。

## 三、十面必要性审判

| 一级面 | 如果删除会丢失什么 | 为什么不能由相邻面吞并 | 裁定 |
|---|---|---|---|
| 人机交互面 | 持续人机关系、意图澄清、呈现和反馈入口 | 治理面拥有任务权力，不应同时垄断用户体验和表达 | 必要 |
| 情报产品面 | 面向消费、分发、版本和纠正的正式交付物 | 研判结果不等于可传播、可撤回、可承担影响的产品 | 必要 |
| 数据认知面 | 掌数、联结、察变的认识过程 | 数据底座只保证可靠存在，不能拥有“如何认识世界”的处理语义 | 必要 |
| 情报研判面 | 推势、卜算、警险及不确定性判断 | 数据认知描述世界状态，不应把预测和规范性判断伪装成事实 | 必要 |
| 智能治理面 | 规划、统筹、审核、封驳和问责 | 运行面负责执行，不能自行产生并批准自己的授权 | 必要 |
| 领域能力面 | 六部专业语义、领域规则和跨领域协作 | 共享情报主干不能代替专业知识，也不应复制六套平台 | 必要 |
| 智能执行与运行面 | Run、Task、Agent/Tool 实例、调度和恢复 | 控制面保存期望状态，不应冒充一次任务的实时执行者 | 必要 |
| 数据底座面 | 权威资料、证据、事实、关系、版本和纠正血缘 | Agent Memory 和业务处理过程不能成为长期事实主库 | 必要 |
| 平台控制面 | 租户、策略、目录、模板、预算和版本的长期期望状态 | 运行时状态短暂且任务化，无法承担平台级确定性强制 | 必要 |
| 能力演进面 | 跨全域观察、实验、评测与候选变更 | 任一业务面只优化自身会形成局部最优和自证闭环 | 必要 |

结论：十面均具有不可被相邻面无损吸收的稳定问题族。

## 四、十面充分性审判

使用十二个宏观问题族反向投影：

| 宏观问题族 | 一级归属或结构位置 | 是否存在空白 |
|---|---|---|
| 人类需求与持续交互 | 人机交互面、外部主权 | 否 |
| 正式情报交付与影响 | 情报产品面 | 否 |
| 数据采集、清洗、关联、Diff | 数据认知面 + 数据底座面 | 否 |
| 事实、关系、事件与长期知识 | 数据底座面 | 否 |
| 态势、趋势、预测与风险 | 情报研判面 | 否 |
| 人物、商业、舆情、地缘、法规、技术 | 领域能力面 | 否 |
| 多 Agent 规划、制衡与问责 | 智能治理面 | 否 |
| Agent、Tool、Script 的实际协作 | 智能执行与运行面 | 否 |
| 多租户、权限、预算、版本和策略 | 平台控制面 + 七维横切治理 | 否 |
| 时空、规模、辖域和联合空间 | 四条扩展轴 | 否 |
| 故障、生存、恢复和未来替换 | 生存性与负空间 | 否 |
| 模型和整体架构持续变化 | 能力演进面 | 否 |

未发现必须新增一级面的宏观问题族。

## 五、互斥性与重叠审判

十面不是完全无交互，而是必须做到“核心权威不可混同”。

| 容易混淆的边界 | 分界规则 | 结果 |
|---|---|---|
| 人机交互 / 智能治理 | 皇帝交互投影负责关系与表达；皇帝治理本体负责协调与权力 | 可区分 |
| 情报产品 / 情报研判 | 研判形成判断；产品决定如何交付、版本化和纠正 | 可区分 |
| 数据认知 / 数据底座 | 前者处理认识；后者持久保存权威状态和血缘 | 可区分 |
| 数据认知 / 情报研判 | 前者说明发生了什么；后者说明意味着什么、可能如何发展 | 可区分 |
| 智能治理 / 智能运行 | 前者拥有规划、审核和问责；后者限域执行 | 可区分 |
| 领域能力 / 情报主干 | 前者提供专业语义；后者提供共享生产链 | 可区分 |
| 平台控制 / 智能运行 | 前者保存长期期望状态；后者保存即时执行状态 | 可区分 |
| 能力演进 / 各对象所有面 | 演进面提出与验证；对象所有面验收，有权主体采用 | 可区分 |
| 数据底座 / 基础设施 | 前者是逻辑知识责任；后者是计算、存储和网络承载 | 可区分 |

重叠存在于协作，不存在于最终权威所有权。

## 六、一级关系闭合

### 6.1 六条主线

```text
权力线：
外部原生权威 → 皇帝承接 → 三省制衡 → 平台强制
→ 运行限域执行 → 审计、人类接管与责任

情报线：
掌数 → 联结 → 察变 → 推势 → 卜算 → 警险 → 产品

对象线（经 v0002 复核后的正式表达）：
Source → Document → Snapshot → Evidence
→ Claim + Proposition → scoped Acceptance → Fact Aggregate
→ Mention / Entity / Relationship / Event / Change
→ Assessment / Scenario / Forecast / Risk
→ Product Edition → Release / Distribution / Delivery

运行线：
Mandate / Mission → Plan → Run → Task / Agent / Tool
→ Product / Action / Effect → Feedback

生存线：
预防 → 感知 → 遏制 → 延续 → 恢复 → 纠正与演进

演进线：
观察 → 缺口 → 候选 → 实验 → 评测 → 采用
→ 发布 → 结果 → 保留 / 调整 / 回滚 / 影响纠正
```

六条线都有起点、所有者转换、持久记录与异常出口，不依赖一条万能箭头。

### 6.2 七类全局流

控制、数据、知识形成、决定与授权、预算与资源、审计与证据、反馈与演进已经分别建模。共享一次调用不意味着共享同一种权力。

### 6.3 十种运行形态

即时查询、复杂调查、持续监测、事件响应、批处理、多人/多 Agent 协作、主动交付、能力演进、外部行动、灾难恢复均有顶层位置。

## 八、允许带入 v1.0 的保留项

以下内容可以在未详细完成的情况下进入基线，因为它们已有稳定归属，不构成一级阻塞：

- 对象完整 Schema、ID 与字段约束；
- Contract Envelope 的协议字段、版本兼容和超时重试；
- 角色—权限—动作授权矩阵；
- 数据分层、索引、图存储和湖仓等技术选择；
- Agent Runtime、模型路由、沙箱和调度算法；
- 容量、SLO、成本数字和多区域部署拓扑；
- 细粒度法规、隐私、来源许可和保留策略；
- 六部与公共官署内部流程；
- 完整威胁模型、故障库和极端规模计算；
- 面试讲解、视图和案例的进一步压缩。

它们是“待提高分辨率”，不是“骨架没有位置”。

## 九、基线冻结规则

`Skeleton v1.0` 冻结的是语义，不冻结实现：

```text
冻结：
项目定位与主权原则
五域十面及其核心责任
组织—技术映射原则
对象语义分层
六条主线、七流、四轴、七维
生存底线、负空间和演进权分离

不冻结：
具体模型、Agent 数量和提示词
Tool、Script、服务和产品选型
Schema、API、队列和数据库
部署拓扑、容量参数和供应商
六部与官署内部实现
```

重新打开一级骨架必须同时满足：

1. 出现无法稳定归入十面、横切维度、外部边界或承载层的问题族；
2. 该问题跨多个场景持续存在，而非单一实现不便；
3. 调整收益大于权威迁移、历史兼容和认知成本；
4. 经过 ADR、影响分析、压力场景和全局闭合复核；
5. 高影响变更由有权人类正式采用。

## 十、阶段转移

```text
此前：
整体骨架扩展与完善

现在：
Skeleton v1.0 基线成立

下一阶段：
按骨架分区逐步提高专题分辨率
```

专题深化不得重新从零发明顶层结构。任何细节必须能够回挂到十层阅读树（L0～L9）、十面所有权、六条主线及相应横切约束。

## 十一、语义专题完成后的复核附记

2026-07-29，v0002 情报语义专题完成后再次反投影：

- Mention、Scenario、Governance Case、Product Edition 等新增核心对象均能归入既有十面；
- Authority Domain、Epistemic Record、Transition Envelope 和 typed lineage 属于 L4～L6 深化；
- SCN-0010～SCN-0018 未要求新增一级面、全局流或横切维度；
- 原文“九层”经计数校正为 `L0～L9` 十层，不改变任何架构内容。

因此 v0002 增强了 Skeleton v1.0 的语义证明，没有重新打开一级骨架。最终证据见[外层架构骨架终局完成审计](./outer-skeleton-final-completion-audit.md)。

## 十二、最终裁定

> 天机阁整体架构骨架在当前认知范围和面试架构目标下已经正式完善，可以停止无边界扩骨架，进入专题深化阶段。

这里的“正式完善”表示骨架已经具备稳定边界、职责、关系、权威、异常、演进和验证位置；不表示所有内部设计已经完成，也不表示未来永远不可调整。
