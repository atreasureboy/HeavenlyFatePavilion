# SCN-0009：模型退化与能力回滚

状态：Accepted

## 目标

新模型版本灰度后，实体合并误报率和 Token 成本同时上升。验证天机阁能从运行证据发现能力缺口、治理变更并安全回滚。

## 主路径

```text
运行面产生模型调用、质量、成本和失败遥测
→ 数据认知面发现消歧质量下降
→ 都察院抽样确认并形成 Evolution Evidence
→ 能力演进面创建 Capability Gap
→ 关联当前 Model/Workflow/Prompt/Rule 版本
→ 若超过停止阈值：
   平台控制面阻止扩大灰度
   Capability Version Canary → RolledBack
→ 回到上一 Retained 版本
→ 血缘查询定位灰度期间产生的 Entity Merge / Fact / Product
→ 创建重算、拆分、重评和更正 Task
→ 中书提出修复候选，尚书安排实验，门下审核评测设计
→ 候选在隔离数据集和授权租户流量中重新评测
→ 通过后重新走 Staged → Canary → RollingOut
```

## Agent / Tool 分工

- 指标、版本标记、阈值、流量切分、回滚和影响查询：Tool/Service；
- 异常归因、候选修复、评测解释和治理审核：Agent；
- 发布权属于版本化平台策略，不属于模型自身；
- 人类在高影响、评测争议或架构级变更时决定。

## 横切验证

- 租户：灰度租户和对照租户隔离；
- 权限：评测数据具有用途授权；
- 证据：每个错误输出可回溯到模型和输入版本；
- 预算：同时评估质量收益与 Token 成本；
- 风险质量：停止阈值预先定义；
- 审计：发布、灰度、回滚和重算全记录；
- 生命周期：旧版本 Retained，问题版本 RolledBack 而非删除。

## 异常

- 自动回滚失败：停止新调用并切换预定义降级能力；
- 新旧版本输出无法兼容：通过版本适配器或重算，不静默混用；
- 回归集被污染：评测无效，退回候选；
- 发现整体架构缺口：升级为人类主导架构迭代，而非局部 Prompt 修补。

## 验证结果

通过。自我演进覆盖模型、工作流和派生结果纠正，同时受治理、权限和发布状态机约束。

验证 `INV-0002` 至 `INV-0008`。
