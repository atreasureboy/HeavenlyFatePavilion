# SCN-0004：冲突证据与事实裁定

状态：Accepted

## 目标

两个可信来源对同一人物任职终止日期给出不同说法。验证系统不会为追求单一答案而抹平冲突。

## 主路径

```text
两个 Snapshot 形成各自 Evidence
→ 提取 Claim A 与 Claim B
→ 实体和时间范围确认指向同一命题
→ 冲突检测产生 EPI Exception
→ 两个 Claim 进入 Disputed
→ 数据认知面追加来源独立性、时效和原文上下文
→ 吏部 Agent 解释履历语义和可能的日期口径
→ 门下寻找反证
→ 大理寺按规则裁定：
   ├── 一方 Verified，另一方 Rejected/Superseded
   ├── 两者描述不同业务日期，拆成两个 Fact
   └── 证据仍不足，保留 Disputed Claim
→ 下游只使用与裁定状态相符的视图
```

## 权威边界

- 大理寺不修改原始 Evidence；
- 吏部 Agent 提供领域解释，不拥有事实写入强制权；
- 数据底座保存双方主张、裁定、理由和版本；
- 租户可以在私有覆盖层保留判断，不能改写公共裁定历史。

## 异常

- 新来源仍无法解决：保持 `Unresolved`，产品表达分歧；
- 裁定者利益冲突：换独立审理主体；
- 旧 Fact 已被产品引用：触发受影响产品重新评估；
- 来源后来更正：创建新 Snapshot 和因果事件，不覆盖旧快照。

## 审计

记录冲突检测规则、候选事实、全部证据、领域意见、门下反证、裁定主体、政策版本与下游影响。

## 验证结果

通过。`Disputed` 是正式知识状态，不是错误兜底；事实裁定与证据保全职责分离。
