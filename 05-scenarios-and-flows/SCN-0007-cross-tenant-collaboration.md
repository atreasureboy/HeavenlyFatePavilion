# SCN-0007：跨租户联合调查

状态：Accepted

## 目标

仙门 A 与仙门 B 共同调查供应链事件，但双方只愿共享部分资料。验证联合协作不会使租户边界消失。

## 前置

双方有权管理员创建有名称的 `Collaboration Space C`，明确：

- 参与租户和成员；
- 可贡献的数据对象与字段；
- 允许用途；
- 可见期限和退出规则；
- 导出、再传播和派生产品规则；
- 成本分摊；
- 共同裁定与审计访问方式。

## 主路径

```text
平台控制面批准并版本化联合空间政策
→ A、B 分别发布显式数据授权，不复制整个私有覆盖层
→ 联合 Mission 在 C 作用域创建
→ 皇帝 A/B 各自保持稳定身份，通过联合治理上下文协作
→ 运行面只向任务授予 C 范围能力令牌
→ 数据底座构造：
   Public Baseline
   + A 授权视图
   + B 授权视图
   + C 内派生对象
→ 跨部调查、事实验证和联合研判
→ 产品生成时分别计算联合版、A 私有版、B 私有版
→ 到期或退出后撤销未来访问，按政策处置 C 中派生对象
```

## 禁止

- 用一方租户权限代表另一方；
- 把缺失 `tenant_id` 当作联合空间；
- 联合 Agent 把 A 私有上下文带入 B 的产品；
- 因“共同研判”自动获得原始资料下载权；
- 平台运营者因主持联合空间而取得业务使用权。

## 异常

- 一方撤回某份资料：停止新使用并进行派生影响分析；
- 双方对事实有不同裁定：保留作用域化 Claim/Assessment，不强制统一；
- 费用争议：暂停新增高成本 Task，不影响审计保全；
- 发生跨租户泄露：S4 隔离、冻结相关分发、保全证据并人类接管。

## 验证结果

通过。多租户协作通过第三种显式作用域实现，而不是关闭隔离；皇帝、数据、预算和产品仍保持清晰归属。

验证 `INV-0001`、`INV-0002`、`INV-0006`、`INV-0007`、`INV-0008`。
